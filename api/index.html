Telegram API

Оригинальный русскоязычный обзор уровня «приложение» — надстройки над протоколом MTProto. Первоисточник со всеми подразделами: core.telegram.org/api.

Протокол отвечает на вопрос «как байты доходят до сервера и шифруются»; уровень API отвечает на вопрос «какие методы вызвать и как обрабатывать события». Все методы и типы — в схеме; ниже — ключевые темы для реализации клиента.

Базовый сценарий клиента

  1. Получить api_id/api_hash — идентификаторы приложения (выдаются на my.telegram.org).
  2. Создать auth_key — см. Создание авторизационного ключа.
  3. Авторизовать пользователя или бота — обмен кодом и паролем описан в разделе Авторизация.
  4. Инициализация соединения — initConnection поверх первого запроса: сообщает о приложении, устройстве, языке; в ответ сервер присылает конфигурацию (help.getConfig).
  5. Синхронизация времени и солей, далее — обычный обмен запросами и обновлениями.

Основные темы

Авторизация

Обмен кодом из СМС, двухфакторный пароль, выход и завершение сессий: auth.sendCode, auth.signIn, auth.signUp, auth.checkPassword и др. Подробности — в разделе Авторизация.

Обновления (события)

Сервер присылает обновления — новые сообщения, изменения чатов, статусы и т.д. Клиент обязан уметь: запрашивать разницу (updates.getDifference), обрабатывать пропуски (pts, qts, date), применять обновления в правильном порядке. Обзор — в разделе Получение обновлений.

Файлы

Загрузка и скачивание файлов с поддержкой докачки и параллельных частей: upload.saveFilePart, upload.getFile, локации файлов (InputFileLocation) и file references. Обзор — в разделе Работа с файлами.

Как вызывать методы

Правила уровня layer, повторные вызовы, флуд-контроль, ошибки: вызов методов и ошибки.

Сквозное шифрование

  • Секретные чаты — переписка, которую не может прочитать сервер.
  • Perfect Forward Secrecy — сменяемые ключи секретных чатов.
