# Формальное описание комбинаторов TL

[Формальное объявление комбинаторов TL](/mtproto/TL-combinators/)

Основная статья: [Формальное описание TL](TL-formal). См. также [Язык TL](TL).

Комбинаторы в TL объявляются следующим образом:

_combinator-decl_ ::= _full-combinator-id_ { _opt-args_ } { _args_ } `=` _result-type_ `;`  
_full-combinator-id_ ::= _lc-ident-full_ | `_`  
_combinator-id_ ::= _lc-ident-ns_ | `_`  
_opt-args_ ::= `{` _var-ident_ { _var-ident_ } : \[_excl-mark_\] _type-expr_ `}`  
_args_ ::= _var-ident-opt_ `:` \[ _conditional-arg-def_ \] \[ `!` \] _type-term_  
_args_ ::= \[ _var-ident-opt_ `:` \] \[ _multiplicity_ `*`\] `[` { _args_ } `]`  
_args_ ::= `(` _var-ident-opt_ { _var-ident-opt_ } `:` \[`!`\] _type-term_ `)`  
_args_ ::= \[ `!` \] _type-term_  
_multiplicity_ ::= _nat-term_  
_var-ident-opt_ ::= _var-ident_ | `_`  
_conditional-arg-def_ ::= _var-ident_ \[ `.` _nat-const_ \] `?`  
_result-type_ ::= _boxed-type-ident_ { _subexpr_ }  
_result-type_ ::= _boxed-type-ident_ `<` _subexpr_ { `,` _subexpr_ } `>`

Поясним, что всё это означает.

-   Идентификатор комбинатора — это либо идентификатор, начинающийся со строчной латинской буквы (_lc-ident_), либо идентификатор пространства имён (тоже _lc-ident_), за которым следует точка и ещё один _lc-ident_. Таким образом, `cons` и `lists.get` — допустимые идентификаторы комбинаторов.

-   У комбинатора есть _имя_, также называемое _номером_ (не путать с _обозначением_), — 32-битное число, которое однозначно его определяет. Оно либо вычисляется автоматически (см. ниже), либо явно задаётся в объявлении. Для этого к идентификатору определяемого комбинатора добавляются знак решётки (`#`) и ровно 8 шестнадцатеричных цифр — имя комбинатора.

-   Объявление комбинатора начинается с его идентификатора, к которому может быть добавлено его имя (через знак решётки).

-   За идентификатором комбинатора следует основная часть объявления, состоящая из объявлений _полей_ (или _переменных_), включая указание их _типов_.

-   Сначала идут объявления необязательных полей (их может быть несколько или не быть вовсе). Затем идут объявления обязательных полей (их также может не быть).

-   Идентификатором поля (переменной) может быть любой идентификатор, который начинается с прописной или строчной буквы и не содержит ссылок на пространство имён. Хорошая практика — использовать _uc-ident_ для идентификаторов переменных типов и _lc-indent_ для остальных переменных.

[@note] В оригинале здесь опечатка: _lc-indent_ вместо _lc-ident_. Она сохранена, но имеется в виду обычный _lc-ident_ — идентификатор со строчной буквы.

-   Далее объявление комбинатора содержит знак равенства (`=`) и результирующий тип (он может быть составным или встречаться впервые). Результирующий тип может быть полиморфным и/или зависимым; в качестве подвыражений могут возвращаться любые поля определяемого конструктора, имеющие тип `Type` или `#`.

-   Объявление комбинатора завершается точкой с запятой.

Далее _поля_, _переменные_ и _аргументы_ конструктора означают одно и то же.

### Объявления необязательных полей

-   Они имеют вид `{` _field\_1_ ... _field\_k_ `:` _type-expr_ `}`, где _field\_i_ — идентификатор переменной (поля), уникальный в пределах области видимости объявления комбинатора, а _type-expr_ — тип, общий для всех этих полей.

-   Если _k>1_, такая запись функционально эквивалентна `{` _field\_1_ `:` _type-expr_ `}` ... `{` _field\_k_ `:` _type-expr_ `}`.

-   Все необязательные поля обязаны быть явно поименованы (использовать `_` вместо _field\_i_ не допускается).

-   Более того, в настоящее время имена всех необязательных полей обязаны входить в результирующий тип комбинатора (возможно, более одного раза) и сами иметь тип `#` (то есть `nat`) или `Type`. Поэтому, если точный результирующий тип известен, можно определить значения всех неявных параметров комбинатора (возможно, получив при этом противоречие вида `2=3`, что означает недопустимость комбинатора в данном контексте).

### Объявления обязательных полей

-   Они могут иметь вид `(` _field\_1_ ... _field\_k_ `:` _type-expr_ `)`, аналогичный объявлению необязательного поля, но с круглыми скобками. Такая запись эквивалентна `(` _field\_1_ `:` _type-expr_ `)` ... `(` _field\_k_ : _type-expr_ `)`, где поля определяются по одному.

-   В качестве имён одного или нескольких полей (_field\_i_) можно использовать знак подчёркивания (`_`), указывающий, что поле анонимно (его точное имя несущественно).

-   Одно поле может быть объявлено без внешних круглых скобок, вот так: _field\_id_ `:` _type-expr_. Однако здесь, если _type-expr_ — сложный тип, вокруг _type-expr_ могут потребоваться скобки (это отражено в БНФ).

-   Кроме того, одно анонимное поле может быть объявлено записью _type-expr_, функционально эквивалентной `_` `:` _type-expr_.

-   Объявления обязательных полей следуют одно за другим, разделяясь пробелами (точнее говоря, любым количеством пробельных символов).

-   Тип объявляемого поля (_type-expr_) может использовать ранее определённые переменные (поля) объявляемого комбинатора в качестве подвыражений (то есть значений параметров). Например:

    nil {X:Type} = List X; cons {X:Type} hd:X tl:(list X) = List X; typed\_list (X:Type) (l : list X) = TypedList;

### Повторения

-   Они допускаются только среди обязательных параметров и имеют вид \[ _field-id_ `:` \] \[ _multiplicity_ `*` \] `[` _args_ `]`, где _args_ записывается в том же формате, что и объявление (нескольких) обязательных полей комбинатора, с той разницей, что в типах аргументов разрешено использовать все ранее объявленные поля объемлющего комбинатора.

-   Имя поля объемлющего комбинатора, которое получает повторение в качестве значения, можно указать явно (_field-id_), а можно опустить — это равносильно указанию знака подчёркивания в качестве _field-id_.

-   Поле _multiplicity_ — это выражение типа `#` (`nat`); им может быть числовая константа, имя одного из предшествующих полей типа `#` либо выражение вида `(` _c_ `+` _v_ `)`, где _c_ — числовая константа, а _v_ — имя поля типа `#`. Смысл поля _multiplicity_ в том, чтобы задать длину вектора (повторения), каждый элемент которого состоит из значений типов, перечисленных в _args_.

-   Поле _multiplicity_ можно опустить. В этом случае берётся последний из предшествующих параметров типа `#` объемлющего комбинатора (и он обязан существовать).

-   Функционально повторение _field-id_ `:` _multiplicity_ `*` `[` _args_ `]` равносильно объявлению одного поля `(` _field-id_ `:` `%Tuple` `%AuxType` _multiplicity_ `)`, где `aux_type` — вспомогательный тип с новым именем, определённый как `aux_type *args* = AuxType`. Если внутри _args_ используются какие-либо поля объемлющего типа, они добавляются во вспомогательный конструктор `aux_type` и в его результирующий тип `AuxType` в качестве первых (необязательных) параметров.

-   Если _args_ состоит из одного анонимного поля типа _some-type_, то вместо `%AuxType` можно напрямую использовать _some-type_.

-   Если при реализации повторения переписываются описанным выше способом, разумно использовать вместо `aux_type` и `AuxType` такие идентификаторы, которые содержат имя определяемого внешнего комбинатора и порядковый номер повторения внутри его определения.

Пример:

```
matrix {m n : #} a : m* [ n* [ double ] ] = Matrix m n;
```

функционально равносильно

```
aux_type {n : #} (_ : %Tuple double n) = AuxType n;
matrix {m : #} {n : #} (a : %Tuple %(AuxType n) m) = Matrix m n;
```

Более того, встроенные типы `Tuple` и `Vector` можно было бы определить так:

```
tnil {X : Type} = Tuple X 0;
tcons {X : Type} {n : #} hd:X tl:%(Tuple X n) = Tuple X (S n);
vector {X : Type} (n : #) (v : %(Tuple X n)) = Vector X;
```

На самом деле определением `Vector` считается следующая равносильная запись (то есть именно эта запись используется для вычисления имени конструктора `vector` и его частичных применений):

```
vector {t : Type} # [ t ] = Vector t;
```

Если раскрыть её через `Tuple`, получится в точности предыдущее определение.

### Условные поля

Конструкция

_args_ ::= _var-ident-opt_ `:` \[ _conditional-arg-def_ \] \[ `!` \] _type-term_  
_conditional-arg-def_ ::= _var-ident_ \[ `.` _nat-const_ \] `?`

[@term:flags] позволяет задавать поля, которые присутствуют только тогда, когда значение предшествующего обязательного или необязательного поля типа `#` (в схеме Telegram такое поле-битовую маску принято называть `flags`) отлично от нуля — или когда отличен от нуля выбранный бит этого поля, если применён специальный двоичный оператор выбора бита `.`. Пример:

`user {fields:#} id:int first_name:(fields.0?string) last_name:(fields.1?string) friends:(fields.2?%(Vector int)) = User fields;`  
`get_users req_fields:# ids:%(Vector int) = Vector %(User req_fields)`
