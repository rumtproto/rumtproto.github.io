# Сериализация данных (язык TL)

Оригинальное русскоязычное изложение правил, по которым значения типов [TL](/mtproto/TL/) превращаются в байты и обратно. Первоисточник: [core.telegram.org/mtproto/serialize](https://core.telegram.org/mtproto/serialize).

Все целые числа передаются в **малоэндийном** (little-endian) порядке байтов.

## Базовые типы

| Тип | Размер | Пояснение |
|---|---|---|
| `int` | 4 байта | целое со знаком |
| `long` | 8 байт | целое со знаком |
| `int128` / `int256` | 16 / 32 байта | «сырые» числа фиксированной длины (используются, например, для `nonce`) |
| `double` | 8 байт | IEEE 754, little-endian |
| `string` / `bytes` | см. ниже | строка/массив байтов с длиной |
| `!X` (function) | — | тип «функция как параметр»; сериализуется как сериализованный вызов соответствующей функции |

### Строки и байтовые массивы

Длина кодируется компактно:

- если длина `l < 254`, сначала пишется один байт `l`, затем данные, затем от 0 до 3 нулевых байтов выравнивания до кратности 4;
- если `l >= 254`, пишется байт `254`, затем 3 байта длины (малоэндийные), затем данные и выравнивание до кратности 4.

Итого полная запись всегда кратна 4 байтам.

### Векторы

`Vector t` сериализуется так: конструктор [`vector`](/constructor/vector/) (`#1cb5c415`), затем `int` с количеством элементов, затем элементы подряд.

## Комбинаторы (конструкторы типов)

Каждый конструктор схемы начинается с 4-байтного идентификатора (`constructor ID`), например:

```
boolFalse#bc799737 = Bool;
boolTrue#997275b5 = Bool;
```

Сериализация значения типа — это идентификатор конструктора, за которым в порядке объявления следуют сериализованные поля.

### Поля

- Обычное поле `name:Type` — сериализованное значение типа.
- **Поля с флагами** (условные) записываются как `flags.N?Type`: в конструкторе есть служебное поле `flags:#` (битовая маска); поле `N` присутствует в потоке тогда и только тогда, когда установлен бит `N`. Например, в [`message`](/constructor/message/) десятки опциональных полей управляются одним словом `flags`.
- Поле `flags2:#` и т.п. — дополнительные слова маски, когда битов не хватает.
- Тип `#` — это 32-битное беззнаковое целое (используется для масок и «сырых» идентификаторов).
- Тип `true` не занимает места в потоке: наличие значения кодируется самим битом флага.

## Полиморфизм и зависимые типы

- Если поле имеет абстрактный тип (например, [`Peer`](/type/Peer/)), на его месте сериализуется один из конструкторов этого типа вместе со своим идентификатором.
- Некоторые конструкторы отличаются только значениями полей при одинаковой структуре; формальное описание возможностей языка — в оригинальных статьях о [полиморфизме](https://core.telegram.org/mtproto/TL-polymorph) и [зависимых типах](https://core.telegram.org/mtproto/TL-dependent).

## Методы (запросы)

Запрос сериализуется точно так же: идентификатор метода + поля. Ответ — значение соответствующего типа схемы. Ошибки — конструктор [`rpc_error`](https://core.telegram.org/constructor/rpc_error/).

## Практические следствия

- Парсер клиента должен корректно переживать поля и флаги, появившиеся в новых слоях схемы: неизвестные части следует пропускать, опираясь на объявленную структуру конструктора, а не аварийно завершаться.
- При генерации кода из схемы удобно использовать машиночитаемые версии: [схема в JSON](/schema/json/).
