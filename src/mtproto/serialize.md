# Двоичная сериализация данных

Для работы MTProto необходимо, чтобы элементарные и составные типы данных, а также запросы, которым такие типы данных передаются в качестве аргументов или которыми они возвращаются, передавались в двоичном виде (то есть были _сериализованы_). Для описания сериализуемых типов данных используется [язык TL](/mtproto/TL/).

### Общие определения

Для наших целей _тип_ можно отождествить с множеством его _(сериализованных) значений_, понимаемых как строки (конечные последовательности) 32-битных чисел (передаваемых в порядке little endian).

Следовательно:

-   _Алфавит_ (A) в данном случае — это множество 32-битных чисел (обычно знаковых, то есть в диапазоне от -2^31 до 2^31 - 1).
-   _Значение_ в данном случае — то же самое, что _строка в алфавите A_, то есть конечная (возможно, пустая) последовательность 32-битных чисел. Множество всех таких последовательностей обозначается как _A\*_.
-   _Тип_ для наших целей — то же самое, что множество допустимых значений типа, то есть некоторое множество T, которое служит подмножеством A\* и префиксным кодом (то есть ни один элемент T не может быть префиксом любого другого элемента). Следовательно, любая последовательность из A\* может содержать не более одного префикса, входящего в T.
-   _Значение типа T_ — любая последовательность (значение), входящая в T как в подмножество A\*.
-   _Совместимые типы_ — это типы T и T', не пересекающиеся как подмножества A\*, такие что объединение T и T' образует префиксный код.
-   _Согласованная система типов_ — конечное или бесконечное множество типов T\_1, ..., T\_n, ..., такое что любые два типа из этого множества совместимы.
-   _Тип данных_ — то же самое, что _тип_ в смысле приведённого выше определения.
-   _Функциональный тип_ — тип, описывающий функцию; типом в смысле приведённого выше определения он не является. Поначалу мы игнорируем существование функциональных типов и описываем только типы данных; однако в действительности функциональные типы будут впоследствии реализованы в некотором расширении этой системы с помощью так называемых _временны́х комбинаторов_.

#### Комбинаторы, конструкторы, составные типы данных

-   _Комбинатор_ — функция, которая принимает аргументы определённых типов и возвращает значение некоторого другого типа. Обычно мы рассматриваем комбинаторы, у которых типы аргументов и результата — типы данных, а не функциональные типы.

-   _Арность (комбинатора)_ — неотрицательное целое число, количество аргументов комбинатора.

-   _Идентификатор комбинатора_ — идентификатор, начинающийся со строчной латинской буквы и однозначно определяющий комбинатор.

-   _Номер комбинатора_, или _имя комбинатора_, — 32-битное число (то есть элемент A), однозначно определяющее комбинатор. Чаще всего это CRC32 строки с описанием комбинатора без завершающей точки с запятой и с одним пробелом между соседними лексемами. Это число всегда попадает в диапазон от 0x01000000 до 0xffffff00. Старшие 256 значений зарезервированы для так называемых _комбинаторов временно́й логики_, используемых для передачи функций. Часто мы обозначаем как _комбинатор_ имя комбинатора в одинарных кавычках: '_комбинатор_'.

-   _Описание комбинатора_ — строка формата `combinator_name type_arg_1 ... type_arg_N = type_res;`, где `N` — арность комбинатора, `type_arg_i` — тип i-го аргумента (точнее, строка с именем комбинатора), а `type_res` — тип значения комбинатора.

-   _Конструктор_ — комбинатор, который не может быть вычислен (редуцирован). Он используется для представления составных типов данных. Например, комбинатор 'int\_tree' с описанием `int_tree IntTree int IntTree = IntTree` вместе с комбинатором `empty_tree = IntTree` может использоваться для определения составного типа данных под названием «IntTree», принимающего значения в виде двоичных деревьев с целыми числами в узлах.

-   _Функция (функциональный комбинатор)_ — комбинатор, который может быть вычислен (редуцирован) при условии, что предоставлено нужное количество аргументов нужных типов. Результат вычисления — выражение, состоящее только из конструкторов и значений базовых типов.

-   _Нормальная форма_ — выражение, состоящее только из конструкторов и значений базовых типов; обычно именно ею и заканчивается вычисление функции.

-   _Идентификатор типа_ — идентификатор, который обычно начинается с заглавной латинской буквы и однозначно определяет тип.

-   _Номер типа_, или _имя типа_, — 32-битное число, однозначно определяющее тип; обычно это сумма значений CRC32 описаний конструкторов данного типа.

-   _Описание (составного) типа T_ — набор описаний всех конструкторов, принимающих значения типа _T_. Обычно оно записывается как текст, каждая строка которого содержит описание одного конструктора. Вот, например, описание типа 'IntTree':

    int\_tree IntTree int IntTree = IntTree; empty\_tree = IntTree;

-   _Полиморфный тип_ — тип, описание которого вместо реальных типов содержит параметры (_переменные типа_); примерно то же, что шаблоны в C++. Вот описание типа `List alpha`, где `List` — полиморфный тип арности 1 (то есть зависящий от одного аргумента), а `alpha` — переменная типа, выступающая как необязательный параметр конструктора (в фигурных скобках):

    cons {alpha:Type} alpha (List alpha) = List alpha; nil {alpha:Type} = List alpha;

-   _Значение (составного) типа T_ — любая последовательность из A\* формата `constr_num arg1 ... argN`, где constr\_num — номер некоторого конструктора _C_, принимающего значения типа _T_, а arg\_i — значение типа _T\_i_, то есть типа i-го аргумента конструктора _C_. Например, пусть комбинатор int\_tree имеет номер 17, а комбинатор empty\_tree — номер 239. Тогда значением типа `IntTree` будет, например, `17 17 239 1 239 2 239`, что удобнее записать как `'int_tree' 'int_tree' 'empty_tree' 1 'empty_tree' 2 'empty_tree'`. С точки зрения языка высокого уровня это `int_tree (int_tree (empty_tree) 1 (empty_tree)) 2 (empty_tree): IntTree`.

-   _Схема_ — набор описаний всех (составных) типов данных. Она используется для определения некоторой согласованной системы типов.

#### Boxed- и bare-типы

-   [@term:boxed type] _Boxed-тип_ (тип «в обёртке») — тип, любое значение которого начинается с номера конструктора. Поскольку у каждого конструктора однозначно определён тип значения, первое число в значении любого boxed-типа однозначно задаёт его тип. Это гарантирует, что все boxed-типы в совокупности образуют согласованную систему типов. Идентификатор boxed-типа всегда пишется с заглавной буквы.
-   [@term:bare type] _Bare-тип_ («голый» тип) — тип, значения которого не содержат номера конструктора, а лишь подразумевают его. Идентификатор bare-типа всегда совпадает с именем подразумеваемого конструктора (и потому начинается со строчной буквы) и может быть дополнен спереди знаком процента (%). Кроме того, если `X` — boxed-тип не более чем с одним конструктором, то `%X` обозначает соответствующий bare-тип. Значения bare-типа совпадают с множеством последовательностей чисел, полученных отбрасыванием первого числа (то есть внешнего номера конструктора) из множества значений соответствующего boxed-типа (являющегося типом результата выбранного конструктора), начинающихся с номера выбранного конструктора. Например, `3 4` — значение bare-типа `int_couple`, определённого как `int_couple int int = IntCouple`. Соответствующий boxed-тип — `IntCouple`; если 404 — номер конструктора `int_couple`, то `404 3 4` будет значением boxed-типа `IntCouple`, соответствующим значению bare-типа `int_couple` (также известного как `%int_couple` и `%IntCouple`; последняя форма концептуально предпочтительнее, но длиннее).

[@note] Знак `%` — это оператор «снять обёртку»: он превращает boxed-тип в соответствующий bare-тип, то есть в те же значения, но без ведущего номера конструктора. Применять его можно лишь тогда, когда у типа ровно один конструктор, — иначе по значению нельзя было бы восстановить, какой именно конструктор подразумевался.

Концептуально везде следует использовать только boxed-типы. Однако ради скорости и компактности приходится использовать bare-типы (например, массив из 10 000 значений bare-типа int занимает 40 000 байт, тогда как boxed-значения Int занимают вдвое больше места; поэтому при передаче, скажем, большого массива целочисленных идентификаторов эффективнее использовать тип `Vector int`, а не `Vector Int`). Кроме того, все базовые типы (int, long, double, string) — bare.

Если boxed-тип полиморфен и имеет типовую арность r, то это верно и для любого производного bare-типа. Иными словами, если определить `intCouple {alpha:Type} int alpha = IntCouple alpha`, то в дальнейшем intCouple как идентификатор тоже будет полиморфным типом арности 1 в описаниях комбинаторов (а следовательно, конструкторов и типов). Записи `intCouple X`, `%(IntCouple X)` и `%IntCouple X` эквивалентны.

#### Базовые типы

Базовые типы существуют как в bare-варианте (int, long, double, string), так и в boxed-варианте (Int, Long, Double, String). Идентификаторы их _конструкторов_ совпадают с именами соответствующих bare-типов. Их псевдоописания выглядят следующим образом:

```
int ? = Int;
long ? = Long;
double ? = Double;
string ? = String;
```

Следовательно, номер конструктора `int`, например, — это CRC32 строки `"int ? = Int"`.

Значения bare-типа `int` — это в точности все одноэлементные _последовательности_, то есть числа от -2^31 до 2^31-1 в этом случае представляют сами себя. Значения типа `long` — двухэлементные последовательности, представляющие собой 64-битные знаковые числа (снова в порядке little endian). Значения типа `double` — тоже двухэлементные последовательности, содержащие 64-битные вещественные числа в стандартном формате двойной точности. Наконец, значения типа `string` выглядят по-разному в зависимости от длины L сериализуемой строки:

-   Если L <= 253, сериализованное значение содержит один байт со значением L, затем L байт самой строки, за которыми следуют от 0 до 3 символов со значением 0, так чтобы общая длина значения делилась на 4; всё это целиком интерпретируется как последовательность из int(L/4)+1 32-битных чисел.
-   Если L >= 254, сериализованное значение содержит байт 254, затем 3 байта с длиной строки L, затем L байт самой строки, за которыми следуют от 0 до 3 нулевых байтов дополнения.

#### Псевдотип Object

Псевдотип `Object` — это «тип», который может принимать значения, принадлежащие любому boxed-типу схемы. Это позволяет быстро описывать такие типы, как _список произвольных элементов_, не прибегая к полиморфным типам. Злоупотреблять этой возможностью не стоит, поскольку она приводит к использованию динамической типизации. Тем не менее трудно представить себе структуры данных, знакомые нам по PHP и JSON, без псевдотипа Object.

Везде, где это возможно, рекомендуется использовать `TypedObject`:

```
object X:Type value:X = TypedObject;
```

#### Встроенные составные типы: векторы и ассоциативные массивы

Полиморфный псевдотип Vector t — это «тип», значением которого является последовательность значений произвольного типа t — boxed или bare.

```
vector {t:Type} # [ t ] = Vector t;
```

При сериализации всегда используется один и тот же конструктор «vector» (const 0x1cb5c415 = crc32("vector t:Type # \[ t \] = Vector t”), не зависящий от конкретного значения переменной типа t. Значение типа Vector t — это номер соответствующего конструктора, за которым следует N, число элементов вектора, а затем N значений типа t. Значение необязательного параметра t в сериализации не участвует, поскольку выводится из типа результата (всегда известного до десериализации).

Полиморфные псевдотипы IntHash t и StrHash t — это ассоциативные массивы, сопоставляющие целочисленным и строковым ключам значения типа t. По сути, это векторы, содержащие bare-пары (int, t) или (string, t):

```
coupleInt {t:Type} int t = CoupleInt t;
intHash {t:Type} (vector %(CoupleInt t)) = IntHash t;
coupleStr {t:Type} string t = CoupleStr t;
strHash {t:Type} (vector %(CoupleStr t)) = StrHash t;
```

Знак процента здесь означает, что берётся bare-тип, соответствующий указанному в скобках boxed-типу; при этом у такого boxed-типа должно быть не более одного конструктора — при любых значениях параметров.

Ключи могут быть упорядочены, а могут идти в произвольном порядке (как в массивах PHP). Для ассоциативных массивов с упорядоченными ключами используются псевдонимы IntSortedHash или StrSortedHash:

```
intSortedHash {t:Type} (intHash t) = IntSortedHash t;
strSortedHash {t:Type} (strHash t) = StrSortedHash t;
```

#### Конструкторы полиморфных типов

Конструктор полиморфного типа не зависит от конкретных типов, к которым этот полиморфный тип применяется. При вычислении номера конструктора необязательные параметры (обычно содержащие переменные типа и записанные в фигурных скобках) перестают быть необязательными (фигурные скобки убираются), а кроме того, убираются и все круглые скобки. Таким образом,

```
vector {t:Type} # [ t ] = Vector t;
```

соответствует номеру конструктора crc32("vector t:Type # \[ t \] = Vector t") = 0x1cb5c415. При (де)сериализации конкретные значения необязательной переменной t выводятся из типа результата (то есть из сериализуемого или десериализуемого объекта), который всегда известен, и никогда не сериализуются явно.

Раньше требовалось заранее знать, к каким именно типам переменных будет применяться каждый полиморфный тип. Для этого система типов использовала строки вида

```
polymorphic_type_name type_1 ... type_N;
```

Например,

```
Vector int;
Vector string;
Vector Object;
```

Теперь такие строки игнорируются.

См. также [полиморфизм в TL](/mtproto/TL-polymorph/).

В данном случае псевдотип Object позволяет использовать Vector Object для хранения списков чего угодно (значений любых boxed-типов). Поскольку bare-типы эффективны при небольшой длине, на практике вряд ли потребуются случаи сложнее приведённых выше.

#### Имена полей

Допустим, нам нужно представить _пользователей_ тройками, состоящими из одного целого числа (идентификатора пользователя) и двух строк (имени и фамилии). Нужная структура данных — тройка int, string, string, которую можно объявить так:

```
user int string string = User;
```

С другой стороны, группу можно описать похожей тройкой, состоящей из идентификатора группы, её названия и описания:

```
group int string string = Group;
```

Чтобы разница между User и Group была очевидной, удобно назначить имена некоторым или всем полям:

```
user id:int first_name:string last_name:string = User;
group id:int title:string description:string = Group;
```

Если впоследствии тип User потребуется расширить, добавив записи с каким-либо дополнительным полем, это можно сделать следующим образом:

```
userv2 id:int unread_messages:int first_name:string last_name:string in_groups:vector int = User;
```

Помимо прочего, такой подход помогает задавать корректные соответствия между полями разных конструкторов одного и того же типа, преобразовывать их друг в друга, а также превращать значения типа в ассоциативный массив со строковыми ключами (имена полей, если они заданы, — естественный выбор для таких ключей).
