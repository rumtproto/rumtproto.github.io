# Язык TL

Оригинальное русскоязычное описание языка описания типов, которым задаются все структуры данных и методы Telegram. Первоисточник: [core.telegram.org/mtproto/TL](https://core.telegram.org/mtproto/TL).

TL (Type Language) — формальный язык, на котором записана вся схема данных: типы, конструкторы, методы и их сериализация. Из одного описания на TL автоматически генерируются парсеры и сериализаторы для любого языка программирования.

## Основные понятия

- **Тип** — множество значений (например, `Bool`, `User`, [`Message`](/type/Message/)).
- **Конструктор** — способ построить значение типа; у каждого конструктора есть уникальное имя и 32-битный идентификатор:

```
boolFalse#bc799737 = Bool;
boolTrue#997275b5 = Bool;
```

- **Метод (функция)** — запрос, имеющий список параметров и тип результата:

```
messages.sendMessage#a67574d8 flags:# ... = Updates;
```

- **Схема** — набор объявлений; актуальная схема — [здесь](/schema/), слой протокола — [здесь](/schema/mtproto/), секретные чаты — [здесь](/schema/end-to-end/).

## Синтаксис вкратце

```
имя_конструктора#идентификатор поле1:Тип1 поле2:Тип2 ... = ИмяТипа;
имя_метода#идентификатор параметр:Тип ... = ТипРезультата;
```

- `#идентификатор` — 32-битный номер, с которого начинается сериализованное значение; может быть вычислен автоматически (хеш от объявления), тогда записывается просто `#`.
- `flags:#` — битовая маска; поля вида `flags.N?Тип` присутствуют, только если установлен бит `N` (см. [сериализацию](/mtproto/serialize/)).
- `Vector t` — список элементов типа `t`.
- Слой схемы задаётся директивой `---layer---` и определяет набор доступных объявлений (см. [Слои схемы](/api/layers/)).

## Разделы спецификации языка

Оригинальная документация разбирает язык по частям; ключевые темы:

- **Комбинаторы и типы** — как устроены объявления;
- **Абстрактные типы** — типы, значения которых строятся одним из нескольких конструкторов (например, [`Peer`](/type/Peer/));
- **Опциональные поля** (`flags`) — компактные «флаговые» параметры;
- **Полиморфизм** — конструкторы и методы, параметризованные другими типами;
- **Зависимые типы** — поля, тип которых зависит от значений других полей;
- **Шаблоны (паттерны)** — сопоставление значений схемы.

Справочник по всем этим темам на английском — в разделе [оригинальных статей о TL](https://core.telegram.org/mtproto/TL); на этом сайте доступны сгенерированные справочники: [конструкторы](/constructor/), [методы](/method/), [типы](/type/).

## Практика

- Машиночитаемая схема в формате JSON: [/schema/json](/schema/json/) — удобна для кодогенерации.
- При реализации клиента удобно генерировать структуры из схемы, а не писать их вручную: новые слои будут добавлять поля, и генератор обновит код автоматически.
- Неизвестные конструкторы при парсинге следует пропускать по их объявленной структуре, а не аварийно завершаться.
