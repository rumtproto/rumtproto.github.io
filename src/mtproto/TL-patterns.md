# Шаблонные типы TL

_partial-app-decl_ ::= _partial-type-app-decl_ | _partial-comb-app-decl_  
_partial-type-app-decl_ ::= _boxed-type-ident_ _subexpr_ { _subexpr_ } `;` | _boxed-type-ident_ `<` _expr_ { `,` _expr_ } `>` `;`  
_partial-comb-app-decl_ ::= _combinator-id_ _subexpr_ { _subexpr_ } `;`

Согласно первоначальному замыслу, шаблоны обязаны применяться для подстановки конкретных значений в первые несколько или во все необязательные аргументы конструктора либо полиморфного типа. Например, если `Tuple int 10` используется часто, для него можно объявить шаблон, и тогда подходящие конструкторы будут сгенерированы автоматически. При использовании такого конструктора может оказаться, что тип `int` или размер кортежа `10` попросту некуда передавать. Точно так же изначально предполагалось объявлять шаблоны для `Vector int`, `Vector string` и т. п., чтобы породить собственный конструктор для каждого используемого типа вектора. Такие конструкторы позволили бы при десериализации определить, массив какого рода передаётся.

Сейчас шаблоны не используются. Вместо них применяются одни и те же универсальные конструкторы (например, `vector {t:Type} [t] = Vector t`), а значения необязательных параметров выводятся из типа результата (если из схемы уже известно, что при десериализации в этом месте должен находиться `Vector int`, то понятно, что мы увидим универсальный конструктор `vector`, в котором _t_ равно `int`).

Этот подход лучше тем, что не требуется заранее определять шаблоны `Vector SomeType` для всех возможных типов, чтобы для каждого такого случая породить собственный конструктор. Тем не менее у него есть недостаток. Если кто-то захочет передать сериализацию значения «одетого» типа `Vector int` как сериализацию значения типа `Object`, при сериализации возникает проблема: увидев универсальный конструктор `vector` и прочитав затем длину вектора, мы не можем определить, значения какого типа следует ожидать дальше.

[@note] В оригинале здесь сказано «при сериализации», хотя описанные действия — чтение конструктора и длины вектора — относятся к десериализации. Формулировка сохранена как есть; по существу речь о том, что записанное таким образом значение невозможно прочитать обратно, не зная типа его элементов.

В принципе, эту проблему можно решить, воспользовавшись полной формой конструктора (`@vector`), соответствующей `vector` (она определяется автоматически и отличается тем, что все необязательные параметры становятся обязательными), либо определив

object X:Type X = TypedObject

и передавая тип объекта явно. В обоих случаях требуется [сериализация типа](TL-types).
