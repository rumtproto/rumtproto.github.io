# Сериализация типов

См. [Полиморфизм в TL](/mtproto/TL-polymorph/) и [Язык TL](/mtproto/TL/).

Осталось описать, как передаются (сериализуются) типы, то есть значения типа Type. Ничего неожиданного здесь в целом не происходит: есть конструкторы типов разной арности (скажем, List — конструктор арности 1, а IntList — конструктор арности 0), и если известно, что каждому конструктору типа сопоставлено 32-битное «имя», то остальное вопросов не вызывает — значения типа Type сериализуются точно так же, как значения любого другого рекурсивного типа с заданным набором конструкторов разной арности.

[@term:bare] [@term:boxed] Как сопоставить 32-битное «имя» типу — точнее, конструктору типа — вроде List или IntList? Предлагается брать сумму имён всех его конструкторов плюс CRC32 строки, где записаны имя типа и все его параметры, например «IntList = Type» или «List X:Type = Type». Так, «имя» конструктора List — это сумма CRC32 трёх строк: "List X:Type = Type", "cons X:Type hd:X tl:List X = List X" и "nil X:Type = List X". С «голыми» (`bare`) типами, которые формально представляют собой подтипы отвечающего им «упакованного» (`boxed`) типа, дело обстоит несколько сложнее: для них берётся логическое отрицание имени соответствующего конструктора. Для встроенных голых и упакованных типов (например, int и Int) применяется псевдообъявление (например, int ? = Int").

[@note] Голое значение передаётся без 32-битного идентификатора конструктора, а упакованное — с ним впереди. Поэтому «имена» голого и упакованного вариантов одного типа обязаны различаться; «логическое отрицание» здесь означает побитовую инверсию 32-битного значения.

-   Это описание несколько устарело и в будущем может быть обновлено. В частности, не объяснено, как следует трактовать модификатор `!`.\*
