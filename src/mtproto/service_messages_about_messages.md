# Сообщения о сообщениях

Оригинальное русскоязычное описание механизмов подтверждения, запроса состояния и повторной отправки. Первоисточник: [core.telegram.org/mtproto/service_messages_about_messages](https://core.telegram.org/mtproto/service_messages_about_messages).

Протокол не полагается на транспортную доставку: сторона сама отслеживает, какие сообщения доставлены и обработаны, с помощью специальных «сообщений о сообщениях».

## Статусы сообщений

Про каждое отправленное содержательное сообщение сторона знает одно из состояний:

- не получено получателем;
- получено, но не обработано (лежит в очереди);
- обработано (ответ вычислен или сообщение применено);
- ответ уже доставлен отправителю.

Для запроса и передачи статусов используются следующие конструкторы.

### [`msgs_state_req`](https://core.telegram.org/constructor/msgs_state_req/) — запрос состояния

Список идентификаторов сообщений, о которых нужно узнать статус. Ответ — [`msgs_state_info`](https://core.telegram.org/constructor/msgs_state_info/).

### [`msgs_state_info`](https://core.telegram.org/constructor/msgs_state_info/) — сведения о состоянии

Для каждого запрошенного идентификатора возвращается байт с флагами: получено ли сообщение, обработано ли оно, доставлен ли ответ.

### [`msgs_all_info`](https://core.telegram.org/constructor/msgs_all_info/) — сведения обо всех сообщениях сессии

Полный дамп состояний по всей сессии (полезен после переподключения, когда нужно понять, что «пропало»).

## Повторная отправка

### [`msg_resend_req`](https://core.telegram.org/constructor/msg_resend_req/) / [`msg_resend_ans_req`](https://core.telegram.org/constructor/msg_resend_ans_req/)

Просьба отправить заново сообщения по идентификаторам: первое — сами сообщения, второе — ответы на запросы. Если повторная отправка невозможна (например, ответ уже удалён), сервер вместо этого присылает `msgs_state_info`.

### [`msg_detailed_info`](https://core.telegram.org/constructor/msg_detailed_info/) и [`msg_new_detailed_info`](https://core.telegram.org/constructor/msg_new_detailed_info/)

Развёрнутый ответ на запрос состояния: `answer_msg_id` — идентификатор сообщения с ответом, `status` — статус. Вариант `msg_new_detailed_info` приходит без запроса, когда сервер узнаёт, что клиент, вероятно, пропустил ответ.

## Подтверждения

[`msgs_ack`](https://core.telegram.org/constructor/msgs_ack/) — основной способ подтвердить получение сообщения. Правила:

- подтверждение само не требует подтверждения и не считается содержательным сообщением (не увеличивает счётчик `seq_no`);
- получатель запроса обязан подтвердить его, даже если ещё не обработал;
- отправитель, не дождавшийся ни подтверждения, ни ответа за разумное время, может повторить сообщение (с тем же `message_id`), запросить состояние или пересоздать сессию;
- дубликаты идентификаторов получатель обязан игнорировать (защита от повторов).

## Практические рекомендации

1. Держите окно недавно виденных `message_id` (например, за несколько минут по времени сервера) и отбрасывайте повторы.
2. При долгом отсутствии подтверждений сначала отправляйте `msg_resend_req`/`msgs_state_req` и только затем пересоздавайте сессию.
3. После переподключения запрашивайте состояние «повисших» запросов через `msgs_state_req`, чтобы не выполнять повторно операции с побочными эффектами. Безопасно повторять такие операции (например, отправку сообщений) помогает `random_id` на уровне API.
