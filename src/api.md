# Telegram API

Оригинальный русскоязычный обзор уровня «приложение» — надстройки над [протоколом MTProto](/mtproto/). Первоисточник со всеми подразделами: [core.telegram.org/api](https://core.telegram.org/api).

Протокол отвечает на вопрос «как байты доходят до сервера и шифруются»; уровень API отвечает на вопрос «какие методы вызвать и как обрабатывать события». Все методы и типы — в [схеме](/schema/); ниже — ключевые темы для реализации клиента.

## Базовый сценарий клиента

1. **Получить `api_id`/`api_hash`** — идентификаторы приложения (выдаются на [my.telegram.org](https://my.telegram.org)).
2. **Создать `auth_key`** — см. [Создание авторизационного ключа](/mtproto/auth_key/).
3. **Авторизовать пользователя или бота** — обмен кодом и паролем описан в разделе [Авторизация](/api/auth/).
4. **Инициализация соединения** — [`initConnection`](/method/initConnection/) поверх первого запроса: сообщает о приложении, устройстве, языке; в ответ сервер присылает конфигурацию ([`help.getConfig`](/method/help.getConfig/)).
5. **Синхронизация времени и солей**, далее — обычный обмен запросами и обновлениями.

## Основные темы

### Авторизация

Обмен кодом из СМС, двухфакторный пароль, выход и завершение сессий: [`auth.sendCode`](/method/auth.sendCode/), [`auth.signIn`](/method/auth.signIn/), [`auth.signUp`](/method/auth.signUp/), [`auth.checkPassword`](/method/auth.checkPassword/) и др. Подробности — в разделе [Авторизация](/api/auth/).

### Обновления (события)

Сервер присылает [обновления](/type/Update/) — новые сообщения, изменения чатов, статусы и т.д. Клиент обязан уметь: запрашивать разницу (`updates.getDifference`), обрабатывать пропуски (`pts`, `qts`, `date`), применять обновления в правильном порядке. Обзор — в разделе [Получение обновлений](/api/updates/).

### Файлы

Загрузка и скачивание файлов с поддержкой докачки и параллельных частей: [`upload.saveFilePart`](/method/upload.saveFilePart/), [`upload.getFile`](/method/upload.getFile/), локации файлов ([`InputFileLocation`](/type/InputFileLocation/)) и `file references`. Обзор — в разделе [Работа с файлами](/api/files/).

### Как вызывать методы

Правила уровня `layer`, повторные вызовы, флуд-контроль, ошибки: [вызов методов](/api/invoking/) и [ошибки](/api/errors/).

### Сквозное шифрование

- [Секретные чаты](/api/end-to-end/) — переписка, которую не может прочитать сервер.
- [Perfect Forward Secrecy](/api/pfs/) — сменяемые ключи секретных чатов.

### Прочие разделы оригинала

Полный список тем (боты, платежи, каналы, стикеры, истории, веб-приложения и десятки других) — на странице [оригинала](https://core.telegram.org/api): этот сайт сосредоточен на протоколе и базовых темах, а тематические статьи даются ссылками на английский оригинал, поскольку это развивающаяся документация функций приложения.
