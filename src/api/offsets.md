# Постраничная выборка в API

Многие методы Telegram API дают доступ к потенциально большим спискам объектов, а это требует постраничной выборки.

Чтобы за один запрос получать только нужное подмножество результатов, предусмотрен ряд входных параметров. Ниже они перечислены в том порядке, в котором их применяет API.

Как правило, результаты возвращаются в обратном хронологическом порядке, то есть по убыванию значений идентификаторов объектов.

### Параметр `limit`

[@term:limit] Ограничение на количество возвращаемых объектов — `limit` задаёт верхнюю границу размера страницы, обычно от 1 до 100. Если передан 0, ограничение часто принимает промежуточное значение по умолчанию — около 20.

### Постраничная выборка по `offset`

[@term:offset] В немногих методах, работающих преимущественно со статическими данными, этот параметр задаёт смещение: он позволяет пропустить `offset` элементов от начала списка; в некоторых случаях допускаются отрицательные значения.

### Постраничная выборка по `offset_id`

[@term:offset_id] [@term:add_offset] В большинстве методов, где результаты приходят в реальном времени (например, история любого чата), значение `offset` напрямую не передаётся. Вместо этого оно вычисляется по переданным `offset_id` (идентификатор результата, от которого ведётся отсчёт) и `add_offset` (поправка к вычисленному смещению) как `offsetFromID(offset_id) + add_offset`, где `offsetFromID(offset_id)` — количество результатов от начала списка до результата с идентификатором `offset_id` включительно.

Примеры использования:

-   Загрузить 20 сообщений старше сообщения с идентификатором `MSGID`:

    `messages.getHistory({offset_id: MSGID, add_offset: 0, limit: 20})`

-   Загрузить 20 сообщений новее сообщения с идентификатором `MSGID`:

    `messages.getHistory({offset_id: MSGID, add_offset: -20, limit: 20})`

-   Загрузить 20 сообщений вокруг сообщения с идентификатором `MSGID`:

    `messages.getHistory({offset_id: MSGID, add_offset: -10, limit: 20})`

### Дополнительная фильтрация

Есть ещё несколько параметров: их применяют к списку уже после того, как из него выделен срез по смещению и ограничению, — чтобы ещё сильнее сузить итоговую выдачу:

-   **max\_id**: позволяет вернуть только результаты с идентификатором строго меньше `max_id` (например, с идентификатором сообщения)
-   **min\_id**: позволяет вернуть только результаты с идентификатором строго больше `min_id` (например, с идентификатором сообщения)

-   **min\_date**: позволяет вернуть только результаты новее `min_date`:
-   **hash**: см. ниже.

### Вычисление хеша

Чтобы сузить итоговое подмножество ещё сильнее, предусмотрен механизм, который позволяет вовсе не загружать данные, если получившийся список не изменился по сравнению с сохранённым на клиенте, — по аналогии с [ETag](https://en.wikipedia.org/wiki/HTTP_ETag).

[@term:hash] Если у клиента есть закешированные результаты запроса к API, он может вычислить для них значение `hash` (хеш выборки — контрольная сумма уже полученного списка): для этого берут идентификаторы результатов — идентификаторы сообщений либо другие поля с именем `id`, а иногда и дополнительные поля — и по ним считают 64-битный хеш по следующему алгоритму:

```
# Here, ^ indicates a bitwise XOR

hash = 0
for id in ids:
    hash = hash ^ (hash >> 21)
    hash = hash ^ (hash << 35)
    hash = hash ^ (hash >> 4)
	hash = hash + id
```

Оператор `>>` здесь — беззнаковый сдвиг вправо.

Обратите внимание: иногда массив `ids`, передаваемый алгоритму, обязан содержать строки (скажем, краткое имя шаблона быстрых ответов и тому подобное). Тогда их преобразуют в значения типа long: берут первые 8 байт MD5-хеша строки (**не** в шестнадцатеричном виде) и трактуют их как 64-битное целое в порядке big-endian.

Иногда у контейнера с результатами уже есть готовое поле `hash` — тогда можно взять его.

Если клиент передал верное и актуальное значение, API вернёт вместо самих результатов один из конструкторов `*NotModified`, например [messages.messagesNotModified](/constructor/messages.messagesNotModified/).

### Примеры методов

-   [messages.getHistory](/method/messages.getHistory/) поддерживает все параметры навигации по результатам, включая хеши идентификаторов сообщений, но не поддерживает фильтры
-   [channels.getParticipants](/method/channels.getParticipants/) поддерживает простую навигацию с помощью **limit** и **offset**, а также фильтрацию и сокращение выдачи по `hash`, который вычисляется по идентификаторам возвращаемых пользователей
