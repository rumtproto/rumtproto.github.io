# Веб-события

[@term:Mini App] При работе с HTML5-играми, сайтами платёжных шлюзов и [Mini App ботов](/api/bots/webapps/) (Mini App — веб-приложение, открываемое прямо внутри клиента Telegram) приложения Telegram должны предоставлять API, позволяющие получать данные и события от этих сайтов.

### API событий

Игры, платёжные шлюзы и [Mini App ботов](/api/bots/webapps/) могут порождать события, предназначенные для приложений Telegram. Обычно события порождаются методом `postEvent` из [библиотеки GamingCommunication](https://github.com/TelegramMessenger/GamingCommunication/blob/master/games.js) либо [библиотекой Mini App для ботов](https://core.telegram.org/bots/webapps#initializing-mini-apps).  
Функция `postEvent` пытается доставить событие приложению Telegram несколькими разными способами.

#### WebviewProxy

В мобильных приложениях API приёма событий обычно предоставляется в виде объекта `window.TelegramWebviewProxy` с методом `postEvent`.

```
window.TelegramWebviewProxy.postEvent(eventType, eventData)
```

#### window.external

В качестве альтернативы может предоставляться метод `window.external.notify`, принимающий строку с JSON, в которой указаны тип события и его полезная нагрузка:

```
window.external.notify(JSON.stringify({eventType: eventType, eventData: eventData}));
```

#### postMessage API

Наконец, веб-клиенты MTProto, которым нужно открыть игру, открыть [Mini App бота](/api/bots/webapps/) или провести платёж в iframe, могут использовать [postMessage API](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) для получения событий из iframe.  
Библиотеки GamingCommunication и Mini App для ботов по умолчанию используют `'*'` в качестве `targetOrigin`, то есть отправляют сообщения родительским страницам независимо от источника встраивающей страницы.

```
window.parent.postMessage(JSON.stringify({eventType: eventType, eventData: eventData}), targetOrigin);
```

### Типы событий

`eventType` — простая строка, указывающая тип события, а `eventData` — полезная нагрузка в виде объекта, который будет разобран приложением Telegram.

#### `payment_form_submit`

Полезная нагрузка события: JSON-объект с полями `credentials` и `title`.

-   `title` — замаскированное название банковской карты.
-   `credentials` — специфичный для сервиса JSON-объект со сведениями о платёжных реквизитах, которые пользователь передал платёжной системе.

**Ни Telegram, ни боты не получат доступ к данным вашей банковской карты.**  
Реквизиты карты обрабатываются исключительно платёжной системой, см. [документацию по платежам, подробнее »](/api/payments/).

#### `share_score`

Полезной нагрузки нет.

Вызывается играми, когда пользователь явно нажимает кнопку **поделиться результатом**, чтобы поделиться игрой вместе со своим результатом.  
Обычно это делается вызовом [messages.forwardMessages](/method/messages.forwardMessages/) для сообщения с игрой с установленным флагом `with_my_score`.

#### `share_game`

Полезной нагрузки нет.

Вызывается играми, когда пользователь явно нажимает кнопку **поделиться игрой**, чтобы поделиться игрой без своего результата.  
[@term:deep link] Обычно это делается вызовом [messages.forwardMessages](/method/messages.forwardMessages/) для сообщения с игрой без флага `with_my_score` либо отправкой [глубокой ссылки](/api/links/#game-links) на игру (`deep link` — ссылка вида `tg://…` или `https://t.me/…`, открывающая нужный экран приложения).

#### `web_app_close`

Полезной нагрузки нет либо передаётся JSON-объект со следующими полями (клиент должен их корректно проверить).

-   `return_back` — если поле истинно, а веб-приложение было открыто по [глубокой ссылке](/api/links/) из другого приложения (то есть не по глубокой ссылке внутри клиента Telegram), клиенту Telegram следует вернуться в приложение, которое открыло ссылку, а не на главный экран клиента Telegram. (логическое значение, необязательное)

[@term:webview] Порождается [Mini App ботов](/api/bots/webapps/), когда webview (встроенное окно браузера, в котором открыт Mini App) следует закрыть.

#### `web_app_open_popup`

Данные события: JSON-объект со следующими полями (клиент обязан их корректно проверить).

-   `title` — заголовок всплывающего окна (строка, необязательное, не более 64 символов)
-   `message` — текст всплывающего окна (строка, не более 256 символов)
-   `buttons` — массив объектов следующего вида (массив из 1–3 объектов)
    -   `type` — тип кнопки (строка, одно из значений `ok`, `close`, `cancel`, `default`, `destructive` (в этом случае кнопка должна быть красной))
    -   `text` — текст кнопки (строка, необязательное для типов `ok`, `close` и `cancel`)
    -   `id` — идентификатор кнопки (уникальная строка)

Порождается [Mini App ботов](/api/bots/webapps/), чтобы открыть поверх webview всплывающее окно средствами системы.

По умолчанию кнопки следует размещать в один ряд.  
Если Mini App передаёт две кнопки, которые не помещаются по горизонтали в один ряд, каждую кнопку следует вывести в отдельном ряду.  
Если Mini App передаёт три кнопки, каждую кнопку всегда следует выводить в отдельном ряду.

-   Если пользователь нажимает любую из кнопок, вызовите `window.Telegram.WebView.receiveEvent("popup_closed", {"button_id": "<button id>"})`
-   Если пользователь прерывает взаимодействие, не нажав ни одну из заданных кнопок, вызовите `window.Telegram.WebView.receiveEvent("popup_closed", {})`

Отключите обработку этого события, пока всплывающее окно уже показано, и включите её снова только после того, как будет отправлено ответное событие `popup_closed`.  
Пока обработка включена, допускается обработать не более 3 подряд идущих корректных событий этого типа за 3 секунды; лишние события игнорируются.

#### `web_app_request_write_access`

Данные события: `null`

Порождается [Mini App ботов](/api/bots/webapps/), чтобы запросить у пользователя разрешение отправлять ему сообщения.

Получив это событие, клиенту следует сначала вызвать [bots.canSendMessage](/method/bots.canSendMessage/) и проверить, не выдал ли пользователь боту разрешение писать ему тем или иным способом ранее.

-   Если метод возвращает [boolTrue](/constructor/boolTrue/), в Mini App следует отправить [событие write\_access\_requested »](/api/bots/webapps/#write-access-requested) со значением `{"status": "allowed"}`.
-   Иначе, если метод возвращает [boolFalse](/constructor/boolFalse/), пользователю следует показать запрос с сообщением о том, что бот просит разрешение отправлять ему сообщения.  
    Если пользователь соглашается, вызовите [bots.allowSendMessage](/method/bots.allowSendMessage/), и при успешном вызове метода отправьте [событие write\_access\_requested »](/api/bots/webapps/#write-access-requested) со значением `{"status": "allowed"}`.  
    Иначе, если пользователь отказывается или вызов [bots.allowSendMessage](/method/bots.allowSendMessage/) завершается ошибкой, отправьте [событие write\_access\_requested »](/api/bots/webapps/#write-access-requested) со значением `{"status": "cancelled"}`.

#### `web_app_request_phone`

Данные события: `null`

Порождается [Mini App ботов](/api/bots/webapps/), чтобы попросить пользователя поделиться своим номером телефона в виде контакта.

Получив это событие, клиент должен показать пользователю запрос с сообщением о том, что бот просит его поделиться номером телефона (при необходимости — также с предложением разблокировать бота, если тот сейчас заблокирован).

Если пользователь соглашается, его номер телефона передаётся отправкой боту контакта (предварительно бота следует разблокировать, если пользователь его заблокировал); если все RPC-запросы (на разблокировку бота и на отправку сообщения) выполнены успешно, следует отправить [событие phone\_requested »](/api/bots/webapps/#write-access-requested) со значением `{"status": "sent"}`.

Если пользователь отказывается или любой из промежуточных вызовов метода завершается ошибкой, следует отправить [событие phone\_requested »](/api/bots/webapps/#write-access-requested) со значением `{"status": "cancelled"}`.

[@note] Обе ссылки на событие `phone_requested` ведут на якорь `#write-access-requested` — это ошибка в оригинале, сохранённая здесь дословно. Описание самого события `phone_requested` следует искать в документации по Mini App отдельно.

#### `web_app_biometry_get_info`

Данные события: `null`

Порождается [Mini App ботов](/api/bots/webapps/), чтобы клиент инициализировал объект менеджера биометрической аутентификации для текущего бота; по завершении порождается [событие `biometry_info_received` »](/api/bots/webapps/#biometry-info-received).

Этот запрос должен лишь инициализировать состояние на стороне клиента, то есть проверить, доступна ли биометрическая аутентификация в принципе; ничего спрашивать у пользователя он не должен.

#### `web_app_biometry_request_access`

Данные события: JSON-объект с необязательным строковым полем `reason` (1–128 символов, используется в запросе), содержащим причину, по которой бот просит разрешение на биометрическую аутентификацию.

Порождается [Mini App ботов](/api/bots/webapps/), чтобы запросить у пользователя разрешение на использование биометрической аутентификации; по завершении порождается [событие `biometry_info_received` »](/api/bots/webapps/#biometry-info-received).

Этот запрос не должен запускать саму биометрическую аутентификацию — он должен лишь запросить у пользователя разрешение на её использование через всплывающее окно, которое показывается только **один раз** (для данного бота): окно не должно показываться, если пользователь ранее уже разрешил, отклонил или отменил запрос разрешения на биометрию от этого бота.

#### `web_app_biometry_update_token`

Данные события: JSON-объект со следующими полями:

-   `token` — новый токен (строка, 0–1024 символа) либо пустая строка для его удаления.
-   `reason` — необязательное строковое поле, содержащее причину, по которой бот просит выполнить аутентификацию с помощью биометрии (1–128 символов, используется в запросе).

Порождается [Mini App ботов](/api/bots/webapps/), чтобы выполнить аутентификацию по биометрии и надёжно сохранить биометрический токен на устройстве; по завершении порождается [событие `biometry_token_updated` »](/api/bots/webapps/#biometry-token-updated).

Этот токен (им может быть, например, закрытый ключ криптовалютного кошелька или иные данные, которые приложению нужно держать в безопасности) обязан надёжно храниться клиентом Telegram и быть привязан к боту, которому принадлежит Mini App.

Например, токен может храниться непосредственно в защищённом хранилище устройства и быть доступным только после биометрической аутентификации, либо он может храниться в обычном, незащищённом хранилище, но **в зашифрованном виде** — зашифрованным на ключе, который возвращает защищённое хранилище устройства после биометрической аутентификации (например, на Android — с помощью объекта CryptoObject, возвращаемого в [результате биометрического запроса](https://developer.android.com/reference/android/hardware/biometrics/BiometricPrompt.AuthenticationResult#getCryptoObject\(\))).

Если пользователь [ранее запретил](#web-app-biometry-request-access) боту использовать биометрическую аутентификацию, этот запрос должен немедленно завершиться неудачей с порождением соответствующего [события `biometry_token_updated` »](/api/bots/webapps/#biometry-token-updated).

#### `web_app_biometry_request_auth`

Данные события: JSON-объект с необязательным строковым полем `reason`, содержащим причину, по которой бот просит выполнить аутентификацию с помощью биометрии (1–128 символов, используется в запросе).

Порождается [Mini App ботов](/api/bots/webapps/), чтобы выполнить аутентификацию с помощью биометрии и получить [ранее сохранённый защищённый токен](#web-app-biometry-update-token); по завершении порождается [событие `biometry_auth_requested` »](/api/bots/webapps/#biometry-auth-requested), содержащее либо ошибку, либо расшифрованный [биометрический токен »](#web-app-biometry-update-token) (либо пустую строку, если токен ещё не задан).

Использовать это событие следует, только если поле `token_saved` [объекта biometry\_info\_received »](/api/bots/webapps/#biometry-info-received) равно `true`; в противном случае сначала задайте новый токен с помощью [web\_app\_biometry\_update\_token »](#web-app-biometry-update-token).

Если пользователь [ранее запретил](#web-app-biometry-request-access) боту использовать биометрическую аутентификацию, этот запрос должен немедленно завершиться неудачей с порождением соответствующего [события `biometry_auth_requested` »](/api/bots/webapps/#biometry-auth-requested).

#### `web_app_biometry_open_settings`

Данные события: `null`

Порождается [Mini App ботов](/api/bots/webapps/), чтобы открыть страницу настроек биометрической аутентификации для ботов; это полезно, когда приложению нужно запросить разрешение на использование биометрии у пользователей, которые ранее в нём отказали.

Обратите внимание: это событие следует обрабатывать только в ответ на действие пользователя в интерфейсе Mini App (например, нажатие внутри Mini App или на главную кнопку), и обрабатываться оно должно не чаще одного раза в секунду.

#### `web_app_invoke_custom_method`

Данные события: JSON-объект со следующими полями:

-   `req_id` — строка с идентификатором текущего запроса
-   `method` — строка с именем вызываемого пользовательского метода
-   `params` — объект с параметрами вызова метода

Порождается [Mini App ботов](/api/bots/webapps/) для вызова пользовательских методов на серверах Telegram от имени пользователя.

Это событие должно приводить к запросу [bots.invokeWebViewCustomMethod](/method/bots.invokeWebViewCustomMethod/), в котором `method` передаётся в `custom_method`, а `params` — в `params`.

При получении ответа должно порождаться [событие custom\_method\_invoked »](/api/bots/webapps/#custom-method-invoked) со следующими полями:

-   `req_id` — значение `req_id` из объекта `web_app_invoke_custom_method`
-   `result` — JSON-данные из ответа метода [bots.invokeWebViewCustomMethod](/method/bots.invokeWebViewCustomMethod/), если вызов метода прошёл успешно
-   `error` — текст ошибки RPC, если вызов метода завершился неудачей

#### `web_app_read_text_from_clipboard`

Данные события: JSON-объект со следующими полями:

-   `req_id` — строка с идентификатором текущего запроса

Порождается [Mini App ботов](/api/bots/webapps/) для получения содержимого системного буфера обмена.

Только для Mini App, принадлежащих ботам, которые добавлены в [меню вложений](/api/bots/attach/) или перечислены в параметре конфигурации [`whitelisted_bots` »](/api/config/#whitelisted-bots) — независимо от того, каким образом был запущен сам Mini App, — это событие должно приводить к порождению [события clipboard\_text\_received »](/api/bots/webapps/#clipboard-text-received) со следующими данными:

-   `req_id` — значение `req_id` из запроса `web_app_read_text_from_clipboard`
-   `data` — строка с содержимым буфера обмена

Обратите внимание: этот метод может вызываться только в ответ на действие пользователя в интерфейсе Mini App (например, нажатие внутри Mini App либо на главную кнопку или кнопку настроек).  
Учтите, что у действий пользователя есть срок жизни в 10 секунд: если последнее действие пользователя в Mini App (как описано выше) произошло более 10 секунд назад, события этого типа обязательно игнорировать и отправить [событие clipboard\_text\_received »](/api/bots/webapps/#clipboard-text-received) с правильным `req_id` и без поля `data`.

[Событие clipboard\_text\_received »](/api/bots/webapps/#clipboard-text-received) с правильным `req_id` и без поля `data` обязательно отправить и в том случае, если бот не добавлен в [меню вложений](/api/bots/attach/) и не перечислен в параметре конфигурации [`whitelisted_bots` »](/api/config/#whitelisted-bots).

#### `web_app_open_scan_qr_popup`

Данные события: JSON-объект со следующими полями:

-   `text` — необязательная строка с текстом, который отображается под заголовком «Сканировать QR-код», 0–64 символа.

Порождается [Mini App ботов](/api/bots/webapps/), чтобы клиент открыл встроенный сканер QR-кодов и начал непрерывное сканирование QR-кодов.

[Событие `qr_text_received` »](/api/bots/webapps/#qr-text-received) должно порождаться каждый раз при сканировании нового QR-кода — до тех пор, пока пользователь не закроет всплывающее окно через интерфейс либо Mini App не закроет его событием [web\_app\_close\_scan\_qr\_popup](#web-app-close-scan-qr-popup).

При закрытии всплывающего окна должно порождаться [событие `scan_qr_popup_closed` »](/api/bots/webapps/#scan-qr-popup-closed); это же событие должно порождаться, если окно сканирования QR-кода не удаётся открыть из-за отсутствия разрешений.

#### `web_app_close_scan_qr_popup`

Данные события: `null`

Порождается [Mini App ботов](/api/bots/webapps/), чтобы клиент закрыл встроенный сканер QR-кодов, открытый с помощью [web\_app\_open\_scan\_qr\_popup](#web-app-open-scan-qr-popup).

[Событие `scan_qr_popup_closed` »](/api/bots/webapps/#scan-qr-popup-closed) порождаться _не_ должно, если окно с QR-кодом закрыто этим событием.

#### `web_app_setup_closing_behavior`

Данные события: JSON-объект с булевым полем `need_confirmation`.

Если поле равно `true`, клиенту следует, прежде чем закрыть webview, запросить у пользователя подтверждение всплывающим окном с текстом «Внесённые изменения могут быть не сохранены.» и кнопками «Отмена»/«Всё равно закрыть», чтобы случайно не прервать ответственную операцию; в противном случае подтверждение запрашивать не следует.

#### `web_app_set_background_color`

Данные события: JSON-объект со строковым полем `color`, содержащим цвет в шестнадцатеричном формате RGB.

Учтите, что у действий пользователя есть срок жизни в 1 секунду: события этого типа обязательно игнорировать, если последнее действие пользователя в Mini App произошло более 1 секунды назад.

#### `web_app_setup_main_button`

Полезная нагрузка события: JSON-объект со следующими полями:

-   `is_visible` — видима ли главная кнопка (булево, по умолчанию false)

-   `text_color` — цвет текста кнопки в шестнадцатеричном формате RGB (строка, по умолчанию берётся [параметр темы `button_text_color`](/api/bots/webapps/#theme-parameters))
-   `is_progress_visible` — показывает, должна ли кнопка отображать индикатор загрузки (булево, по умолчанию false)

В некоторых клиентах реализована горизонтальная панель вкладок с типами медиа, расположенная внизу экрана и открывающаяся по нажатию на кнопку меню вложений: эта панель содержит горизонтальный список кнопок для прикрепления медиа определённого типа и для открытия установленных [Mini App из меню вложений](/api/bots/attach/).

В остальных случаях главную кнопку можно показать сразу, без всякого действия пользователя, как только получено событие `web_app_setup_main_button` с `is_visible=true`.

Используется [веб-приложениями ботов](/api/bots/webapps/), чтобы восстановить ключ из защищённого хранилища на устройстве пользователя, привязанного к текущему авторизованному пользователю и данному Mini App.

При успехе порождает [событие secure\_storage\_key\_restored »](/api/bots/webapps/#secure-storage-key-restored), при неудаче — [событие secure\_storage\_failed »](/api/bots/webapps/#secure-storage-failed).

#### `web_app_hide_keyboard`

Полезная нагрузка события: `null`

Скрывает экранную клавиатуру, если она в данный момент видима. Если клавиатура не активна, не делает ничего.

#### `web_app_verify_age`

Полезная нагрузка события: JSON-объект со следующими ключами:

-   `passed` — булево значение, показывает, прошёл ли пользователь проверку возраста
-   `age` — необязательное целое число, определённый возраст, если пользователь прошёл проверку возраста
-   `gender` — необязательное булево значение, показывает определённый пол, если пользователь прошёл проверку возраста
-   `genderProbability` — необязательное число с плавающей точкой, вероятность определённого пола, если пользователь прошёл проверку возраста

Сообщает результат [проверки возраста; подробнее о полном сценарии см. здесь »](/api/age-verification/).

#### `navigationBarColor`

Данные события: JSON-массив `[r, g, b, a]`, где `r`, `g`, `b` — целочисленные компоненты цвета в диапазоне `0-255`, а `a` — необязательная непрозрачность в диапазоне `0-1` (по умолчанию `1`).

Порождается страницей, открытой во [встроенном браузере](/api/web-events/), чтобы задать цвет панели навигации/фона клиента.

#### `actionBarColor`

Данные события: JSON-массив `[r, g, b, a]`, где `r`, `g`, `b` — целочисленные компоненты цвета в диапазоне `0-255`, а `a` — необязательная непрозрачность в диапазоне `0-1` (по умолчанию `1`).

Порождается страницей, открытой во [встроенном браузере](/api/web-events/), чтобы задать цвет панели действий клиента.

#### `allowScroll`

Данные события: JSON-массив `[allow_x, allow_y]` из двух булевых значений (каждое по умолчанию `true`).

Порождается страницей, открытой во [встроенном браузере](/api/web-events/), чтобы задать, разрешает ли жест закрытия свайпом в клиенте горизонтальную (`allow_x`) и вертикальную (`allow_y`) прокрутку страницы.

#### `siteName`

Данные события: строка с понятным человеку названием сайта.

Порождается страницей, открытой во [встроенном браузере](/api/web-events/), чтобы задать название сайта, которое отображается и сохраняется в истории посещений для текущей страницы.

#### `oauth_request`

Полезная нагрузка события: JSON-объект со следующими ключами:

-   `url` — необязательная строка; если задана, обязана содержать [глубокую ссылку oauth »](/api/links/#oauth-links), которую нужно передать в [сценарий входа через OAuth »](/api/url-authorization/#oauth-authorization-for-mini-apps).

[@term:OAuth] Используется, чтобы запустить [сценарий входа через OAuth »](/api/url-authorization/#oauth-authorization-for-mini-apps) (протокол делегированной авторизации на стороннем сервисе) — если поле `url` задано, **или** чтобы проверить, поддерживает ли текущий клиент вход через OAuth — если поле `url` **не** задано.

Независимо от содержимого события клиент должен немедленно ответить [событием `oauth_supported` »](/api/bots/webapps/#oauth-supported) со значением `version`, равным `1`.

#### `web_app_request_chat`

Полезная нагрузка события: JSON-объект со следующими ключами:

-   `req_id` — строка, значение [bots.requestedButton](/constructor/bots.requestedButton/).`webapp_req_id`, полученное ботом из [bots.requestWebViewButton](/method/bots.requestWebViewButton/)

Используется [приложениями Mini App](/api/bots/webapps/), чтобы попросить клиент выполнить [запрос пира](/api/bots/buttons/#requesting-peers-via-mini-apps), подготовленный ботом.

Клиенты обязаны вызвать [bots.getRequestedWebViewButton](/method/bots.getRequestedWebViewButton/), передав бота данного Mini App и значение `req_id` в качестве [bots.getRequestedWebViewButton](/method/bots.getRequestedWebViewButton/).`webapp_req_id`.

Метод [bots.getRequestedWebViewButton](/method/bots.getRequestedWebViewButton/) вернёт [keyboardButtonRequestPeer](/constructor/keyboardButtonRequestPeer/), который клиенты обязаны обработать так, как описано в разделе [запрос пиров через Mini Apps](/api/bots/buttons/#requesting-peers-via-mini-apps).

При успехе порождает [событие `requested_chat_sent`](/api/bots/webapps/#requested-chat-sent).  
При неудаче или отмене порождает [событие `requested_chat_failed`](/api/bots/webapps/#requested-chat-failed).
