# Обработка PUSH-уведомлений

### Настройка приложения

Чтобы приложение могло отправлять APNS-уведомления на серверы Apple или GCM-уведомления на серверы Google, в [настройках приложения](https://core.telegram.org/myapp) необходимо указать сертификаты приложения (APNS) либо ключ приложения (GCM).

### Подписка на уведомления

[@term:token_type] Чтобы подписаться на уведомления, клиент должен вызвать метод [account.registerDevice](/method/account.registerDevice/), передав в качестве параметров **token\_type** (`token_type` — числовой код службы push-уведомлений) и **token** (выданный ею идентификатор), которые идентифицируют текущее устройство. Этот запрос полезно повторять не реже одного раза в 24 часа, а также при каждом перезапуске приложения. Для отписки используется [account.unregisterDevice](/method/account.unregisterDevice/).

Поддерживаются следующие значения **token\_type**:

-   `1` — APNS (токен устройства для apple push)
-   `2` — FCM (токен firebase для google firebase)
-   `3` — MPNS (URI канала для microsoft push)
-   `4` — Simple push (адрес (endpoint) для устаревшего simple push API от firefox): обратите внимание, что этот тип push-уведомлений может использоваться и открытой спецификацией push-уведомлений вроде [UnifiedPush »](https://unifiedpush.org/).  
    Simple push работает так: каждый раз, когда приходит значимое сообщение, на указанный HTTPS-адрес отправляется простой запрос PUT с полезной нагрузкой `version=number`; получив такое уведомление, клиент должен подключиться к MTProto API и забрать [обновления](/api/updates/).  
    (Учтите, что в реализации Telegram значение `number` не обязательно возрастает последовательно — просто считайте каждый отдельный запрос сигналом о том, что появилось новое сообщение, которое нужно получить через MTProto.)
-   `5` — Ubuntu phone (токен для ubuntu push)
-   `6` — Blackberry (токен для blackberry push)
-   `7` — отдельная сессия MTProto
-   `8` — WNS (windows push)
-   `9` — APNS VoIP (токен для apple push VoIP)
-   `10` — Web push (веб-push, см. ниже)
-   `11` — MPNS VoIP (токен для microsoft push VoIP)
-   `12` — Tizen (токен для tizen push)
-   `13` — Huawei push

Для веб-push (`10`) токен должен быть объектом в формате JSON со следующими ключами:

-   `endpoint`: абсолютный URL, предоставляемый службой push-уведомлений, по которому сервер приложения может отправлять push-сообщения
-   `keys`: параметры протокола Диффи — Хеллмана на эллиптической кривой P-256 в виде следующего объекта
    -   `p256dh`: открытый ключ Диффи — Хеллмана на эллиптической кривой P-256 в кодировке base64url
    -   `auth`: секрет аутентификации в кодировке base64url

### Шифрование уведомлений

[@term:auth_key] Для FCM и APNS VoIP в метод [account.registerDevice](/method/account.registerDevice/) можно передать необязательный ключ шифрования (`secret`), которым будут зашифрованы push-уведомления. Этот ключ (`auth_key` — авторизационный ключ, общий секрет, на котором строится шифрование) используется для шифрования полезной нагрузки по правилам [MTProto v2](/mtproto/description/).

Полезная нагрузка FCM представляет собой JSON, содержащий поле `p` с зашифрованной [полезной нагрузкой MTProto](/mtproto/description/) в кодировке base64url. После расшифровки получится объект JSON, перед которым идёт 32-битное целое число с порядком байтов little-endian, равное длине этой полезной нагрузки JSON. Как обычно, обязательно выполняйте все проверки безопасности, описанные в [документации по MTProto](/mtproto/description/#important-checks).

[Пример реализации](https://github.com/DrKLO/Telegram/blob/b1aa2020e5533ea18dc77aab6c6b8236e5dc2b6c/TMessagesProj/src/main/java/org/telegram/messenger/GcmPushListenerService.java#L30).

Как упоминалось [выше](#subscribing-to-notifications), полезную нагрузку можно также шифровать с помощью [протокола Диффи — Хеллмана на эллиптической кривой P-256 при использовании веб-push](https://tools.ietf.org/html/rfc8291).

### Структура уведомления

Уведомление (при необходимости [зашифрованное](#notification-encryption)) передаётся как объект JSON следующего вида:

```
{
  "data": {
    "loc_key": "CHAT_MESSAGE_CONTACT",
    "loc_args": ["John Doe", "My magical group", "Contact Exchange"],
    "user_id": 14124122,
    "custom": {
      "chat_id": 241233,
      "msg_id": 123
    },
    "sound": "sound1.mp3",
  }
}
```

Каждое уведомление описывается несколькими параметрами.

-   loc\_key — тип уведомления: строковый литерал вида `/[A-Z_0-9]+/`, кратко описывающий уведомление. Например, `CHAT_MESSAGE_TEXT`.
-   loc\_args — аргументы для подстановки в уведомление: список аргументов, которые при подстановке в шаблон дают читаемый текст уведомления.
-   custom — произвольные параметры, передаваемые в приложение при открытии уведомления. Возможные поля:
    -   attachb64 — для уведомлений о медиафайлах: TL-сериализация соответствующего объекта [Photo](/type/Photo/) / [Document](/type/Document/) в кодировке base64url
    -   updates — TL-сериализация объекта [Updates](/type/Updates/) в кодировке base64url; сейчас отправляется только для PHONE\_CALL\_REQUEST (внутри содержится [updatePhoneCall](/constructor/updatePhoneCall/))
    -   call\_id — идентификатор звонка, используется в PHONE\_CALL\_REQUEST
    -   call\_ah — хеш доступа к звонку, используется в PHONE\_CALL\_REQUEST
    -   encryption\_id — идентификатор секретного чата для ENCRYPTION\_REQUEST, ENCRYPTION\_ACCEPT, ENCRYPTED\_MESSAGE
    -   random\_id — случайный идентификатор сообщения в ENCRYPTED\_MESSAGE
    -   contact\_id — идентификатор пользователя Telegram из контактов, который зарегистрировался в Telegram, для CONTACT\_JOINED
    -   msg\_id — идентификатор сообщения для события нового сообщения или события реакции
    -   channel\_id — идентификатор [канала или супергруппы](/api/channel/), где произошло событие
    -   chat\_id — идентификатор [обычной группы](/api/channel/#basic-groups), где произошло событие
    -   from\_id — идентификатор пользователя, у которого произошло событие
    -   chat\_from\_broadcast\_id — если сообщение в группе было отправлено от имени канала, это поле содержит идентификатор канала-отправителя
    -   chat\_from\_group\_id — если сообщение в группе было отправлено от имени супергруппы, это поле содержит идентификатор супергруппы-отправителя
    -   chat\_from\_id — только для групп: идентификатор автора сообщения (игнорируйте, если присутствует chat\_from\_broadcast\_id или chat\_from\_group\_id)
    -   mention — было ли в этом новом сообщении упоминание текущего пользователя или ответ ему
    -   silent — было ли сообщение отправлено без звука (для такого уведомления звук воспроизводить не следует)
    -   schedule — является ли сообщение исходящим и отправленным через [отложенные сообщения](/api/scheduled-messages/)
    -   report\_delivery\_until\_date — если поле задано и текущее время в формате unixtime больше указанного, вызовите [messages.reportMessagesDelivery](/method/messages.reportMessagesDelivery/), установив флаг `push` и передав идентификатор и пир этого сообщения сразу же, как только клиент его получит (запросы для одного и того же пира допускается объединять в пакеты); применяется для [проверочных сообщений Telegram Gateway](https://telegram.org/blog/star-messages-gateway-2-0-and-more#save-even-more-on-user-verification).
    -   edit\_date — когда сообщение редактировалось в последний раз
    -   top\_msg\_id — thread\_id для новых упоминаний и ответов в [обсуждениях](/api/threads/)
    -   data\_url — полный URL веб-страницы, которая пытается выполнить вход через OAUTH\_REQUEST
    -   announcement — идентификатор объявления, используется в MESSAGE\_ANNOUNCEMENT
-   sound — имя звукового файла, который следует воспроизвести.
-   user\_id — идентификатор аккаунта, которому нужно доставить PUSH-уведомление; актуально для клиентов, где одновременно активны несколько аккаунтов.
-   message — необязательный текст уведомления, сейчас используется в MESSAGE\_ANNOUNCEMENT

Машиночитаемый список всех типов уведомлений вместе с их шаблонами и аргументами для подстановки также встроен в индекс [/api/config.json](/api/config.json/) — под ключами `push` (шаблоны уведомлений по типам) и `push_arguments` (списки аргументов для подстановки по типам).

### Обработка уведомлений

В принципе, для формирования уведомления достаточно **data.loc\_key**, **data.custom** и подключения к интернету. Разумеется, при формировании визуального уведомления по возможности не нужно использовать все переданные данные — можно опираться на сведения, которые уже хранятся у клиента. Но если пользователь или чат локально не закешированы, допускается использовать и значения, переданные в loc\_args. **data.user\_id** — это идентификатор аккаунта, которому нужно доставить PUSH-уведомление; актуально для клиентов, где одновременно активны несколько аккаунтов.

### Служебные уведомления

Перечисленные ниже уведомления клиенты обрабатывают особым образом: они обновляют локальное состояние приложения или порождают лёгкие локальные события вместо того, чтобы показывать обычное уведомление о сообщении.

#### DC\_UPDATE

**Дополнительные аргументы custom**

**data.custom.dc** — номер дата-центра  
**data.custom.addr** — адрес сервера вместе с номером порта в формате `111.112.113.114:443`

**Описание**

Добавьте полученный адрес сервера в список возможных адресов указанного DC.

Если передан адрес первого DC (`dc=1`), рекомендуется сразу же вызвать [help.getConfig](/method/help.getConfig/), чтобы обновить конфигурацию дата-центров.

**Пример шаблона**

`Откройте это уведомление, чтобы обновить настройки приложения`

**Аргументы**

Это уведомление не использует аргументы для подстановки.

#### MESSAGE\_DELETED

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.chat\_id** — для [чатов](/api/channel/): идентификатор [чата](/api/channel/)  
**data.custom.from\_id** — для личных переписок: идентификатор автора  
**data.custom.messages** — перечисленные через запятую идентификаторы удалённых сообщений

**Описание**

В указанном диалоге были удалены сообщения: удалите локальные уведомления для перечисленных сообщений.

**data.custom.messages** содержит разделённый запятыми список серверных идентификаторов сообщений.

#### READ\_REACTION

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.chat\_id** — для [чатов](/api/channel/): идентификатор [чата](/api/channel/)  
**data.custom.from\_id** — для личных переписок: идентификатор автора  
**data.custom.topic\_id** — необязательный идентификатор темы форума  
**data.custom.messages** — перечисленные через запятую идентификаторы сообщений, реакции на которые были прочитаны

**Описание**

Реакции на указанные сообщения были прочитаны: удалите локальные уведомления о реакциях для этих сообщений.

#### READ\_HISTORY

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.chat\_id** — для [чатов](/api/channel/): идентификатор [чата](/api/channel/)  
**data.custom.from\_id** — для личных переписок: идентификатор автора  
**data.custom.max\_id** — максимальный идентификатор прочитанных сообщений

**Описание**

В указанном несекретном диалоге была прочитана история сообщений: пометьте входящую историю вплоть до **data.custom.max\_id** как прочитанную и удалите соответствующие уведомления.

#### READ\_STORIES

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.from\_id** — для историй, опубликованных пользователем: идентификатор автора  
**data.custom.max\_id** — максимальный идентификатор прочитанной истории

**Описание**

Уведомления об историях указанного пользователя или канала были прочитаны: пометьте истории вплоть до **data.custom.max\_id** как прочитанные и удалите соответствующие уведомления об историях.

#### STORY\_DELETED

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.from\_id** — для историй, опубликованных пользователем: идентификатор автора  
**data.custom.story\_id** — перечисленные через запятую идентификаторы удалённых историй

**Описание**

История была удалена: удалите локальные уведомления для этой истории.

#### STORY\_NOTEXT

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.from\_id** — для историй, опубликованных пользователем: идентификатор автора  
**data.custom.story\_id** — идентификатор истории

**Описание**

Опубликована новая история без текста.

**Пример шаблона**

`опубликовал(а) историю`

**Аргументы**

Это уведомление не использует аргументы для подстановки.

#### STORY\_LIVE

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.from\_id** — для историй, опубликованных пользователем: идентификатор автора  
**data.custom.story\_id** — идентификатор истории

**Описание**

Начата прямая трансляция в истории.

**Пример шаблона**

`начал(а) прямую трансляцию!`

**Аргументы**

Это уведомление не использует аргументы для подстановки.

#### STORY\_HIDDEN\_AUTHOR

**Дополнительные аргументы custom**

**data.custom.channel\_id** — для [каналов и супергрупп](/api/channel/): идентификатор [канала или супергруппы](/api/channel/)  
**data.custom.from\_id** — для историй, опубликованных пользователем: идентификатор автора  
**data.custom.story\_id** — идентификатор истории

**Описание**

Опубликована новая история, но клиент не должен раскрывать автора в видимом тексте уведомления.

**Пример шаблона**

`Опубликована новая история`

**Аргументы**

Это уведомление не использует аргументы для подстановки.

#### GEO\_LIVE\_PENDING

**Описание**

Обновите все трансляции геопозиции, за которыми вы сейчас следите или которые сами передаёте.

Этот push — лишь сигнал к пробуждению, ему не нужны ни аргументы для подстановки, ни видимое пользователю уведомление.

#### SESSION\_REVOKE

**Описание**

Выполните выход и удалите базу данных для сессии, указанной в **data.user\_id**; применяйте это только в том случае, если уведомление пришло [в зашифрованном MTProto-виде](#notification-encryption)

#### MESSAGE\_MUTED

**Описание**

Присылается редко для чатов с отключёнными уведомлениями — примерно на каждое десятое сообщение в таком чате или примерно раз в 15 секунд в личных переписках, чтобы обновить состояние счётчика непрочитанного либо инициировать получение обновлений с сервера.

Этот push не предназначен для показа пользователю в виде видимого уведомления.

#### MESSAGE\_ANNOUNCEMENT

**Дополнительные аргументы custom**

**data.custom.announcement** — идентификатор объявления (целое число)

**Дополнительные аргументы верхнего уровня**

**data.message** — непустой текст объявления

**Описание**

Примерно соответствует сообщению, полученному от служебных уведомлений ([updateServiceNotification](/constructor/updateServiceNotification/) со значением `type="announcement"`), но доставляется через push-уведомления, без обращения к API.

Текст push-уведомления берётся из **data.message**.

Клиенты могут отсеивать повторяющиеся объявления по идентификатору объявления из **data.custom.announcement**: например, сохраняя полученные идентификаторы в течение 7 дней и не теряя этот кеш при перезапусках.

### Возможные уведомления

#### AUTH\_REGION

**Пример шаблона**

`Новый вход с неопознанного устройства {1}, местоположение: {2}`

**Аргументы**

1.  Название устройства
2.  Местоположение

#### AUTH\_UNKNOWN

**Пример шаблона**

`Новый вход с неопознанного устройства {1}`

**Аргументы**

1.  Название устройства

#### CHANNEL\_MESSAGES

**Пример шаблона**

`{1} опубликовал(а) альбом`

**Аргументы**

1.  Автор сообщения

#### CHANNEL\_MESSAGE\_AUDIO

**Пример шаблона**

`{1} опубликовал(а) голосовое сообщение`

**Аргументы**

1.  Автор сообщения

#### CHANNEL\_MESSAGE\_CONTACT

**Пример шаблона**

`{1} опубликовал(а) контакт {2}`

**Аргументы**

1.  Автор сообщения
2.  Имя контакта

#### CHANNEL\_MESSAGE\_DOC

**Пример шаблона**

`{1} опубликовал(а) файл`

**Аргументы**

1.  Автор сообщения

#### CHANNEL\_MESSAGE\_DOCS

**Пример шаблона**

`{1} опубликовал(а) файлов: {2}`

**Аргументы**

1.  Название канала
2.  Количество опубликованных документов

#### CHANNEL\_MESSAGE\_FWDS

**Пример шаблона**

#### CHANNEL\_MESSAGE\_GAME
