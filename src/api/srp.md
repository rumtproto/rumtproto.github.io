# SRP: проверка облачного пароля (2FA)

Оригинальное русскоязычное описание обмена, которым клиент доказывает знание облачного пароля, не передавая его серверу. Первоисточник: [core.telegram.org/api/srp](https://core.telegram.org/api/srp).

Если у аккаунта включена двухфакторная защита, после ввода кода из СМС сервер требует подтвердить знание облачного пароля. Обмен построен на варианте протокола SRP (Secure Remote Password — парольно-аутентифицированный обмен ключами): пароль участвует только в вычислениях на клиенте.

## Параметры

Клиент запрашивает [`account.getPassword`](/method/account.getPassword/) и получает [`account.password`](/constructor/account.password/):

- `current_algo` — алгоритм и параметры ([`passwordKdfAlgoSHA256SHA256PBKDF2HMACSHA512iter100000SHA256ModPow`](/constructor/passwordKdfAlgoSHA256SHA256PBKDF2HMACSHA512iter100000SHA256ModPow/)): соль `salt1`, `salt2`, генератор `g` и простой модуль `p`;
- `srp_B` — публичное значение сервера;
- `srp_id` — идентификатор раунда.

## Вычисления клиента (кратко)

1. `x` выводится из пароля: хешевая цепочка `SHA256` с солями и `PBKDF2-HMAC-SHA512` (100 000 итераций) — по формулам из конструктора алгоритма.
2. Клиент выбирает случайное `a`, считает `A = g^a mod p` и отправляет `A` вместе с `srp_id`.
3. Из `A`, `srp_B`, `x` и случайности обеих сторон выводится общий ключ `K` (через `SHA256`-микширование); клиент строит доказательство `M1`.
4. Сервер проверяет `M1` и в ответ присылает своё доказательство `M2`; клиент проверяет и его — после этого вход считается успешным.

Итог: [`auth.checkPassword`](/method/auth.checkPassword/) с [`inputCheckPasswordSRP`](/constructor/inputCheckPasswordSRP/) (`srp_id`, `A`, `M1`).

## Требования безопасности

- Пароль никогда не покидает устройство в каком-либо виде, кроме участия в хешевых вычислениях.
- `p` обязан быть безопасным простым (проверка, как для `dh_prime` — см. [рекомендации по безопасности](/mtproto/security_guidelines/)).
- Все случайные значения — криптографически стойкие.
- Ошибки вида `PASSWORD_HASH_INVALID` означают неверный пароль; `SRP_ID_CHANGED` — раунд устарел, нужно заново запросить параметры.
