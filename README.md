# MTProto — документация Telegram на русском

Репозиторий сайта **[rumtproto.github.io](https://rumtproto.github.io)** — полного русского
перевода документации Telegram, собираемого как статический сайт на
[Eleventy](https://www.11ty.dev/).

Сайт постранично повторяет оригинал на [core.telegram.org](https://core.telegram.org)
и его английское зеркало [mirrortproto.github.io](https://mirrortproto.github.io):

| | |
|---|---|
| Страниц всего | **3191** |
| Статей (Telegram API, MTProto, схема, FAQ) | **163** |
| Страниц справочника схемы TL | **3022** (1615 конструкторов, 787 методов, 620 типов) |
| Переведённых абзацев со ссылкой на оригинал | **17 079** |
| Проверенных ссылок на якоря | **44 684** |

## Принципы перевода

**Абзац в абзац.** Каждая страница — точный структурный слепок оригинала: столько же
абзацев, заголовков, пунктов списков и строк таблиц, в том же порядке. Нумерация абзацев
общая с английским зеркалом: абзац №7 здесь — абзац №7 там, поэтому
`rumtproto.github.io/api/config/#p-7` и `mirrortproto.github.io/api/config/#p-7` —
один и тот же фрагмент текста.

**Якоря оригинала сохранены.** Заголовки получают те же `id`, что и на core.telegram.org,
поэтому все перекрёстные ссылки документации работают, а ссылки вида
`/api/config/#restriction-add-platforms` ведут туда же, куда и в оригинале. Дополнительно
каждая ссылка доступна по русскому слагу заголовка.

**Код неприкосновенен.** Определения схемы TL, JSON-дампы, примеры кода и вывода
скопированы буква в букву. Не переводятся имена конструкторов, методов, типов, полей и
флагов, коды ошибок и любой текст в `обратных кавычках`.

Полный свод правил, которым следует перевод, — [`tools/STYLEGUIDE.md`](tools/STYLEGUIDE.md).

## Метки абзацев

Рядом с каждым абзацем стоит маленькая иконка-метка; при наведении появляется подсказка.
Меток три, и на одном абзаце их может быть несколько.

| Метка | Что означает | Как задаётся |
|---|---|---|
| **перевод** | ссылка на этот же абзац английского оригинала на `mirrortproto.github.io` | проставляется автоматически при сборке |
| **термин** | здесь впервые на странице вводится непереводимый термин; подсказка содержит его объяснение | маркер `[@term:термин]` в начале абзаца |
| **пояснение** | абзац добавлен переводчиком: его нет в оригинале | маркер `[@note]` в начале абзаца |

Нумерация абзацев вычисляется при сборке, поэтому она не может разойтись с текстом:
абзацы с `[@note]` получают отдельные идентификаторы `n-1`, `n-2`, … и не сдвигают нумерацию
переведённых абзацев. Явный маркер `[@t:N]` остаётся доступным как переопределение для
редких страниц, где соответствие не один к одному.

Объяснения терминов в подсказках берутся из [`src/_data/terms.json`](src/_data/terms.json) —
общего словаря проекта; правка в нём отражается на всех страницах сразу.

Пример:

```markdown
[@term:auth_key] Клиент и сервер вырабатывают общий `auth_key` (авторизационный ключ —
долговременный секрет длиной 2048 бит, которым шифруются все сообщения).

[@note] Порядок вычисления ключа сообщения важен для реализации: SHA256 берётся от
конкатенации 32 байт авторизационного ключа и тела сообщения — именно в таком порядке.
```

## Требования

- Node.js ≥ 18 (проверено на 24)
- npm

## Сборка

```bash
npm install      # зависимости: eleventy, markdown-it-anchor, pagefind, turndown
npm run build    # собирает сайт в docs/ и строит поисковый индекс
npm run check    # проверки готового сайта (см. ниже)
```

Готовый сайт лежит в `docs/`. Локальный просмотр:

```bash
npx serve docs
```

### Режим разработки

```bash
npm run serve    # eleventy --serve → http://localhost:8080/
```

Поиск в этом режиме работает после хотя бы одной полной сборки (`npm run build`): индекс
лежит в `docs/pagefind/` и подхватывается дев-сервером.

## Проверки

`npm run check` (файл `tools/verify.mjs`) проверяет собранный сайт:

- все внутренние ссылки разрешаются;
- ровно один `<h1>` на странице, есть `skip-link`, `canonical` и `lang="ru"`;
- **все ссылки на якоря заголовков разрешаются** — включая якоря, унаследованные от оригинала;
- **у каждого переведённого абзаца есть метка со ссылкой на оригинал**;
- `sitemap.xml` и `robots.txt` на месте;
- поисковый индекс покрывает все страницы.

`npm run audit` дополнительно сверяет содержимое с оригиналом:

- `tools/audit.mjs` — по каждой статье: число абзацев против оригинала, число заголовков,
  доля русского текста, повторные метки терминов;
- `tools/checkrefs.mjs` — по каждой из 3022 страниц справочника: число абзацев,
  неизменность TL-определений, совпадение последовательности HTML-тегов и адресов ссылок.

Отдельные проверки для работы над текстом:

```bash
node tools/checkpage.mjs api/config     # одна статья против оригинала
node tools/checkchunk.mjs <slug> <file> # один фрагмент перевода
node tools/checktm.mjs 042              # одна пачка строк справочника
node tools/verify_mirror.mjs            # сверка нумерации абзацев с живым зеркалом
```

## Публикация (GitHub Pages)

1. Соберите сайт: `npm run build`.
2. Закоммитьте `docs/` вместе с исходниками и отправьте в ветку `main`.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/docs`.

## Конвейер (нужен только при обновлении снимка)

Сеть используется единственным шагом — `tools/crawl.mjs`. Всё остальное работает
из `backup/<дата>/`.

1. `tools/crawl.mjs` — снимает бэкап с core.telegram.org.
2. `tools/gen_en.mjs` — восстанавливает английские исходники в `.extracted/en/` и считает
   для каждой страницы число абзацев и якоря заголовков (эталон для проверок).
3. `tools/chunk_pages.mjs` — режет статьи на фрагменты для перевода
   (`.extracted/chunks/`); переводы кладутся в `.extracted/chunks_ru/`.
4. `tools/assemble.mjs` — собирает страницы из фрагментов в `src/` и проверяет
   совпадение числа абзацев.
5. `tools/refstrings.mjs` + `tools/tmbatches.mjs` — извлекают из справочника схемы
   10 524 уникальные строки и делят их на пачки для перевода.
6. `tools/genrefs.mjs` + `tools/genrefindexes.mjs` — собирают 3022 страницы справочника
   из английских исходников и памяти переводов и строят алфавитные указатели.
7. `tools/genanchors.mjs` + `tools/gennav.mjs` — якоря заголовков, меню и хлебные крошки.
8. `tools/fixfences.mjs` — восстанавливает блоки кода, если их случайно переформатировали.

После первой сборки **источником правды для текста является `src/`**: шаги 3–4 нужны
только когда страница переводится заново с нуля.

## Права

Оригинальные тексты, схема и иллюстрации принадлежат Telegram. Права на использование
контента получены от Telegram. Определения схемы и идентификаторы сохранены без изменений;
за каноническими формулировками обращайтесь к первоисточнику по ссылке, которая есть
на каждой странице.

или присылайте pull request.
