# MTProto по-русски

Русская версия [MTProto Mirror](https://mirrortproto.github.io) — документации
Telegram API, MTProto и схемы TL. Сайт **не поддерживает отдельную копию
переведённых Markdown-страниц**: на каждой сборке он берёт закреплённый снимок
английского зеркала и подставляет только точные переводы из отдельной памяти
переводов.

Это устраняет главный класс ошибок перевода документации: если Telegram или
зеркало добавило либо изменило текст, у него ещё нет ключа в памяти — поэтому
он остаётся видимым по-английски. Пустого абзаца, случайно устаревшего перевода
или ручного расхождения структуры страницы быть не может.

## Гарантии сборки

- **Источник структуры — `mirror/`.** Вендорированный, закреплённый commit
  [mirrortproto.github.io](https://github.com/mirrortproto/mirrortproto.github.io)
  задаёт список страниц, ссылки, Markdown-разметку, код, таблицы, медиа и
  английские якоря.
- **Источник перевода — `i18n/`.** Основная память
  [`i18n/segments.json`](i18n/segments.json) имеет буквальный формат
  `"English source text": "Русский перевод"`. Одинаковая английская строка
  переводится один раз и используется всюду.
- **Контекст без дублирования.** Редкие контекстные варианты хранятся в
  `i18n/pages/<страница>.json`; метаданные (`title`, `description`), термины,
  пояснения, меню и хлебные крошки — в отдельных файлах `i18n/`.
- **Безопасный fallback.** Ненайденный или изменённый ключ не заменяется ничем:
  он остаётся точным английским текстом из зеркала. Метка перевода появляется
  только у действительно переведённого фрагмента.
- **Структура неизменна.** Проверка сравнивает последовательность блоков на всех
  3470 страницах зеркала, включая главную, поиск, 404 и указатели схемы. Перевод
  не может изменить список, таблицу, блок кода или порядок абзацев. Собственных
  страниц у сайта нет: всё, что добавляет переводчик, оформляется пояснением с
  отдельной меткой.
- **Имена схемы неприкосновенны.** Ключ, совпадающий с именем конструктора,
  метода или типа, отвергается и при сборе памяти, и при подстановке: перевод
  такого сегмента переименовал бы сущность API по всему сайту.
- **Дефекты зеркала воспроизводятся честно.** Если ссылка не разрешается уже в
  оригинале, проверка сообщает предупреждением и не считает это ошибкой: цель
  ссылки не меняется в одностороннем порядке.
- **Оригинальные deep links сохранены.** Английские `id` заголовков,
  исторические alias-якоря и `p-N` совпадают с зеркалом. Пояснения переводчика
  получают `n-N` и никогда не сдвигают `p-N`.
- **Функции зеркала перенесены.** Собираются Pagefind-поиск, canonical/OG/
  hreflang метаданные, JSON-LD breadcrumbs, тема, media placeholders и
  Telegram Instant View. У изображений и видео нет inline-обработчиков,
  которые Instant View удаляет.
- **Стили и скрипты переиспользуются, а не копируются.** `style.css` и
  инлайновые скрипты зеркала берутся без изменений, поэтому исправления вёрстки
  и поведения приходят автоматически. Отличия русской версии вынесены в
  отдельные подключаемые `css/translation.css` и `js/translation.js`.
- **Шаблоны выводятся из шаблонов зеркала.** `layout.njk`, `sitemap.njk` и
  `robots.njk` получаются контролируемыми заменами строк. Если upstream изменит
  разметку, сборка упадёт с понятной ошибкой, а не тихо испортит страницу.

Интерфейс полностью русский. Меню сохраняет исходный состав, порядок и адреса
пунктов зеркала, но подписи в нём русские. Английский текст остаётся только там,
где для исходного фрагмента документации ещё нет перевода, а также в именах
конструкторов, методов, типов и других идентификаторах схемы.

## Быстрый старт

Требуются Node.js 18+ и npm.

```bash
npm install
npm run build     # mirror + i18n -> build/ -> docs/ + Pagefind
npm run check     # полный набор инвариантов
```

Публикуемая статическая папка — [`docs/`](docs/). Локальный просмотр:

```bash
npx serve docs
```

## Обновление зеркала с минимальным объёмом перевода

Обычное обновление — не миграция и не повторный перевод сайта.

```bash
npm run sync:mirror       # получает и закрепляет новый snapshot mirror/
# посмотреть i18n/update-report.json
npm run build
npm run check
```

Или одной командой:

```bash
npm run update
```

Если зеркало изменило только формат ссылок, а текст остался прежним, перенести
готовые переводы на новые ключи можно командой `npm run remap`: она переносит
пару только при полном совпадении текста без учёта адресов ссылок.

`sync:mirror` сравнивает старый и новый снимки по исходным сегментам и пишет
[`i18n/update-report.json`](i18n/update-report.json):

- `pages.added`, `pages.changed`, `pages.removed` — изменившийся inventory;
- `keys.needsTranslation` — **единственный** список новых исходных строк,
  которым требуется перевод;
- `keys.alreadyTranslated` — новые употребления уже знакомых строк;
- `keys.retiredWithTranslation` — ключи, которые больше не встречаются и могут
  быть рассмотрены для очистки, но автоматически не удаляются.

Чтобы добавить перевод, внесите одну строку в `i18n/segments.json`:

```json
{
  "The exact new English sentence.": "Точный русский перевод нового английского предложения."
}
```

Если это тот же английский текст, но в данном месте нужен иной перевод,
добавьте его только для этой страницы в
`i18n/pages/api__example.json`. Не изменяйте `mirror/` и не редактируйте
`build/` или `docs/` вручную: `build/` всегда пересоздаётся, а `docs/` —
результат сборки.

## Пояснения и термины

`i18n/annotations.json` привязывает к **исходному английскому ключу**:

- `terms` — термины, у которых показывается метка и tooltip со словарным
  определением из `i18n/terms.json`;
- `notes` — пояснения переводчика. После обычного абзаца они становятся
  отдельным `n-N`; внутри сложного списка остаются в том же элементе, чтобы не
  менять дерево Markdown.

В готовом HTML служебные маркеры отсутствуют. У перевода есть компактная
ссылка ↔ на соответствующий `#p-N` английского зеркала; термин и пояснение
имеют отдельные доступные метки.

## Структура репозитория

```text
mirror/                 # закреплённые исходники mirrortproto (источник структуры)
i18n/                   # единственный источник русских текстов и метаданных
  segments.json         # exact English source -> Russian translation
  pages/                # только контекстные переопределения
  annotations.json      # термины и пояснения
  nav.json              # русские подписи пунктов меню
  crumbs.json           # русские подписи хлебных крошек
  never-translate.json  # сегменты без перевода по определению (см. ниже)
  coverage.json         # ключи, реально ожидающие перевода
  retired.json          # старые ключи, сохранённые для review, но не применяемые
  update-report.json    # работа после следующей синхронизации
site/                   # только дополнительные ассеты поверх зеркала
  css/translation.css   # только метки перевода, подключается после style.css
  js/translation.js     # только русские отличия поведения, отдельным файлом

build/                  # генерируемый вход Eleventy (игнорируется Git)
docs/                   # готовый статический сайт для GitHub Pages
tools/                  # sync, apply, генераторы и строгий verifier
```

Каждый инструмент в `tools/` участвует в сборке, обновлении или проверке;
одноразовые миграционные скрипты удалены после завершения перехода.

## Что не переводится по определению

`i18n/never-translate.json` — материализованный список сегментов, у которых
перевода нет и быть не может: имена конструкторов, методов и типов, ссылки на
страницы схемы, типовые выражения TL, формулы и аббревиатуры протоколов.

Он пересобирается из зеркала на каждой сборке и **исключён из статистики
покрытия**: эти сегменты не являются незавершённой работой. Правила намеренно
узкие — обычный текст, который лишь упоминает идентификатор или содержит
формулу, остаётся в статистике. Секция `manual` предназначена для ручных
добавлений и сохраняется между запусками.

## Что проверяет `npm run check`

- каждая страница зеркала присутствует в `build/` и `docs/`;
- блоковая структура всех обычных страниц совпадает с `mirror/`;
- в памяти переводов нет пустых ключей или значений;
- ровно один `<h1>`, русский `lang`, skip-link, canonical, OG, hreflang и
  Instant View metadata есть на каждой странице;
- нет утёкших служебных маркеров и inline media handlers;
- все метки перевода ведут на корректный `mirrortproto.github.io/#p-N`;
- все исходные якоря заголовков, внутренние ссылки и фрагменты разрешаются;
- Pagefind покрывает весь сайт;
- меню сохраняет пункты и порядок зеркала и имеет русские подписи;
- хлебные крошки совпадают со структурой зеркала на каждой странице;
- интерфейс русский, без английских строк в шапке и навигации;
- `sitemap.xml`, `robots.txt`, `canonical` и `og:url` указывают на наш домен;
- `style.css` зеркала переиспользуется, а `translation.css` и `translation.js`
  подключены на каждой странице.

## Права

Оригинальные тексты, схема и иллюстрации принадлежат Telegram. Права на
использование контента получены от Telegram. Имена конструкторов, методов,
типов, полей, флагов, TL-определения и код сохраняются без изменений, потому
что это необходимо для технической совместимости.
