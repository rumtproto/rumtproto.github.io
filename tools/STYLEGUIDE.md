# Руководство переводчика rumtproto.github.io

Единые правила для всех страниц сайта. Любой перевод, который им не следует,
считается дефектным и переписывается.

## 1. Главный принцип: абзац в абзац

Русская страница — **точный структурный слепок** английского оригинала.

- Каждому абзацу оригинала соответствует **ровно один** абзац перевода.
- **Нельзя** объединять два абзаца в один или разбивать один на два.
- **Нельзя** пропускать абзацы, списки, пункты списка, строки таблиц, заголовки,
  цитаты, картинки и блоки кода.
- **Нельзя** добавлять свои абзацы без метки `[@note]` (см. §4).
- Порядок блоков сохраняется полностью.

Нумерация абзацев проставляется автоматически при сборке и совпадает с нумерацией
английского зеркала: абзац №7 здесь — абзац №7 там. Поэтому любое расхождение в
числе абзацев ломает все ссылки на оригинал.

## 2. Что переводится, а что — нет

**Переводится:** заголовки, текст абзацев, текст пунктов списков, текст ячеек
таблиц, подписи к картинкам, текст ссылок, текст цитат, значения `alt`/`title`.

**Не переводится и сохраняется буква в букву:**

- содержимое блоков кода ``` ``` ``` ``` (TL-схема, JSON, примеры кода, консольный вывод);
- имена конструкторов, методов, типов и полей схемы: `messages.sendMessage`,
  `inputPeerSelf`, `flags.2?true`, `access_hash`, `msg_id`;
- любые идентификаторы в `обратных кавычках` — они всегда остаются как есть;
- коды ошибок: `FLOOD_WAIT_X`, `PHONE_CODE_INVALID`, `AUTH_KEY_UNREGISTERED`;
- URL, значения атрибутов HTML, якоря (`#section-name`), пути ссылок;
- названия продуктов и торговые марки: Telegram, Telegram Premium, Telegram Stars,
  Telegram Business, Telegram Passport, Mini App, Bot API, TDLib, Fragment, TON.

Ссылки переводятся только по тексту, адрес остаётся неизменным:
`[Working with Updates](/api/updates/)` → `[Работа с обновлениями](/api/updates/)`.

## 3. Термины: метка `[@term:…]`

Многие понятия протокола не имеют устоявшегося русского эквивалента и
сохраняются в оригинальном написании. **При первом появлении такого термина на
странице** абзац получает метку `[@term:термин]`, а сам термин поясняется прямо
в тексте — коротко, в скобках или через тире.

```markdown
[@term:auth_key] Клиент и сервер вырабатывают общий `auth_key` (авторизационный
ключ — долговременный секрет длиной 2048 бит, которым шифруются все сообщения).
```

Правила:

- метка ставится **один раз на страницу** для каждого термина — на том абзаце,
  где термин встречается впервые;
- на одном абзаце может быть несколько меток `[@term:…]`, если он вводит
  несколько терминов сразу;
- метка ставится **в начале абзаца**, до текста;
- значение метки — сам термин в оригинальном написании (`[@term:access_hash]`,
  `[@term:Mini App]`, `[@term:long polling]`);
- термин, который уже понятен из русского текста (`сообщение`, `чат`), меткой
  не помечается.

Типичные кандидаты: `auth_key`, `server_salt`, `session`, `msg_id`, `seq_no`,
`access_hash`, `file_reference`, `pts`, `qts`, `layer`, `peer`, `flags`,
`long polling`, `deep link`, `Mini App`, `inline query`, `takeout`, `Perfect
Forward Secrecy`, `rate limit`, `slow mode`.

## 4. Пояснения переводчика: метка `[@note]`

Абзац, которого нет в оригинале, обязан начинаться с `[@note]`. Такие абзацы не
участвуют в нумерации и не сдвигают ссылки на оригинал.

```markdown
[@note] Здесь `pts` — счётчик состояния диалога; он растёт монотонно, и клиент
использует его, чтобы понять, не пропустил ли он обновления.
```

Когда уместно:

- разъяснить неочевидное место оригинала, если без этого текст непонятен;
- расшифровать аббревиатуру или указать общепринятый русский эквивалент;
- предупредить о неоднозначности или устаревшей формулировке оригинала.

Когда **не** уместно: пересказ соседнего абзаца, общие слова, «вода», реклама,
собственные суждения о качестве Telegram. Пояснений должно быть немного —
ориентир: не больше одного на 8–10 абзацев, и только там, где они реально нужны.

## 5. Язык и стиль

- Нейтральный технический русский, безличные конструкции: «клиент отправляет»,
  «сервер возвращает», «следует проверить». Обращение на «вы» — со строчной.
- Не калькировать английский синтаксис. Длинные английские предложения можно
  перестроить, но **в границах одного абзаца**.
- Термины схемы склоняются только через русское слово-носитель: «поле
  `access_hash`», «в конструкторе `inputPeerUser`», а не «`access_hash`-а».
- Кавычки — «ёлочки», вложенные — „лапки“. Тире — длинное (—) с пробелами.
- Диапазоны — короткое тире без пробелов: `1–10`.
- Буква «ё» пишется.
- Единицы: «байт», «бит», «секунда»; числа с неразрывным пробелом перед единицей.
- `»` в конце текста ссылки оригинала сохраняется: `подробнее »`.

## 7. Оформление markdown

- Заголовки — `#`, `##`, `###` ровно того же уровня, что в оригинале.
- Списки — тем же маркером и той же вложенности; нумерованные остаются нумерованными.
- Таблицы: если в оригинале таблица записана HTML-тегами `<table>…</table>`,
  она остаётся HTML — переводится только текст внутри ячеек, атрибуты не трогаются.
- Блоки кода — тремя обратными кавычками, содержимое не меняется.
- Сырой HTML (`<img>`, `<video>`, `<div class="…">`) сохраняется как есть;
  переводятся только `alt` и `title`.
- Пустая строка между блоками обязательна.
- Метки `[@t:N]` вручную **не** ставятся: нумерация вычисляется при сборке.

## 8. Самопроверка перед сдачей

1. Число абзацев совпадает с оригиналом (метки `[@note]` не в счёт).
2. Число заголовков и их уровни совпадают.
3. Число блоков кода совпадает, содержимое не изменено.
4. Нет английских предложений, кроме кода, идентификаторов и названий.
5. Каждый новый непереводимый термин помечен `[@term:…]` при первом появлении.
6. Все ссылки сохранили адреса; переведён только их текст.
