Воспроизводимые сборки для iOS и Android #

На этой странице приведены инструкции по проверке того, что открытый исходный код Telegram в точности совпадает с кодом, используемым для сборки приложений, доступных в App Store, Google Play и напрямую на сайте Telegram.¶

Предупреждение: Telegram поддерживает воспроизводимые сборки начиная с версии 5.13. Учтите, что на данном этапе процесс проверки следует считать экспериментальным. Мы будем обновлять наши приложения и эти инструкции, чтобы сделать процесс максимально простым.¶

  • Telegram для Android
  • Telegram для iOS

Внимательно прочитайте соответствующие примечания и раздел устранения неполадок.¶

Воспроизводимые сборки для Android #

Шаг 1. Установите Docker #

Docker можно получить здесь. После завершения установки войдите в учётную запись Docker: Settings > Resources > Advanced и настройте объём ресурсов, которые Docker может использовать:¶

Производительность Docker

Производительность Docker¶

Чтобы ускорить сборку, рекомендуется выделить максимальный объём, доступный аппаратному обеспечению системы.¶

Шаг 2. Уточните версию, установленную на устройстве Android #

Номер версии/сборки и источник (веб-сайт, Play Store, Huawei Store) указаны внизу страницы настроек. Telegram поддерживает воспроизводимые сборки начиная с версии 5.13.¶

Версия приложения

Версия приложения¶

Тег коммита для получения исходного кода из приведённого выше примера: release-9.3.3_3026.¶

Убедитесь, что используете правильные версию и номер сборки проверяемой версии, а не данные из этого примера 😈.¶

Шаг 3. Получите исходный код #

Откройте Terminal и выполните команды:
git clone https://github.com/DrKLO/Telegram.git $HOME/telegram-android
cd $HOME/telegram-android
git checkout release-{VERSION AND BUILD NUMBER FROM STEP 2}¶

Для нашего примера команда будет такой:
git checkout release-5.13.0_1821¶

Шаг 4. Соберите приложение #

Откройте Terminal и выполните команды:
cd $HOME/telegram-android
docker build -t telegram-build .¶

docker run --rm -v "$PWD":/home/source telegram-build¶

Эти команды создадут 3 разных APK и 2 пакета:¶

/apk/afat/standalone/app.apk — используется для прямых загрузок с telegram.org/android
/apk/afat/elease/app.apk — версия для Play Store
/apk/afat/release/app-huawei.apk — используется исключительно для магазина Huawei¶

bundle/bundleAfat_SDK23Release/TMessagesProj_App-bundleAfat_SDK23-release.aab
bundle/bundleAfatRelease/TMessagesProj_App-bundleAfat-release.aab¶

Эти APK находятся здесь:
$HOME/telegram-android/TMessagesProj/build/outputs/apk/afat/¶

Используйте имя папки из шага 4, чтобы найти папку с APK, соответствующим установленному на устройстве. Например, для версии из Play Store путь к APK будет таким:¶

$HOME/telegram-android/TMessagesProj/build/outputs/apk/afat/release/app.apk
Скопируйте этот APK в корневой каталог исходного кода, выполнив в Terminal команду:
cp $HOME/telegram-android/TMessagesProj/build/outputs/apk/afat/release/app.apk $HOME/telegram-android/telegram_built.apk¶

Шаг 5. APK Telegram, установленный на устройстве #

Для этого шага понадобится adb.¶

ADB

ADB¶

Если APK был загружен напрямую с сайта Telegram, используйте на этом шаге имя пакета org.telegram.messenger.web. Для проверки APK из Google Play используйте org.telegram.messenger.¶

Подключите устройство к компьютеру, откройте Terminal и выполните команду:
adb shell pm path org.telegram.messenger¶

Вывод будет примерно таким:
package:/data/app/org.telegram.messenger-_zOSURFEx2GpHM8UDF_PVg==/base.apk
Используя эти сведения, скопируйте APK с устройства в $HOME/telegram-android командой:
adb pull /data/app/org.telegram.messenger-_zOSURFEx2GpHM8UDF_PVg==/base.apk $HOME/telegram-android/telegram_store.apk¶

Шаг 6. Сравните APK #

Чтобы сравнить версии Direct и Huawei Store, откройте Terminal и выполните команды:
cd $HOME/telegram-android
python apkdiff.py telegram_store.apk telegram_built.apk
Если APK совпадают, появится сообщение
APKs are the same!¶

Версии Play Store, собранные из пакета, будут помечены как «store bundled». Для проверки таких сборок используйте:¶

python apkfrombundle.py telegram_bundle.aab telegram_store.apk¶

Если что-то пойдёт не так, появится следующее:¶

Если APK не совпадают, убедитесь, что выбрали правильную версию кода и подходящий SDK.¶

Если возникли проблемы, сначала ознакомьтесь с разделом устранения неполадок.¶

Воспроизводимые сборки для iOS #

К сожалению, процесс проверки сборок iOS значительно сложнее, чем для Android. Основные проблемы, связанные с текущими политиками и инфраструктурой Apple, таковы:¶

  1. Apple настаивает на использовании шифрования FairPlay, чтобы «защитить» даже бесплатные приложения с открытым исходным кодом от «пиратов приложений», из-за чего получить исполняемый код приложений невозможно без устройства с jailbreak. Для решения этой проблемы Apple достаточно разрешить отправку в App Store незашифрованных бинарных файлов. Это не повлияет на безопасность, поскольку код всё равно будет подписан, и позволит всем проверять целостность приложений, поддерживающих воспроизводимые сборки, не подвергая риску целостность и безопасность своих устройств.¶

  2. Собирать собственные воспроизводимые бинарные файлы сложно, поскольку macOS не поддерживает контейнеры наподобие Docker. Если бы Apple пошла по стопам Linux (и даже Microsoft!) и добавила поддержку контейнеров, отпала бы необходимость в шагах 1–3 приведённого ниже руководства.¶

В текущих условиях для правильной настройки виртуальной машины для процесса проверки понадобятся устройство с jailbreak, не менее 1,5 часов и примерно 90 ГБ свободного места.¶

Чтобы обеспечить стабильную и легко воспроизводимую среду, сборки Telegram для iOS компилируются на виртуальной машине.¶

Шаг 1. Запуск Darwin-Containers #

  1. Получите последний код DarwinContainers: git clone https://github.com/ali-fareed/darwin-containers.git
  2. Откройте darwin-containers/DarwinContainers.xcodeproj
  3. Выберите цель DarwinContainersDaemon
  4. В разделе Signing & Capabilities выберите свою команду и задайте уникальный bundle id
  5. Запустите

Шаг 2. Создание образа ОС #

Сведения о подходящих версиях macOS и Xcode смотрите в versions.json.¶

./darwin-containers fetch¶

Загрузите подходящий образ восстановления macOS (например, 13.6):¶

./darwin-containers fetch "macOS 13.6"¶

Создайте новый образ ОС:¶

./darwin-containers create --source "macOS 13.6" --tag "macos-13.0-xcode-{XCODE_VERSION}" --manual¶

Следуйте инструкциям по установке. Укажите имя пользователя containerhost и пароль containerhost.¶

Включите Remote Login и разрешите удалённым пользователям полный доступ к диску.¶

Подключитесь к гостевой ВМ через SSH, используя имя пользователя containerhost и пароль containerhost.¶

Создайте каталог ~/.ssh и настройте authorized_keys, используя строку открытого ключа, выведенную ранее командой darwin-containers create.¶

Загрузите подходящую версию Xcode через scp и установите в /Applications. Запустите её хотя бы один раз для завершения установки. Не забудьте загрузить iOS SDK.¶

Выключите гостевую ОС.¶

Шаг 3. Получение IPA для проверки #

python3 -u build-system/Make/Make.py remote-build --darwinContainers="path-to-darwin-containers-script" --darwinContainersHost="unix://$HOME/.darwin-containers.sock" --configurationPath="build-system/appstore-configuration.json" --codesigningInformationPath=build-system/fake-codesigning --configuration=release_arm64

Дополнительные сведения:¶

build-system/Make/RemoteBuild.py
В файле .gitlab-ci.yml — задача verify_beta_testflight¶

Шаг 4. Получение исходного кода #

git clone --recursive https://github.com/TelegramMessenger/telegram-ios.git $HOME/telegram-ios
cd $HOME/telegram-ios
git checkout release-${VERSION_NUMBER}¶

Например, git checkout release-7.3. Учтите, что нужно получить всю историю git, поскольку версия сборки зависит от числа коммитов в репозитории.¶

Шаг 5. Загрузка расшифрованной версии приложения из App Store #

Для этого шага требуется устройство с jailbreak, оснащённое средствами для расшифровки приложений. Мы хотели бы упростить этот процесс, но такова цена использования технологий Apple.¶

Шаг 6. Сравнение сборки AppStore и версии, собранной на виртуальной машине #

Выполните
python3 tools/ipadiff.py build/artifacts/Telegram.ipa PATH-TO-THE-IPA-FILE-FROM-STEP-9¶

  1. Выполните: cd telegram-ios > Enter
  2. Выполните: python3 tools/ipadiff.py build/artifacts/Telegram.ipa /path/ > нажмите Enter

При успешном сравнении будет получен текст примерно такого вида:¶

IPAs are equal, except for the files that can't currently be checked:
    Excluded files that couldn't be checked due to being encrypted:
        PlugIns/SiriIntents.appex/SiriIntents
        PlugIns/Widget.appex/Widget
        PlugIns/NotificationContent.appex/NotificationContent
        PlugIns/NotificationService.appex/NotificationService
        PlugIns/Share.appex/Share
    IPAs contain Watch directory with a Watch app which can't be checked currently.
    IPAs contain .car (Asset Catalog) files that are compiled by the App Store and can't currently be checked:

        Frameworks/TelegramUI.framework/Assets.car
        Assets.car
    IPAs contain .nib (compiled Interface Builder) files that are compiled by the App Store and can't currently be checked:
        Base.lproj/LaunchScreen.nib

При любых расхождениях будет выдан подробный отчёт.¶

iOS: примечания #

  1. Если архив, созданный на шаге 5, содержит зашифрованные файлы, появится предупреждение. Если все эти файлы находятся в подпапке PlugIns, они представляют собой различные системные расширения (например, внешний обмен, Siri). Расшифровать такие файлы существующими способами получения архивов приложений через Jailbreak непросто (но мы работаем над решением этой проблемы). Если всё же удастся расшифровать их, например в iOS 8, они будут сопоставлены.¶

  2. Файлы с расширением .car — это архивы ресурсов приложения (изображений, звуков), скомпилированные и обработанные специально для целевого устройства. App Store обрабатывает их нетривиально; мы планируем отказаться от них в будущих версиях.¶

  3. Файл LaunchScreen.nib — пустой файл с описанием интерфейса, отображаемого системой до запуска приложения. App Store обрабатывает его нетривиально, но он не содержит кода и поэтому может быть проигнорирован.¶

Устранение неполадок #

Если при получении кода, сборке или сравнении приложений возникнут проблемы, свяжитесь с нами через @BotSupport и добавьте к сообщению с описанием проблемы хештег #reproducibleBuilds.¶

Устранение неполадок: Android #

  1. Убедитесь, что получена правильная версия кода.¶

  2. Убедитесь, что приложение собирается с подходящим SDK.¶

  3. Если версия gradle, используемая в Dockerfile, больше недоступна и сборка образа Docker завершается ошибкой, дождитесь обновления Dockerfile или вручную обновите её до последней доступной версии.¶
