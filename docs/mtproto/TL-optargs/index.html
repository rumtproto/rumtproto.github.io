Необязательные параметры комбинаторов и их значения #

Язык TL позволяет объявить несколько первых параметров комбинатора необязательными. После этого их почти никогда не требуется указывать явно. Это напрямую связано с другим важным свойством TL — полиморфизмом.¶

Как правило, все необязательные параметры обязаны встречаться в результирующем типе (хотя бы по одному разу).¶

(Под)выражение может сериализоваться и десериализоваться одним из двух способов:¶

  • Результирующий тип известен (например, мы разбираем ответ на ранее отправленный RPC-запрос — вызов удалённой процедуры, Remote Procedure Call — и потому знаем, значение какого типа ожидается). В этом случае по результирующему типу можно определить значения неявных параметров комбинатора.¶

  • Результирующий тип неизвестен. Он определяется по результату (де)сериализации (например, когда мы сериализуем RPC-запрос). В этом случае необходимо явно указать (и сериализовать) все необязательные параметры комбинатора, воспользовавшись его полной формой.¶

Будем считать, что функциональный комбинатор отличается от конструктора только тем, что перед его результирующим типом неявно добавляется модификатор !, а вычисление функционального выражения (удалённое или локальное) можно представить как применение некоторой полиморфной функции eval : !X -> X.¶

Более того, неизвестный результирующий тип, очевидно, обычно (но не всегда) связан с сериализацией выражения, тип которого модифицирован знаком !.¶

Можно сформулировать следующие правила. Пусть дан некоторый конструктор¶

C {a1:T1} ... {am:Tm} b1:U1 ... bn:Un = T;

Часть его аргументов или его результат могут быть помечены модификатором ! (функциональный комбинатор мы считаем конструктором, результирующий тип которого модифицирован неявным !).¶

Должны выполняться следующие условия:¶

  • Каждый из типов T1, ..., Tm, U1, ..., Un и T может зависеть от параметров типа Type или #, объявленных левее места использования данного типа.¶

  • Типы неявных параметров T1, ..., Tm не могут быть модифицированы знаком !.¶

  • Допускаются только неявные параметры типа Type или #. Иными словами, Ti — это либо Type, либо #. (В отличие от предыдущего правила, это правило в будущем может быть ослаблено.)¶

  • Каждый неявный параметр a1, ..., am обязан использоваться хотя бы один раз — либо внутри одного из типов Ui, помеченных знаком !, либо в результирующем типе T, если у того нет явного или неявного !.¶

  • Если неявный параметр ai не используется в результирующем типе или же результирующий тип помечен знаком !, то первое (самое левое) его использование обязано находиться внутри типа Uj, модифицированного знаком !.¶

Идея такова: мы считаем, что при (де)сериализации значения типа, модифицированного знаком !, этот тип нам заранее неизвестен и мы узна́ем его только по результату (де)сериализации; и наоборот, мы считаем, что при (де)сериализации значения типа без ! этот тип нам известен заранее. При соблюдении сформулированных выше правил мы в этом случае всегда можем вычислить значения всех неявных параметров — либо из (заранее известного) результирующего типа, либо из типа одного из параметров bj:!Uj (который становится известен в процессе сериализации).¶

По сути, ! обозначает направление, в котором распространяется информация о типах. По умолчанию источником сведений о типах (и об их параметрах) служит результирующий тип, а типы аргументов эти сведения получают. Использование ! меняет направление потока информации на противоположное: результирующий тип становится получателем, а тип аргумента — источником сведений о типах.¶
