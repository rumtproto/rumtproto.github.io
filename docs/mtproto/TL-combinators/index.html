Формальное описание комбинаторов TL #

Формальное объявление комбинаторов TL¶

Основная статья: Формальное описание TL. См. также Язык TL.¶

Комбинаторы в TL объявляются следующим образом:¶

combinator-decl ::= full-combinator-id { opt-args } { args } = result-type ;
full-combinator-id ::= lc-ident-full | _
combinator-id ::= lc-ident-ns | _
opt-args ::= { var-ident { var-ident } : [excl-mark] type-expr }
args ::= var-ident-opt : [ conditional-arg-def ] [ ! ] type-term
args ::= [ var-ident-opt : ] [ multiplicity *] [ { args } ]
args ::= ( var-ident-opt { var-ident-opt } : [!] type-term )
args ::= [ ! ] type-term
multiplicity ::= nat-term
var-ident-opt ::= var-ident | _
conditional-arg-def ::= var-ident [ . nat-const ] ?
result-type ::= boxed-type-ident { subexpr }
result-type ::= boxed-type-ident < subexpr { , subexpr } >¶

Поясним, что всё это означает.¶

  • Идентификатор комбинатора — это либо идентификатор, начинающийся со строчной латинской буквы (lc-ident), либо идентификатор пространства имён (тоже lc-ident), за которым следует точка и ещё один lc-ident. Таким образом, cons и lists.get — допустимые идентификаторы комбинаторов.¶

  • У комбинатора есть имя, также называемое номером (не путать с обозначением), — 32-битное число, которое однозначно его определяет. Оно либо вычисляется автоматически (см. ниже), либо явно задаётся в объявлении. Для этого к идентификатору определяемого комбинатора добавляются знак решётки (#) и ровно 8 шестнадцатеричных цифр — имя комбинатора.¶

  • Объявление комбинатора начинается с его идентификатора, к которому может быть добавлено его имя (через знак решётки).¶

  • За идентификатором комбинатора следует основная часть объявления, состоящая из объявлений полей (или переменных), включая указание их типов.¶

  • Сначала идут объявления необязательных полей (их может быть несколько или не быть вовсе). Затем идут объявления обязательных полей (их также может не быть).¶

  • Идентификатором поля (переменной) может быть любой идентификатор, который начинается с прописной или строчной буквы и не содержит ссылок на пространство имён. Хорошая практика — использовать uc-ident для идентификаторов переменных типов и lc-indent для остальных переменных.
    В оригинале здесь опечатка: lc-indent вместо lc-ident. Она сохранена, но имеется в виду обычный lc-ident — идентификатор со строчной буквы.¶

  • Далее объявление комбинатора содержит знак равенства (=) и результирующий тип (он может быть составным или встречаться впервые). Результирующий тип может быть полиморфным и/или зависимым; в качестве подвыражений могут возвращаться любые поля определяемого конструктора, имеющие тип Type или #.¶

  • Объявление комбинатора завершается точкой с запятой.¶

Далее поля, переменные и аргументы конструктора означают одно и то же.¶

Объявления необязательных полей #

  • Они имеют вид { field_1 ... field_k : type-expr }, где field_i — идентификатор переменной (поля), уникальный в пределах области видимости объявления комбинатора, а type-expr — тип, общий для всех этих полей.¶

  • Если k>1, такая запись функционально эквивалентна { field_1 : type-expr } ... { field_k : type-expr }.¶

  • Все необязательные поля обязаны быть явно поименованы (использовать _ вместо field_i не допускается).¶

  • Более того, в настоящее время имена всех необязательных полей обязаны входить в результирующий тип комбинатора (возможно, более одного раза) и сами иметь тип # (то есть nat) или Type. Поэтому, если точный результирующий тип известен, можно определить значения всех неявных параметров комбинатора (возможно, получив при этом противоречие вида 2=3, что означает недопустимость комбинатора в данном контексте).¶

Объявления обязательных полей #

  • Они могут иметь вид ( field_1 ... field_k : type-expr ), аналогичный объявлению необязательного поля, но с круглыми скобками. Такая запись эквивалентна ( field_1 : type-expr ) ... ( field_k : type-expr ), где поля определяются по одному.¶

  • В качестве имён одного или нескольких полей (field_i) можно использовать знак подчёркивания (_), указывающий, что поле анонимно (его точное имя несущественно).¶

  • Одно поле может быть объявлено без внешних круглых скобок, вот так: field_id : type-expr. Однако здесь, если type-expr — сложный тип, вокруг type-expr могут потребоваться скобки (это отражено в БНФ).¶

  • Кроме того, одно анонимное поле может быть объявлено записью type-expr, функционально эквивалентной _ : type-expr.¶

  • Объявления обязательных полей следуют одно за другим, разделяясь пробелами (точнее говоря, любым количеством пробельных символов).¶

  • Тип объявляемого поля (type-expr) может использовать ранее определённые переменные (поля) объявляемого комбинатора в качестве подвыражений (то есть значений параметров). Например:¶

    nil {X:Type} = List X; cons {X:Type} hd:X tl:(list X) = List X; typed_list (X:Type) (l : list X) = TypedList;¶

Повторения #

  • Они допускаются только среди обязательных параметров и имеют вид [ field-id : ] [ multiplicity * ] [ args ], где args записывается в том же формате, что и объявление (нескольких) обязательных полей комбинатора, с той разницей, что в типах аргументов разрешено использовать все ранее объявленные поля объемлющего комбинатора.¶

  • Имя поля объемлющего комбинатора, которое получает повторение в качестве значения, можно указать явно (field-id), а можно опустить — это равносильно указанию знака подчёркивания в качестве field-id.¶

  • Поле multiplicity — это выражение типа # (nat); им может быть числовая константа, имя одного из предшествующих полей типа # либо выражение вида ( c + v ), где c — числовая константа, а v — имя поля типа #. Смысл поля multiplicity в том, чтобы задать длину вектора (повторения), каждый элемент которого состоит из значений типов, перечисленных в args.¶

  • Поле multiplicity можно опустить. В этом случае берётся последний из предшествующих параметров типа # объемлющего комбинатора (и он обязан существовать).¶

  • Функционально повторение field-id : multiplicity * [ args ] равносильно объявлению одного поля ( field-id : %Tuple %AuxType multiplicity ), где aux_type — вспомогательный тип с новым именем, определённый как aux_type *args* = AuxType. Если внутри args используются какие-либо поля объемлющего типа, они добавляются во вспомогательный конструктор aux_type и в его результирующий тип AuxType в качестве первых (необязательных) параметров.¶

  • Если args состоит из одного анонимного поля типа some-type, то вместо %AuxType можно напрямую использовать some-type.¶

  • Если при реализации повторения переписываются описанным выше способом, разумно использовать вместо aux_type и AuxType такие идентификаторы, которые содержат имя определяемого внешнего комбинатора и порядковый номер повторения внутри его определения.¶

Пример:¶

matrix {m n : #} a : m* [ n* [ double ] ] = Matrix m n;

функционально равносильно¶

aux_type {n : #} (_ : %Tuple double n) = AuxType n;
matrix {m : #} {n : #} (a : %Tuple %(AuxType n) m) = Matrix m n;

Более того, встроенные типы Tuple и Vector можно было бы определить так:¶

tnil {X : Type} = Tuple X 0;
tcons {X : Type} {n : #} hd:X tl:%(Tuple X n) = Tuple X (S n);
vector {X : Type} (n : #) (v : %(Tuple X n)) = Vector X;

На самом деле определением Vector считается следующая равносильная запись (то есть именно эта запись используется для вычисления имени конструктора vector и его частичных применений):¶

vector {t : Type} # [ t ] = Vector t;

Если раскрыть её через Tuple, получится в точности предыдущее определение.¶

Условные поля #

Конструкция¶

args ::= var-ident-opt : [ conditional-arg-def ] [ ! ] type-term
conditional-arg-def ::= var-ident [ . nat-const ] ?¶

позволяет задавать поля, которые присутствуют только тогда, когда значение предшествующего обязательного или необязательного поля типа # (в схеме Telegram такое поле-битовую маску принято называть flags) отлично от нуля — или когда отличен от нуля выбранный бит этого поля, если применён специальный двоичный оператор выбора бита .. Пример:¶

user {fields:#} id:int first_name:(fields.0?string) last_name:(fields.1?string) friends:(fields.2?%(Vector int)) = User fields;
get_users req_fields:# ids:%(Vector int) = Vector %(User req_fields)¶
