Сведения о шифровании Telegram Passport #

Данные Telegram Passport хранятся в зашифрованном виде со сквозным шифрованием: сервер Telegram не имеет доступа к данным и служит лишь хранилищем зашифрованных данных, которые не может расшифровать. Шифрование и расшифрование выполняются исключительно клиентами Telegram с открытым исходным кодом.¶

Обзор #

Для шифрования каждого отдельного элемента Telegram Passport клиент создаёт случайный секрет. Секрет представляет собой 32-байтное число, сумма байтов которого по модулю 255 равна 239. Затем этот секрет шифруется с помощью passport_secret, создаваемого пользователем при настройке Telegram Passport. passport_secret шифруется паролем пользователя и хранится в зашифрованном виде в облаке Telegram.¶

Секрет Passport #

Секрет Passport — один из секретных параметров, используемых для шифрования данных, загружаемых пользователем в облако Telegram.¶

При первоначальной настройке Telegram Passport его необходимо создать, зашифровать и загрузить, как описано в разделе Шифрование секрета Passport.¶

При обычном использовании Telegram Passport его необходимо скачать и расшифровать для использования, как описано в разделе Расшифрование секрета Passport.¶

Если в новой версии Telegram определён новый, более безопасный алгоритм шифрования или обновлён пароль 2FA, секрет Passport также необходимо скачать, повторно зашифровать и загрузить, как описано в разделе Шифрование секрета Passport.¶

Шифрование секрета Passport #

Прежде всего с сервера получают параметры Passport; схема:¶

account.password#957b50fb flags:# has_recovery:flags.0?true has_secure_values:flags.1?true has_password:flags.2?true current_algo:flags.2?PasswordKdfAlgo srp_B:flags.2?bytes srp_id:flags.2?long hint:flags.3?string email_unconfirmed_pattern:flags.4?string new_algo:PasswordKdfAlgo new_secure_algo:SecurePasswordKdfAlgo secure_random:bytes pending_reset_date:flags.5?int login_email_pattern:flags.6?string = account.Password;

securePasswordKdfAlgoUnknown#004a8537 = SecurePasswordKdfAlgo;
securePasswordKdfAlgoPBKDF2HMACSHA512iter100000#bbf2dda0 salt:bytes = SecurePasswordKdfAlgo;
securePasswordKdfAlgoSHA512#86471d92 salt:bytes = SecurePasswordKdfAlgo;


---functions---

account.getPassword#548a30f5 = account.Password;

При первом использовании Telegram Passport клиент создаёт passport_secret (32-байтное число, сумма байтов которого по модулю 255 равна 239), используя часть созданного сервером случайного secure_random из account.password как дополнительный источник энтропии для OpenSSL (при повторном шифровании passport_secret более безопасным алгоритмом или после смены пароля 2FA вместо него используется предыдущий passport_secret). Затем passport_secret шифруется паролем пользователя и хешируется с использованием схемы и параметров, указанных в поле new_algo account.password.¶

Сервер должен всегда возвращать конструктор securePasswordKdfAlgoPBKDF2HMACSHA512iter100000 в поле new_algo. Если возвращён securePasswordKdfAlgoUnknown, удалённо сохранённый секрет зашифрован новым алгоритмом, не поддерживаемым текущим клиентом: пользователю следует обновить приложение.¶

Другие конструкторы могут использоваться только при расшифровании старых параметров Passport, созданных устаревшим клиентом; в таком случае секрет Passport следует повторно зашифровать и обновить с помощью new_algo.¶

  • Прежде всего вычисляется отпечаток секрета ( passport_secret_fingerprint ):¶

    passport_secret_fingerprint = long( slice( SHA256( passport_secret ), 0, 8 ) )

  • Затем открытый password пользователя для 2FA хешируется указанным алгоритмом.¶

    • securePasswordKdfAlgoPBKDF2HMACSHA512iter100000¶

      • Извлекаются/создаются следующие параметры:
        • 8 байт серверной соли server_passport_salt из поля salt конструктора securePasswordKdfAlgoPBKDF2HMACSHA512iter100000
        • 32 случайных байта клиентской соли client_passport_salt.

      Чтобы хеши паролей, хранящиеся на сервере, были устойчивее к атакам перебором и при этом сохранялась практическая скорость на устройствах, популярных среди пользователей Telegram, используется PBKDF2-HMAC-SHA512 с 100000 итерациями:¶

      server_passport_salt = new_algo.salt
client_passport_salt = random_bytes(32)
passport_secret_salt = server_passport_salt + client_passport_salt
password_hash = PBKDF2( password, passport_secret_salt, HMACSHA512, 100000)

  • Из созданного password_hash извлекаются параметры secret_key и iv¶

    secret_key = slice( password_hash, 0, 32 )
iv = slice( password_hash, 32, 16 )

  • Созданный ранее passport_secret шифруется с помощью AES256-CBC с ключом secret_key и iv:¶

    encrypted_passport_secret = AES256_CBC_ENC(passport_secret, secret_key, iv)

  • encrypted_passport_secret вместе с passport_secret_salt и отпечатком секрета passport_secret_fingerprint сохраняется на сервере; схема:¶

    boolFalse#bc799737 = Bool;
boolTrue#997275b5 = Bool;

inputCheckPasswordSRP#d27ff082 srp_id:long A:bytes M1:bytes = InputCheckPasswordSRP;

securePasswordKdfAlgoPBKDF2HMACSHA512iter100000#bbf2dda0 salt:bytes = SecurePasswordKdfAlgo;

secureSecretSettings#1527bcac secure_algo:SecurePasswordKdfAlgo secure_secret:bytes secure_secret_id:long = SecureSecretSettings;

account.passwordInputSettings#c23727c9 flags:# new_algo:flags.0?PasswordKdfAlgo new_password_hash:flags.0?bytes hint:flags.0?string email:flags.1?string new_secure_settings:flags.2?SecureSecretSettings = account.PasswordInputSettings;

---functions---

account.updatePasswordSettings#a59b102f password:InputCheckPasswordSRP new_settings:account.PasswordInputSettings = Bool;

    Клиент вызывает account.updatePasswordSettings.¶

    • Параметр password создаётся с использованием пароля 2FA пользователя, как описано в разделе обновления пароля 2FA.
    • Конструктор account.passwordInputSettings в new_settings должен содержать только параметр new_secure_setting с secureSecretSettings.

    Конструктор secureSecretSettings создаётся следующим образом:¶

    • Для secure_algo устанавливается значение поля new_algo account.password, использованное для создания зашифрованного секрета Passport: вместо salt подставляется passport_secret_salt
    • Для secure_secret устанавливается новый encrypted_passport_secret
    • Для secure_secret_id устанавливается новый passport_secret_fingerprint

После этого клиент получает зашифрованный passport_secret с сервера и расшифровывает его после ввода пользователем пароля ».¶

При смене пароля или появлении более безопасного алгоритма в обновлении API клиент повторно шифрует passport_secret с использованием нового пароля. Если пароль отключён, все данные Telegram Passport теряются.¶

Расшифрование секрета Passport #

Схема:¶

securePasswordKdfAlgoUnknown#004a8537 = SecurePasswordKdfAlgo;
securePasswordKdfAlgoPBKDF2HMACSHA512iter100000#bbf2dda0 salt:bytes = SecurePasswordKdfAlgo;
securePasswordKdfAlgoSHA512#86471d92 salt:bytes = SecurePasswordKdfAlgo;

secureSecretSettings#1527bcac secure_algo:SecurePasswordKdfAlgo secure_secret:bytes secure_secret_id:long = SecureSecretSettings;

account.passwordSettings#9a5c33e5 flags:# email:flags.0?string secure_settings:flags.1?SecureSecretSettings = account.PasswordSettings;

---functions---

account.getPasswordSettings#9cd4eaf9 password:InputCheckPasswordSRP = account.PasswordSettings;

Клиент запрашивает пароль 2FA пользователя и создаёт параметры SRP для передачи в account.getPasswordSettings.¶

Если пароль верен, возвращается конструктор account.passwordSettings с secureSecretSettings.¶

Параметры encrypted_passport_secret, passport_secret_fingerprint извлекаются из конструктора secureSecretSettings:¶

encrypted_passport_secret = secureSecretSettings.secure_secret
passport_secret_fingerprint = secureSecretSettings.secure_id

Объединённая passport_secret_salt извлекается из SecurePasswordKdfAlgo.¶

passport_secret_salt = SecurePasswordKdfAlgo.salt

Подобно шифрованию секрета Passport, для расшифрования и проверки encrypted_passport_secret используется следующий процесс:¶

  • Открытый password пользователя для 2FA хешируется указанным алгоритмом.¶

    • securePasswordKdfAlgoPBKDF2HMACSHA512iter100000 Чтобы хеши паролей, хранящиеся на сервере, были устойчивее к атакам перебором и при этом сохранялась практическая скорость на устройствах, популярных среди пользователей Telegram, используется PBKDF2-HMAC-SHA512 с 100000 итерациями:¶

      password_hash = PBKDF2( password, passport_secret_salt, HMACSHA512, 100000)

    • securePasswordKdfAlgoSHA512 Этот режим встречается только в хешах, созданных устаревшими клиентами: хеши, созданные в этом режиме, необходимо повторно зашифровать и обновить с использованием securePasswordKdfAlgoPBKDF2HMACSHA512iter100000, как описано в разделе Шифрование секрета Passport.¶

      password_hash = SHA512( passport_secret_salt + password + passport_secret_salt )

  • Из созданного password_hash извлекаются параметры secret_key и iv¶

    secret_key = slice( password_hash, 0, 32 )
iv = slice( password_hash, 32, 16 )

  • encrypted_passport_secret расшифровывается с помощью AES256-CBC с ключом secret_key и iv:¶

    passport_secret = AES256_CBC_DEC(encrypted_passport_secret, secret_key, iv)

  • passport_secret проверяется созданием и сверкой отпечатка:¶

    my_passport_secret_fingerprint = long( slice( SHA256( passport_secret ), 0, 8 ) )

    Клиент обязан проверить, что passport_secret_fingerprint действительно равен my_passport_secret_fingerprint.¶

passport_secret теперь можно использовать для расшифрования зашифрованных данных Passport, хранящихся на серверах Telegram:¶

Шифрование данных и файлов #

Шифрование #

Для шифрования данных Telegram Passport клиент создаёт data_secret (32-байтное число, сумма байтов которого по модулю 255 равна 239). Данные шифруются по следующей схеме:¶

  • Данные дополняются до длины, кратной 16 байтам. Для этого в начало добавляется от 32 до 255 байтов: первый байт всегда содержит число добавленных байтов, а остальные случайны.¶

  • Вычисляется хеш этих данных data_hash:¶

    data_hash = SHA256( data_bytes )

  • Вычисляется ключ шифрования data_key:¶

    data_secret_hash = SHA512( data_secret + data_hash )
data_key = slice( data_secret_hash, 0, 32 )
iv = slice( data_secret_hash, 32, 16 )

  • Данные шифруются с помощью AES256-CBC с ключом data_key и iv:¶

    encrypted_data = AES256_CBC_ENC(data, data_key, iv)

  • Вычисляется secret_key, ключ для шифрования data_secret:¶

    secret_hash = SHA512( passport_secret + data_hash )
secret_key = slice( secret_hash, 0, 32 )
iv = slice( secret_hash, 32, 16 )

  • data_secret шифруется с помощью AES256-CBC с ключом secret_key и iv:¶

    encrypted_data_secret = AES256_CBC_ENC(data_secret, secret_key, iv)

  • encrypted_data вместе с encrypted_data_secret и data_hash сохраняются на сервере:¶

    Схема:¶

Упаковка #

SecureData #
secureData#8aeabec3 data:bytes data_hash:bytes secret:bytes = SecureData;
  • data — зашифрованный и дополненный (см. шифрование) сериализованный в JSON объект одного из следующих типов: PersonalDetails, IdDocumentData, ResidentialAddress в зависимости от выбранного типа. Данные должны быть в формате JSON, а не TL, поскольку они передаются сервису напрямую со сквозным шифрованием, без посредника Bot API, преобразующего объекты TL.
  • data_hash — это data_hash
  • secret — это encrypted_data_secret

Данные — это зашифрованный и дополненный JSON-объект одного из перечисленных JSON-типов; какого именно, зависит от выбранного типа.¶

  • Поле secret — это encrypted_data_secret.

Адрес электронной почты/номер телефона передаётся в открытом виде с помощью соответствующего конструктора SecurePlainData. Для подтверждения номера телефона или адреса электронной почты и использования его в Telegram Passport применяйте соответствующие методы:¶

  • account.sendVerifyEmailCode — Отправить код подтверждения по электронной почте для passport Telegram.
  • account.verifyEmail — Подтвердить адрес электронной почты для passport Telegram.
  • account.sendVerifyPhoneCode — Отправить код подтверждения номера телефона для passport Telegram.
  • account.verifyPhone — Подтвердить номер телефона для passport Telegram.
  • auth.resendCode — Только для подтверждения кода телефона: повторно отправить код другим способом
  • auth.cancelCode — Только для подтверждения кода телефона: отменить подтверждение кода телефона

Процесс аналогичен используемому для входа:¶

  • Отправьте код электронной почты/телефона соответствующим методом account.sendVerify*Code
    • Обязательно передайте emailVerifyPurposePassport в качестве цели подтверждения в account.sendVerifyEmailCode.
  • Передайте полученный код соответствующему методу account.verify*
  • Только при подтверждении кода телефона можно также повторно отправить/отменить код телефона с помощью auth.resendCode/auth.cancelCode, как при входе.

Подробнее см. в документации по авторизации.¶

Учётные данные Passport #

Когда сервис запрашивает данные, он передаёт клиенту nonce. Одноразовое значение — криптографически стойкий уникальный идентификатор, позволяющий сервису идентифицировать запрос при получении данных, а также подтвердить целостность данных. Сервер Telegram не имеет доступа к этому одноразовому значению.¶

После того как пользователь авторизует передачу данных Telegram Passport, клиент формирует учётные данные (объект JSON Credentials). Учётные данные содержат data_hash и data_secret каждого элемента Telegram Passport, к которому пользователь разрешил доступ. Кроме того, учётные данные всегда содержат nonce, полученное клиентом от сервиса при инициации запроса.¶

Затем учётные данные передаются сервису через Bot API в зашифрованном виде. Для шифрования учётных данных клиент создаёт credentials_secret (32-байтное число, сумма байтов которого по модулю 255 равна 239). Затем учётные данные шифруются по следующей схеме:¶

  • Учётные данные дополняются до длины, кратной 16 байтам. Для этого в начало добавляется от 32 до 255 байтов: первый байт всегда содержит число добавленных байтов, а остальные случайны.¶

  • Вычисляется хеш дополненных учётных данных credentials_hash:¶

    credentials_hash = SHA256( credentials )

  • Вычисляется ключ шифрования credentials_key:¶

    credentials_secret_hash = SHA512( credentials_secret + credentials_hash )
credentials_key = slice( credentials_secret_hash, 0, 32 )
iv = slice( credentials_secret_hash, 32, 16 )

  • Учётные данные шифруются с помощью AES256-CBC с ключом credentials_key и iv.¶

    encrypted_credentials = AES256-CBC-ENC(credentials, credentials_key, iv)

  • credentials_secret шифруется открытым RSA-ключом сервиса с OPENSSL_PKCS1_OAEP_PADDING.¶

    encrypted_credentials_secret = RSA-ENC(credentials_secret, key, OPENSSL_PKCS1_OAEP_PADDING)

  • Зашифрованные учётные данные передаются сервису через MTProto API вместе с зашифрованным credentials_secret и credentials_hash. Вместе с учётными данными сервис получает из облака Telegram запрошенные им данные в зашифрованном виде. См. Отправка формы Passport и PassportData:¶

    secureCredentialsEncrypted#33f0ea47 data:bytes hash:bytes secret:bytes = SecureCredentialsEncrypted;

  • data — это encrypted_credentials¶

  • hash — это credentials_hash¶

  • secret — это encrypted_credentials_secret¶

Затем сервис расшифровывает данные, как описано здесь.¶
