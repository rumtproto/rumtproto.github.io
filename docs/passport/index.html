Руководство по Telegram Passport #

Telegram Passport — единый способ авторизации для сервисов, которым требуется удостоверение личности. Пользователь один раз загружает свои документы, а затем мгновенно передаёт данные сервисам, которым нужен настоящий документ (финансовые организации, ICO и т. п.). Благодаря сквозному шифрованию у Telegram нет доступа к персональным данным пользователей.¶

Обзор #

С точки зрения сервиса, которому нужно удостоверение личности, процесс выглядит так:¶

  • Пользователь нажимает «Войти через Telegram» на вашем сайте или в вашем приложении.
  • Вы запрашиваете нужные данные.
  • Пользователь принимает вашу политику конфиденциальности и соглашается предоставить свои данные.
  • Приложение Telegram пользователя скачивает запрошенные вами данные из хранилища Telegram со сквозным шифрованием и расшифровывает их.
  • Если части запрошенных данных не хватает, пользователь может прямо на этом шаге добавить её в свой Telegram Passport.
  • Приложение пользователя шифрует данные вашим открытым ключом и отправляет их вам.
  • Вы расшифровываете данные, проверяете их на ошибки и повторно запрашиваете отсутствующую или недействительную информацию.
  • Вы регистрируете пользователя в своём сервисе. Готово!

Ознакомьтесь с этим примером, чтобы увидеть Telegram Passport в действии.¶

Чтобы узнать больше о Telegram Passport с точки зрения пользователя, прочитайте эту запись в блоге и техническую документацию MTProto. Если вас интересуют алгоритмы шифрования, используемые на стороне Telegram, смотрите эту страницу.¶

Последние изменения #

25 августа 2018 года #

Telegram Passport 1.1 (запись в блоге)¶

  • Добавлена поддержка запроса нескольких документов одного типа. См. новые объекты PassportScope, PassportScopeElement, PassportScopeElementOneOfSeveral и PassportScopeElementOne.
  • Добавлена поддержка вторых имён.
  • Добавлена поддержка запроса заверенных переводов на английский язык документов (см. Поля; в объект SecureValue также добавлено новое поле translation). Примечание: запрашивайте перевод, только после того как получите действительный документ, для которого он необходим.
  • Добавлена поддержка запроса имён на языке страны проживания пользователя (если это не английский). В объект PersonalDetails добавлены новые поля first_name_native, last_name_native и middle_name_native.
  • Параметр payload заменён новым параметром nonce, выполняющим ту же функцию, чтобы его назначение было понятнее (см. Параметры запроса и объект Credentials).
  • Страница примера обновлена для поддержки новой функциональности.

Настройка Telegram Passport #

Чтобы интегрировать Telegram Passport в процесс входа или проверки, необходим работающий бот Telegram (как его получить, описано на этой странице).¶

Для запроса данных у пользователей Telegram Passport вашему боту нужно сгенерировать пару ключей шифрования.¶

Создание закрытого ключа #

Сначала с помощью консоли сгенерируйте закрытый ключ:¶

openssl genrsa 2048 > private.key

ПРЕДУПРЕЖДЕНИЕ: Храните закрытый ключ В СЕКРЕТЕ!¶

Создание открытого ключа #

Затем с помощью консоли выведите соответствующий открытый ключ:¶

openssl rsa -in private.key -pubout

Используйте команду /setpublickey с @BotFather, чтобы связать этот открытый ключ с вашим ботом.¶

Политика конфиденциальности #

Добавьте ссылку на свою политику конфиденциальности командой /setprivacypolicy. Пользователи увидят эту ссылку, когда им будет предложено разрешить вам доступ к их данным.¶

Используйте следующие параметры для запроса информации через SDK:¶

Этот объект описывает запрашиваемый элемент и должен быть одним из следующих:¶

Получение информации #

Когда пользователь подтверждает ваш запрос, нажав кнопку «Авторизовать», Bot API отправляет боту Update с полем passport_data, содержащим зашифрованные данные Telegram Passport.¶

Учтите, что перед использованием все поля в кодировке base64 следует декодировать.¶

Расшифровка данных #

Чтобы расшифровать полученные данные, сначала расшифруйте учётные данные из EncryptedCredentials.¶

  1. Расшифруйте секрет учётных данных (поле secret в EncryptedCredentials) своим закрытым ключом (задайте параметр дополнения OAEP, например OPENSSL_PKCS1_OAEP_PADDING в PHP)¶

  2. Используйте этот секрет и хеш учётных данных (поле hash в EncryptedCredentials) для вычисления credentials_key и credentials_iv, как описано ниже:¶

     credentials_secret_hash = SHA512( credentials_secret + credentials_hash )
 credentials_key = slice( credentials_secret_hash, 0, 32 )
 credentials_iv = slice( credentials_secret_hash, 32, 16 )

  3. Расшифруйте данные учётных данных (поле data в EncryptedCredentials) алгоритмом AES256-CBC, используя эти credentials_key и credentials_iv. ВАЖНО: на этом шаге убедитесь, что хеш учётных данных равен SHA256( credentials_data )¶

  4. Данные credentials дополнены (padding — выравнивающее дополнение) 32–255 случайными байтами, чтобы их длина стала кратна 16 байтам. Первый байт содержит длину этого дополнения (включая сам байт). Удалите дополнение, чтобы получить данные.¶

Учтите, что все хеши представлены как необработанные двоичные данные, а не шестнадцатеричные строки¶

DataCredentials — учётные данные #

Эти учётные данные можно использовать для расшифровки зашифрованных данных из поля data в EncryptedPassportElement.¶

ПолеТипОписание
data_hashStringКонтрольная сумма зашифрованных данных
СекретStringСекрет зашифрованных данных

  1. Чтобы расшифровать данные, используйте соответствующий секрет и data_hash из DataCredentials, как описано ниже:¶

     data_secret_hash = SHA512( data_secret + data_hash )
 data_key = slice( data_secret_hash, 0, 32 )
 data_iv = slice( data_secret_hash, 32, 16 )

  2. Используйте AES256-CBC с этими data_key и data_iv для расшифровки данных (поле data в EncryptedPassportElement). ВАЖНО: на этом шаге убедитесь, что data_hash из учётных данных равен SHA256( data ).¶

  3. Данные дополняются 32–255 случайными байтами дополнения, чтобы их длина делилась на 16 байт. Первый байт содержит длину дополнения (включая этот байт). Удалите дополнение, чтобы получить данные.¶

  4. Данные представляют собой объект, сериализованный в JSON, одного из следующих типов: PersonalDetails, IdDocumentData, ResidentialAddress — в зависимости от типа.¶

FileCredentials — учётные данные файлов #

Эти учётные данные можно использовать для расшифровки зашифрованных файлов из полей front_side, reverse_side, selfie, files и translation в EncryptedPassportElement.¶

ПолеТипОписание
file_hashStringКонтрольная сумма зашифрованного файла
СекретStringСекрет зашифрованного файла

  1. Чтобы расшифровать файл, используйте соответствующий секрет и file_hash из FileCredentials, как описано ниже:¶

     file_secret_hash = SHA512( file_secret + file_hash )
 file_key = slice( file_secret_hash, 0, 32 )
 file_iv = slice( file_secret_hash, 32, 16 )

  2. Загрузите зашифрованный файл методом getFile.¶

  3. Используйте AES256-CBC с этими file_key и file_iv для расшифровки содержимого файла. ВАЖНО: на этом шаге убедитесь, что file_hash из учётных данных равен SHA256( file_content ).¶

  4. Содержимое файла дополняется 32–255 случайными байтами дополнения, чтобы его длина делилась на 16 байт. Первый байт содержит длину дополнения (включая этот байт). Удалите дополнение, чтобы получить содержимое файла.¶

Исправление ошибок #

Если полученные данные содержат ошибки, бот может использовать метод setPassportDataErrors, чтобы сообщить о них пользователю и снова запросить информацию. Пользователь не сможет повторно отправить данные, пока не будут исправлены все ошибки.¶
