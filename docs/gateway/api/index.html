API шлюза Telegram #

Gateway API — это HTTP-интерфейс для разработчиков, которым нужно доставлять автоматические сообщения, например коды верификации, пользователям, зарегистрировавшим номер телефона в Telegram.¶

На этой странице приведена полная документация API для разработчиков. Подробнее об API и его возможностях см. в обзоре платформы верификации и руководстве по Gateway API.¶

Последние изменения #

26 февраля 2025 года #

  • Обновлены допустимые значения ttl в sendVerificationMessage. Теперь поддерживается диапазон от 30 до 3600 секунд.
  • Уточнено поведение ttl:
    • Если сообщение не доставлено за указанный ttl, плата за запрос будет возвращена автоматически.
    • Если сообщение успешно доставлено в течение ttl, возврата средств не будет.
    • Если ttl уже использовался до этого обновления, для получения возврата ничего менять не нужно.
  • Обновлён revokeVerificationMessage: теперь указано, что сообщение не будет удалено, если оно уже доставлено или прочитано.
  • В RequestStatus добавлено необязательное поле is_refunded, указывающее, была ли возвращена плата за запрос.
  • В поле status объекта DeliveryStatus добавлены новые допустимые статусы delivered и expired.

Выполнение запросов #

Все запросы к Telegram Gateway API должны выполняться по HTTPS и иметь следующий вид: https://gatewayapi.telegram.org/METHOD_NAME. Например:¶

https://gatewayapi.telegram.org/sendVerificationMessage

Поддерживаются HTTP-методы GET и POST. В запросах Gateway API поддерживаются три способа передачи параметров:¶

  • Строка запроса URL
  • application/x-www-form-urlencoded (кодирование полей формы)
  • application/json — формат содержимого

Ответ содержит JSON-объект, в котором всегда есть логическое поле ok. Если ok равно true, запрос выполнен успешно, а его результат находится в поле result. При неуспешном запросе ok равно false, а ошибка описана в поле error (например, ACCESS_TOKEN_INVALID).¶

  • Все методы Gateway API нечувствительны к регистру.
  • Все запросы должны выполняться с использованием UTF-8.

Authorization #

Перед вызовом методов API необходимо получить токен доступа в настройках аккаунта Telegram Gateway.¶

Токен необходимо передавать в каждом запросе одним из двух способов:¶

  • в HTTP-заголовке: Authorization: Bearer <token>
  • в качестве параметра access_token.

Доступные методы #

Поддерживаются HTTP-методы GET и POST. Для передачи параметров в запросах Telegram Gateway API используйте строку запроса URL, application/json или application/x-www-form-urlencoded.
При успешном вызове возвращается JSON-объект с результатом.¶

sendVerificationMessage #

Используйте этот метод для отправки сообщения верификации. За каждую успешную доставку сообщения взимается плата согласно тарифному плану. Обратите внимание: при отправке кодов на собственный номер телефона этот метод всегда бесплатен. При успехе возвращает объект RequestStatus.¶

checkSendAbility #

Используйте этот метод, чтобы при необходимости проверить возможность отправки сообщения верификации на указанный номер телефона. Если возможность отправки подтверждена, взимается плата согласно тарифному плану. После проверки можно отправить сообщение верификации методом sendVerificationMessage, указав request_id из этого ответа.¶

В рамках одного request_id может быть списана только одна плата. Однократный вызов sendVerificationMessage с возвращённым request_id бесплатен, а повторные вызовы приведут к ошибке. Напротив, вызовы без request_id создают новые запросы и влекут соответствующую плату. Обратите внимание: при отправке кодов на собственный номер телефона этот метод всегда бесплатен.¶

Если сообщение можно отправить, возвращает объект RequestStatus. В противном случае возвращается соответствующая ошибка.¶

Примеры — в руководстве >¶

ПараметрТипОбязательныйОписание
phone_numberStringДаНомер телефона, для которого нужно проверить возможность отправки сообщения верификации, в формате E.164.

checkVerificationStatus #

Используйте этот метод для проверки статуса ранее отправленного сообщения верификации. Если код был сгенерирован Telegram, с помощью этого метода также можно проверить правильность кода, введённого пользователем. Даже если код задан самостоятельно, рекомендуется вызвать этот метод после успешного ввода пользователем кода, передав правильный код в параметре code, чтобы мы могли отслеживать коэффициент конверсии ваших верификаций. При успехе возвращает объект RequestStatus.¶

request_idStringДаУникальный идентификатор запроса верификации, статус которого нужно проверить.
кодStringНеобязательныйКод, введённый пользователем. Если указан, метод проверяет, действителен ли код для соответствующего запроса.

revokeVerificationMessage #

Используйте этот метод для отзыва ранее отправленного сообщения верификации. Возвращает True, если запрос на отзыв получен. Однако это не гарантирует удаления сообщения. Например, если сообщение уже доставлено или прочитано, оно не будет удалено.¶

ПараметрТипОбязательныйОписание

Доступные типы #

Все типы, используемые в ответах Telegram Gateway API, представлены JSON-объектами.¶

Для хранения всех полей Integer, если не указано иное, безопасно использовать 32-битные целые числа со знаком.¶

Поля Optional могут не возвращаться, если они неактуальны.¶

Сообщение о доставке #

Telegram Gateway API может отправлять отчёты о доставке на указанный пользователем URL обратного вызова. Если включить в запрос параметр callback_url, API отправит на этот URL HTTP POST-запрос с отчётом о доставке сообщения. Полезная нагрузка POST-запроса будет JSON-объектом, представляющим объект RequestStatus.¶

Ваш URL должен ответить кодом состояния HTTP 200, чтобы подтвердить получение отчёта. Любой другой код состояния считается ошибкой, и сервис повторит отправку того же отчёта до 10 раз с возрастающими задержками между попытками. Если все повторы завершатся неудачно, отчёт будет считаться потерянным.¶

Проверка целостности отчёта #

Все отчёты, отправленные на ваш callback_url, если он указан, также будут содержать следующие заголовки:¶

  • X-Request-Timestamp — метка времени Unix, указывающая, когда сервер отправил отчёт.
  • X-Request-Signature — подпись, созданная сервером и необходимая для аутентификации отчёта на вашей стороне.

Подтвердить происхождение и проверить целостность полученных отчётов можно, сопоставив подпись из заголовка X-Request-Signature с шестнадцатеричным представлением подписи HMAC-SHA-256 для строки проверки данных с хешем SHA256 токена API, показанного в настройках аккаунта Gateway.¶

Строка проверки данных — это конкатенация метки времени отчёта из заголовка X-Request-Timestamp, символа перевода строки ('\n', 0x0A), используемого как разделитель, и необработанного тела POST-запроса HTTP.¶

Пример:¶

data_check_string = X-Request-Timestamp + '\n' + post_body
secret_key = SHA256(api_token)
if (hex(HMAC_SHA256(data_check_string, secret_key)) == X-Request-Signature) {
  // data is from Telegram
}

Чтобы предотвратить использование устаревших данных, следует также проверять заголовок X-Request-Timestamp, содержащий метку времени Unix момента отправки соответствующего отчёта сервером.¶
