Авторизация через Telegram Gateway: краткое руководство #

Telegram Gateway API позволяет любому сервису отправлять коды авторизации через Telegram вместо традиционных SMS, предлагая более доступную, безопасную и надёжную альтернативу. Это руководство поможет быстро интегрировать API в ваш сервис. Подробнее см.:¶

  • Полный справочник по Gateway API для разработчиков
  • Обзор Gateway
  • Вопросы и ответы о Gateway
  • Условия использования Gateway

Содержание #

  • Перед началом работы
  • Отправка кодов авторизации
  • Проверка статуса авторизации
  • Получение отчётов

Перед началом работы #

Кратко: откройте эту страницу и войдите с номером телефона Telegram, затем пополните аккаунт здесь и запишите свой токен API.¶

Перед началом работы потребуется создать аккаунт на нашей специализированной платформе Gateway. Для этого перейдите на платформу Gateway, нажмите «Войти для начала», а затем подтвердите вход через Telegram. При первом использовании платформы вам будет предложено указать основную информацию о себе и своей компании.¶

Для тестирования можно отправлять бесплатные сообщения верификации на аккаунт Telegram, привязанный к номеру, который использовался для входа.¶

Пополнение счёта #

Чтобы отправлять сообщения другим пользователям Telegram через Gateway API, потребуется пополнить аккаунт. Для этого перейдите на эту страницу, нажмите «Пополнить через Fragment» и следуйте инструкциям в Fragment.¶

На той же странице находится подробная история операций с пополнениями и расходами.¶

Получение API-токена #

Перед вызовом методов API необходимо получить токен доступа в настройках аккаунта Telegram Gateway. Для этого откройте эту страницу и нажмите «Копировать токен».¶

Токен необходимо передавать в каждом запросе одним из двух способов:¶

  • В HTTP-заголовке: Authorization: Bearer <token>
  • В качестве параметра access_token.

В этом руководстве предполагается, что вы решили использовать bearer token.¶

Для повышения безопасности на этой странице можно ограничить IP-адреса или диапазоны IP, которым разрешено использовать ваш токен API.¶

Запросы к API #

К API можно обращаться HTTP-методами GET и POST из выбранного языка или фреймворка. В этом руководстве в качестве примера используется Python и предполагается, что определено следующее:¶

import requests

# Base API url, your Gateway API token and a phone number
BASE_URL = 'https://gatewayapi.telegram.org/'
TOKEN = 'AAEFAAAAQKI_mDsJppSEQRr3kLOz9SatBxq48BgQLSHLRv'
PHONE = '+391234567890'
HEADERS = {
    'Authorization': f'Bearer {TOKEN}',
    'Content-Type': 'application/json'
}

# Function to query the API
def post_request_status(endpoint, json_body):
    url = f"{BASE_URL}{endpoint}"
    response = requests.post(url, headers=HEADERS, json=json_body)
    if response.status_code == 200:
        response_json = response.json()
        if response_json.get('ok'):
            res = response_json.get('result', {})
            return res
        else:
            error_message = response_json.get('error', 'Unknown error')
            print(f"Error: {error_message}")
            return None
    else:
        print(f"Failed to get request status: HTTP {response.status_code}")
        return None

Отправка кодов авторизации #

Кратко: передайте номер телефона (в формате E.164) в этот метод, чтобы сразу отправить пользователю код авторизации. Если нужна пробная проверка возможности доставки кода, используйте этот метод.¶

Чтобы отправить пользователю код, сгенерированный Telegram, можно использовать метод sendVerificationMessage:¶

endpoint = 'sendVerificationMessage'

json_body = {
    'phone_number': PHONE,         # Must be the one tied to request_id
    'code_length': 6,              # Ignored if you specify your own 'code'
    'ttl': 60,                     # 1 minute
    'payload': 'my_payload_here',  # Not shown to users
    'callback_url': 'https://my.webhook.here/auth'
}

result = post_request_status(endpoint, json_body)

Если метод возвращает ошибку (например, потому что пользователь не может получать коды), плата не взимается. При успехе он возвращает объект RequestStatus.¶

При желании можно указать параметр sender_username, назначив принадлежащий вам верифицированный канал каналом, от имени которого пользователю будет отправлен код. При отправке кодов себе для тестирования канал не обязан быть верифицирован.¶

Проверка возможности доставки кодов #

Перед отправкой можно также при необходимости использовать метод checkSendAbility, чтобы убедиться, что целевой пользователь способен получать сообщения в Telegram. Это особенно полезно, когда код сгенерирован самостоятельно, но нужно проверить возможность его доставки, прежде чем отправлять его пользователю через Gateway API.¶

endpoint = 'checkSendAbility'

json_body = {
    'phone_number': PHONE # E.164 format
}

result = post_request_status(endpoint, json_body)

if result:
    request_id = result.get('request_id')
    print(f"Request ID: {request_id}")

С вас автоматически взимается предоплата за одно сообщение, если метод указывает, что с пользователем можно связаться, — независимо от того, будет ли сообщение в итоге отправлено. Если метод возвращает ошибку (например, потому что пользователь не может получать коды), плата не взимается.¶

Если проверка прошла успешно и вы решаете отправить сообщение, используйте request_id, возвращённый методом checkSendAbility, чтобы не платить за сообщение повторно.¶

Отзыв кодов #

При желании можно отозвать коды до истечения их срока действия, передав соответствующий request_id методу revokeVerificationMessage. Уже прочитанные сообщения не будут удалены.¶

Обратите внимание: за отозванные коды средства не возвращаются. Если нужно бесплатно отправлять коды для тестирования, направляйте их на собственный номер телефона.¶

Проверка статуса авторизации #

Если Telegram генерирует код (то есть в запросе не указан параметр code), можно использовать метод checkVerificationStatus для проверки OTP, введённого пользователем.¶

endpoint = 'checkVerificationStatus'

json_body = {
    'request_id': request_id, # Relevant request id
    'code': CODE,             # The code the user entered in your app
}

result = post_request_status(endpoint, json_body)

# Assuming the request was successful
status = result.get('verification_status', {}).get('status')
print(status == 'code_valid') # True if the user entered the correct code

Даже если код задан самостоятельно, следует вызвать этот метод после того, как пользователь введёт код, чтобы в интерфейсе Gateway отображалась точная статистика.¶

Получение отчётов #

Если включить параметр callback_url в запрос sendVerificationMessage, Gateway API отправит POST-запрос на этот URL с отчётом о доставке сообщения. Полезная нагрузка POST-запроса будет JSON-объектом, представляющим соответствующий объект RequestStatus.
При обработке отчётов обязательно проверяйте целостность полученных данных, как описано здесь.¶

Примечание: актуальная документация API с подробными объяснениями каждого метода и параметра доступна здесь. Это руководство предназначено для быстрого начала работы и предполагает, что вы знакомы с программированием, корректной обработкой ошибок, надлежащей защитой и хранением номеров телефонов, ответов и учётных данных.¶
