Описание конкурса по взлому Telegram #

« Назад к объявлению конкурса¶

Текущий раунд конкурса завершён. Перейти к результатам »¶

В этом конкурсе вы берёте на себя роль злоумышленника, контролирующего серверы Telegram. Ваша цель — извлечь конфиденциальные данные (секретные адрес электронной почты и пароль) из разговора двух пиров — Пола и Ника. Их представляют два виртуальных пользователя, общающиеся через секретные чаты в Telegram.¶

Пол и Ник используют клиенты, выполняющие все проверки из рекомендаций по безопасности Telegram и сравнивающие визуализации ключей по независимому каналу сразу после создания нового секретного чата. Если какая-либо из этих проверок не пройдена, они перестают принимать сообщения в этом секретном чате. Весь процесс контролируется отправкой команд пользователю Telegram @CryptoContest, который служит интерфейсом этого конкурса. Это позволяет участникам пробовать CPA, KPA, MITM и другие виды активных атак и подмены данных.¶

Протокол #

Протокол, используемый Полом и Ником для создания секретных чатов и обмена сообщениями, идентичен протоколу секретных чатов в Telegram. Поскольку предполагается, что атакующий уже полностью контролирует серверы Telegram, базовое шифрование MTProto полностью исключено. Для дальнейшего упрощения задачи участников несущественные параметры, такие как user_id и random_id, были удалены.¶

Для создания секретных чатов в этом конкурсе используется следующая схема TL:¶

contest.dhConfig#01e00a51 g:int p:64*[int] random:64*[int] = contest.DhConfig;
contest.requestEncryption#3a73a74c g_a:64*[int] = contest.Message;
contest.acceptEncryption#068e4342 g_b:64*[int] fingerprint:int = contest.Message;
contest.encryptedMessage#11a6d4b1 id:long message:string = contest.Message;
---functions---
contest.getDhConfig#369ee1a6 = contest.DhConfig;

Для обмена зашифрованными сообщениями (см. документацию) используется актуальная схема слоя 17 с номерами последовательности, но поддерживаются только текстовые сообщения.¶

Каждое сообщение в открытом виде сначала создаётся как decryptedMessage слоя 17, затем вкладывается в decryptedMessageLayer и шифруется, как описано в документации по секретным чатам. Для этого конкурса между сторонами передаётся результат такого шифрования — (шифротекст).¶

Обратите внимание: отправка сообщений в настоящем секретном чате Telegram предполагает дальнейшее вложение этого шифротекста в API-вызов и дополнительный уровень шифрования MTProto для взаимодействия клиента и сервера. Этот шаг здесь опущен, поскольку предполагается, что атакующий контролирует серверы Telegram, а не только линии связи между клиентами и серверами Telegram.¶

Интерфейс #

Чтобы получить доступ к интерфейсу, найдите пользователя Telegram @CryptoContest через глобальный поиск по имени пользователя в любом из приложений Telegram. Это специальный бот, созданный для этого конкурса. Управлять обменом данными между Полом и Ником можно, отправляя этому боту специально сформированные текстовые сообщения и автоматически обрабатывая сгенерированные ответы на них (для массовых автоматизированных запросов может быть удобен неофициальный Linux CLI).¶

С помощью бота можно создать сколько угодно параллельных секретных чатов между Полом и Ником — у каждого будет отдельный session_id. Все данные представлены в шестнадцатеричном формате, кроме session_id.¶

Команды #

Далее A обозначает создателя секретного чата, B — вторую сторону, S — сервер Telegram.¶

Каждый сеанс секретного чата в этом конкурсе разделён на две фазы:¶

  • Создание секретного чата
  • Отправка зашифрованного сообщения
1. Создание секретного чата #

Чтобы создать новый секретный чат, необходимо обменяться шестью сообщениями:¶

ИсточникНазначениеMessage
AScontest.getDhConfig
SAcontest.DhConfig
ABcontest.requestEncryption
BScontest.getDhConfig
SBcontest.DhConfig
BAcontest.acceptEncryption

Чтобы создать секретный чат в этом конкурсе:¶

  • Отправьте команду START пользователю @CryptoContest в Telegram. Вы получите запрос getDhConfig, отправленный A серверу, и ответ, который сервер обычно отправил бы A. Также первым 32-битным целым числом будет получен новый session_id. Все последующие сообщения, относящиеся к этому конкретному сеансу (экземпляру секретного чата), должны начинаться с этого session_id в десятичной форме.
  • Затем используйте команду PASS, чтобы передать ответ сервера A, или ANSWER bytes, чтобы вместо этого отправить иной ответ. Bytes представляется строкой из чётного числа шестнадцатеричных цифр. В результате будет получен запрос requestEncryption.
  • Затем используйте команду PASS, чтобы передать этот запрос B, или ANSWER bytes, чтобы произвольно изменить его. В результате будет получен запрос B к серверу getDhConfig.
  • Как и ранее, можно использовать PASS или ANSWER bytes. В результате будет получен acceptEncryption.
  • Как и ранее, можно использовать PASS или ANSWER bytes. В результате будет получено «Ok».

После любого из этих шагов может быть получен текст ошибки, если участвующие клиенты обнаружат, что что-то пошло не так. Это может произойти, если не пройдена проверка безопасности, или если после завершения этой стадии первые 128 бит SHA-1 вновь созданного ключа шифрования не совпадают у клиентов обеих сторон (это соответствует сравнению Полом и Ником визуализаций ключа секретного чата в их приложениях Telegram).¶

Если получена такая ошибка, сеанс завершился неудачей и больше не может использоваться. Придётся начать новый сеанс. Учтите, что время на завершение этой фазы ограничено: каждый шаг не должен занимать более одного часа, иначе секретный чат будет отменён.¶

2. Отправка текстовых сообщений #

После создания секретного чата можно использовать следующие запросы, чтобы Пол и Ник обменивались текстовыми сообщениями внутри секретного чата:¶

  • ASK [A|B] — просит A или B отправить другой стороне случайное сообщение в открытом виде. Гарантируется, что хотя бы одно из первых десяти сгенерированных сообщений будет содержать секретные адрес электронной почты и пароль, являющиеся целью этого конкурса. Также гарантируется, что помимо этого все сообщения содержат только английские слова из словаря, пробелы, переводы строк и знаки препинания. Результат этого запроса — шифротекст, соответствующий случайно сгенерированному открытому тексту.
  • TXT [A|B] bytes — просит A или B зашифровать bytes как содержимое текстового сообщения (в открытом виде) и отправить его другой стороне. Обратите внимание: bytes может быть любой последовательностью байтов, необязательно допустимой последовательностью UTF-8. Результат этого запроса — шифротекст, соответствующий заданному открытому тексту.
  • MSG [A|B] bytes — отправляет указанное сообщение (шифротекст) (например, полученное в ответ на запрос ASK или TXT) A или B. Если сообщение успешно расшифровано и принято клиентом, будет получено «Ok», иначе — «Fail».

Цели #

Первому человеку, который взломает в этом конкурсе протокол шифрования Telegram, предлагается награда $300,000.¶

Ваша цель — извлечь секретный адрес электронной почты из одного из случайных сообщений, которыми обмениваются Ник и Пол при использовании команды ASK. Гарантируется, что секретный адрес будет содержаться хотя бы в одном из первых десяти сообщений, сгенерированных в рамках сеанса. Также гарантируется, что помимо этого все сообщения содержат только английские слова из словаря, пробелы, переводы строк и знаки препинания.¶

Получив адрес, необходимо отправить на него электронное письмо. Оно должно содержать:
- Полный текст сообщения, содержавшего секретный адрес электронной почты.
- Журналы сеанса успешной попытки с вашим user_id.
- Подробное описание атаки на протокол.
- Реквизиты банковского счёта для получения приза $300,000.¶

Расшифровка сообщений #

Чтобы подтвердить честность конкурса, в конце конкурса будет добавлена команда, которая по session_id возвращает ключи, использованные для определённого сеанса. Это будет сделано сразу после объявления победителя либо 4 февраля 2015 года, если к этой дате победитель объявлен не будет.¶

Дополнительная цель #

Также предлагается независимая награда $100,000 первому человеку, который заставит бота принять сообщение-шифротекст (то есть первому, кто отправит сообщение с помощью MSG [A|B] bytes и получит результат «OK»), при условии, что этот шифротекст расшифровывается в открытый текст, который никогда ранее не шифровался самим ботом в рамках этого сеанса.¶

Если это удастся, отправьте электронное письмо на security@telegram.org, включив следующее:
- Журналы сеанса успешной попытки с вашим user_id.
- Подробное описание атаки на протокол.
- Реквизиты банковского счёта для получения приза $100,000.¶
