Настройки приватности #

Telegram позволяет пользователям задавать детальные настройки приватности, выбирая, кто может и кто не может взаимодействовать с ними тем или иным образом.¶

Правила приватности определяют, кому разрешено или запрещено то или иное действие, и задаются типом PrivacyRule (правило приватности — описание круга пользователей, которым доступ разрешается или запрещается) и его входным аналогом InputPrivacyRule.
Конструкторы InputPrivacyRule передаются на вход методам, принимающим правила приватности, а конструкторы PrivacyRule содержатся в конструкторах, возвращаемых API.¶

Полный список правил приватности и их описания приведены на странице типа ».¶

Отдельно стоит упомянуть одно правило приватности — (input)privacyValueAllowCloseFriends: оно применимо только при публикации историй и относится исключительно к списку «близких друзей», который можно изменить методом contacts.editCloseFriends, передав полный список близких друзей в виде списка идентификаторов пользователей; учтите, что в список близких друзей можно добавить только тех, кто есть в списке контактов (даже без номера телефона) ».¶

Текущий список близких друзей определяется по тому, у каких пользователей из нашего списка контактов установлен флаг close_friend в соответствующем конструкторе user; о том, как получить список контактов, см. здесь ».¶

Ключи приватности вместе с правилами приватности » определяют, что именно кто-либо может или не может делать, и задаются конструктором PrivacyKey (ключ приватности — обозначение конкретного вида взаимодействия, для которого настраивается доступ) и его входным аналогом InputPrivacyKey.
Конструкторы InputPrivacyKey передаются на вход методам, принимающим ключи приватности, тогда как конструкторы PrivacyKey содержатся в конструкторах, возвращаемых API.¶

Полный список ключей приватности и их описания приведены на странице типа ».¶

Чтобы получить текущий набор правил, связанных с ключом, используйте account.getPrivacy, а чтобы изменить его — account.setPrivacy.¶

Изменение настроек приватности вызывает updatePrivacy, которое отправляется во все сессии, где сейчас выполнен вход в текущий аккаунт.¶

users.getRequirementsToContact#d89a83a3 id:Vector<InputUser> = Vector<RequirementToContact>;

Если пользователь включает у себя глобальную настройку приватности globalPrivacySettings.new_noncontact_peers_require_premium, которая для остальных пользователей отражается в поле user.contact_require_premium, писать ему в личные сообщения смогут только те, у кого есть премиум-аккаунт, кто состоит у него в списке контактов или у кого уже есть с ним личный чат; в остальных случаях сервер вернёт ошибку 403 PRIVACY_PREMIUM_REQUIRED.¶

Учтите, что все перечисленные выше дополнительные условия нужно проверять отдельно, чтобы понять, можем ли мы всё-таки написать пользователю, даже если у него установлен флаг user.contact_require_premium (так, у взаимного контакта этот флаг тоже будет установлен, хотя писать ему по-прежнему можно, и тому подобное); чтобы избежать этих дополнительных проверок, когда вся необходимая информация ещё не закеширована (скажем, при показе списка чатов в окне пересылки), можно вместо этого вызвать метод users.getRequirementsToContact, передав ему список пользователей, видимых в интерфейсе в данный момент: он вернёт список условий (в том числе requirementToContactPremium), прямо указывающих, можем мы написать каждому из этих пользователей или нет.
Как вариант, флаг userFull.contact_require_premium содержит ту же самую информацию, что возвращает users.getRequirementsToContact (уже полностью проверенную, то есть это не просто копия user.contact_require_premium).¶

Эту информацию можно затем использовать, например, чтобы показывать значок замка рядом с аватаром каждого пользователя, которому мы не можем написать, вместе с подсказкой, предлагающей оформить подписку Premium.¶

Учтите, что users.getRequirementsToContact следует вызывать только в том случае, если у нас нет подписки Premium, и только для тех пользователей, чья полная информация (userFull плюс сведения об истории сообщений) ещё не закеширована: если все упомянутые данные есть, то же самое вычисляется локально, а поддерживается в актуальном состоянии автоматически — обычными обновлениями.¶

Учтите также, что настройку globalPrivacySettings.new_noncontact_peers_require_premium могут включать как пользователи без Premium, так и пользователи с Premium, но лишь при условии, что флаг клиентской конфигурации new_noncontact_peers_require_premium_without_ownpremium » равен true; в противном случае включить её могут только пользователи с Premium, а пользователи без Premium при попытке выставить этот флаг через account.setGlobalPrivacySettings получат ошибку PREMIUM_ACCOUNT_REQUIRED.¶
