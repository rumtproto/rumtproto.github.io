Веб-события #

При работе с HTML5-играми, сайтами платёжных шлюзов и Mini App ботов (Mini App — веб-приложение, открываемое прямо внутри клиента Telegram) приложения Telegram должны предоставлять API, позволяющие получать данные и события от этих сайтов.¶

API событий #

Игры, платёжные шлюзы и мини-приложения ботов могут генерировать события, предназначенные для получения приложениями Telegram. Обычно события создаются с помощью метода postEvent библиотеки GamingCommunication или библиотеки мини-приложений ботов.
Функция postEvent попытается отправить событие в приложение Telegram несколькими способами.¶

WebviewProxy #

В мобильных приложениях API приёма событий обычно предоставляется в виде объекта window.TelegramWebviewProxy с методом postEvent.¶

window.TelegramWebviewProxy.postEvent(eventType, eventData)

window.external #

В качестве альтернативы может предоставляться метод window.external.notify, принимающий строку с JSON, в которой указаны тип события и его полезная нагрузка:¶

window.external.notify(JSON.stringify({eventType: eventType, eventData: eventData}));

postMessage API #

Наконец, веб-клиенты MTProto, которым нужно открыть игру, открыть Mini App бота или провести платёж в iframe, могут использовать postMessage API для получения событий из iframe.
Библиотеки GamingCommunication и Mini App для ботов по умолчанию используют '*' в качестве targetOrigin, то есть отправляют сообщения родительским страницам независимо от источника встраивающей страницы.¶

window.parent.postMessage(JSON.stringify({eventType: eventType, eventData: eventData}), targetOrigin);

Типы событий #

eventType — простая строка, указывающая тип события, а eventData — полезная нагрузка в виде объекта, который будет разобран приложением Telegram.¶

payment_form_submit #

Полезная нагрузка события: JSON-объект с полями credentials и title.¶

  • title — замаскированное название банковской карты.
  • credentials — специфичный для сервиса JSON-объект со сведениями о платёжных реквизитах, которые пользователь передал платёжной системе.

Ни Telegram, ни боты не получат доступ к данным вашей банковской карты.
Реквизиты карты обрабатываются исключительно платёжной системой, см. документацию по платежам, подробнее ».¶

share_score #

Полезной нагрузки нет.¶

Вызывается играми, когда пользователь явно нажимает кнопку поделиться результатом, чтобы поделиться игрой вместе со своим результатом.
Обычно это делается вызовом messages.forwardMessages для сообщения с игрой с установленным флагом with_my_score.¶

share_game #

Полезной нагрузки нет.¶

Вызывается играми, когда пользователь явно нажимает кнопку поделиться игрой, чтобы поделиться игрой без своего результата.
Обычно это делается вызовом messages.forwardMessages для сообщения с игрой без флага with_my_score либо отправкой глубокой ссылки на игру (deep link — ссылка вида tg://… или https://t.me/…, открывающая нужный экран приложения).¶

web_app_close #

Полезной нагрузки нет либо передаётся JSON-объект со следующими полями (клиент должен их корректно проверить).¶

  • return_back — если поле истинно, а веб-приложение было открыто по глубокой ссылке из другого приложения (то есть не по глубокой ссылке внутри клиента Telegram), клиенту Telegram следует вернуться в приложение, которое открыло ссылку, а не на главный экран клиента Telegram. (логическое значение, необязательное)

Порождается Mini App ботов, когда webview (встроенное окно браузера, в котором открыт Mini App) следует закрыть.¶

web_app_open_popup #

Данные события: JSON-объект со следующими полями (клиент обязан их корректно проверить).¶

  • title — заголовок всплывающего окна (строка, необязательное, не более 64 символов)
  • message — текст всплывающего окна (строка, не более 256 символов)
  • buttons — массив объектов следующего вида (массив из 1–3 объектов)
    • type — тип кнопки (строка, одно из значений ok, close, cancel, default, destructive (в этом случае кнопка должна быть красной))
    • text — текст кнопки (строка, необязательное для типов ok, close и cancel)
    • id — идентификатор кнопки (уникальная строка)

Порождается Mini App ботов, чтобы открыть поверх webview всплывающее окно средствами системы.¶

По умолчанию кнопки следует размещать в один ряд.
Если Mini App передаёт две кнопки, которые не помещаются по горизонтали в один ряд, каждую кнопку следует вывести в отдельном ряду.
Если Mini App передаёт три кнопки, каждую кнопку всегда следует выводить в отдельном ряду.¶

  • Если пользователь нажимает любую из кнопок, вызовите window.Telegram.WebView.receiveEvent("popup_closed", {"button_id": "<button id>"})
  • Если пользователь прерывает взаимодействие, не нажав ни одну из заданных кнопок, вызовите window.Telegram.WebView.receiveEvent("popup_closed", {})

Отключите обработку этого события, пока всплывающее окно уже показано, и включите её снова только после того, как будет отправлено ответное событие popup_closed.
Пока обработка включена, допускается обработать не более 3 подряд идущих корректных событий этого типа за 3 секунды; лишние события игнорируются.¶

web_app_request_write_access #

Данные события: null¶

Порождается Mini App ботов, чтобы запросить у пользователя разрешение отправлять ему сообщения.¶

Получив это событие, клиенту следует сначала вызвать bots.canSendMessage и проверить, не выдал ли пользователь боту разрешение писать ему тем или иным способом ранее.¶

  • Если метод возвращает boolTrue, в Mini App следует отправить событие write_access_requested » со значением {"status": "allowed"}.
  • Иначе, если метод возвращает boolFalse, пользователю следует показать запрос с сообщением о том, что бот просит разрешение отправлять ему сообщения.
    Если пользователь соглашается, вызовите bots.allowSendMessage, и при успешном вызове метода отправьте событие write_access_requested » со значением {"status": "allowed"}.
    Иначе, если пользователь отказывается или вызов bots.allowSendMessage завершается ошибкой, отправьте событие write_access_requested » со значением {"status": "cancelled"}.

web_app_request_phone #

Данные события: null¶

Порождается Mini App ботов, чтобы попросить пользователя поделиться своим номером телефона в виде контакта.¶

Получив это событие, клиент должен показать пользователю запрос с сообщением о том, что бот просит его поделиться номером телефона (при необходимости — также с предложением разблокировать бота, если тот сейчас заблокирован).¶

Если пользователь соглашается, его номер телефона передаётся отправкой боту контакта (предварительно бота следует разблокировать, если пользователь его заблокировал); если все RPC-запросы (на разблокировку бота и на отправку сообщения) выполнены успешно, следует отправить событие phone_requested » со значением {"status": "sent"}.¶

Если пользователь отказывается или любой из промежуточных вызовов метода завершается ошибкой, следует отправить событие phone_requested » со значением {"status": "cancelled"}.¶

Обе ссылки на событие phone_requested ведут на якорь #write-access-requested — это ошибка в оригинале, сохранённая здесь дословно. Описание самого события phone_requested следует искать в документации по Mini App отдельно.¶

web_app_biometry_get_info #

Данные события: null¶

Порождается Mini App ботов, чтобы клиент инициализировал объект менеджера биометрической аутентификации для текущего бота; по завершении порождается событие biometry_info_received ».¶

Этот запрос должен лишь инициализировать состояние на стороне клиента, то есть проверить, доступна ли биометрическая аутентификация в принципе; ничего спрашивать у пользователя он не должен.¶

web_app_biometry_request_access #

Данные события: JSON-объект с необязательным строковым полем reason (1–128 символов, используется в запросе), содержащим причину, по которой бот просит разрешение на биометрическую аутентификацию.¶

Порождается Mini App ботов, чтобы запросить у пользователя разрешение на использование биометрической аутентификации; по завершении порождается событие biometry_info_received ».¶

Этот запрос не должен запускать саму биометрическую аутентификацию — он должен лишь запросить у пользователя разрешение на её использование через всплывающее окно, которое показывается только один раз (для данного бота): окно не должно показываться, если пользователь ранее уже разрешил, отклонил или отменил запрос разрешения на биометрию от этого бота.¶

web_app_biometry_update_token #

Данные события: JSON-объект со следующими полями:¶

  • token — новый токен (строка, 0–1024 символа) либо пустая строка для его удаления.
  • reason — необязательное строковое поле, содержащее причину, по которой бот просит выполнить аутентификацию с помощью биометрии (1–128 символов, используется в запросе).

Порождается Mini App ботов, чтобы выполнить аутентификацию по биометрии и надёжно сохранить биометрический токен на устройстве; по завершении порождается событие biometry_token_updated ».¶

Этот токен (им может быть, например, закрытый ключ криптовалютного кошелька или иные данные, которые приложению нужно держать в безопасности) обязан надёжно храниться клиентом Telegram и быть привязан к боту, которому принадлежит Mini App.¶

Например, токен может храниться непосредственно в защищённом хранилище устройства и быть доступным только после биометрической аутентификации, либо он может храниться в обычном, незащищённом хранилище, но в зашифрованном виде — зашифрованным на ключе, который возвращает защищённое хранилище устройства после биометрической аутентификации (например, на Android — с помощью объекта CryptoObject, возвращаемого в результате биометрического запроса).¶

Если пользователь ранее запретил боту использовать биометрическую аутентификацию, этот запрос должен немедленно завершиться неудачей с порождением соответствующего события biometry_token_updated ».¶

web_app_biometry_request_auth #

Данные события: JSON-объект с необязательным строковым полем reason, содержащим причину, по которой бот просит выполнить аутентификацию с помощью биометрии (1–128 символов, используется в запросе).¶

Порождается Mini App ботов, чтобы выполнить аутентификацию с помощью биометрии и получить ранее сохранённый защищённый токен; по завершении порождается событие biometry_auth_requested », содержащее либо ошибку, либо расшифрованный биометрический токен » (либо пустую строку, если токен ещё не задан).¶

Использовать это событие следует, только если поле token_saved объекта biometry_info_received » равно true; в противном случае сначала задайте новый токен с помощью web_app_biometry_update_token ».¶

Если пользователь ранее запретил боту использовать биометрическую аутентификацию, этот запрос должен немедленно завершиться неудачей с порождением соответствующего события biometry_auth_requested ».¶

web_app_biometry_open_settings #

Данные события: null¶

Порождается Mini App ботов, чтобы открыть страницу настроек биометрической аутентификации для ботов; это полезно, когда приложению нужно запросить разрешение на использование биометрии у пользователей, которые ранее в нём отказали.¶

Обратите внимание: это событие следует обрабатывать только в ответ на действие пользователя в интерфейсе Mini App (например, нажатие внутри Mini App или на главную кнопку), и обрабатываться оно должно не чаще одного раза в секунду.¶

web_app_invoke_custom_method #

Данные события: JSON-объект со следующими полями:¶

  • req_id — строка с идентификатором текущего запроса
  • method — строка с именем вызываемого пользовательского метода
  • params — объект с параметрами вызова метода

Порождается Mini App ботов для вызова пользовательских методов на серверах Telegram от имени пользователя.¶

Это событие должно приводить к запросу bots.invokeWebViewCustomMethod, в котором method передаётся в custom_method, а params — в params.¶

При получении ответа должно порождаться событие custom_method_invoked » со следующими полями:¶

  • req_id — значение req_id из объекта web_app_invoke_custom_method
  • result — JSON-данные из ответа метода bots.invokeWebViewCustomMethod, если вызов метода прошёл успешно
  • error — текст ошибки RPC, если вызов метода завершился неудачей

web_app_read_text_from_clipboard #

Данные события: JSON-объект со следующими полями:¶

  • req_id — строка с идентификатором текущего запроса

Порождается Mini App ботов для получения содержимого системного буфера обмена.¶

Только для Mini App, принадлежащих ботам, которые добавлены в меню вложений или перечислены в параметре конфигурации whitelisted_bots » — независимо от того, каким образом был запущен сам Mini App, — это событие должно приводить к порождению события clipboard_text_received » со следующими данными:¶

  • req_id — значение req_id из запроса web_app_read_text_from_clipboard
  • data — строка с содержимым буфера обмена

Обратите внимание: этот метод может вызываться только в ответ на действие пользователя в интерфейсе Mini App (например, нажатие внутри Mini App либо на главную кнопку или кнопку настроек).
Учтите, что у действий пользователя есть срок жизни в 10 секунд: если последнее действие пользователя в Mini App (как описано выше) произошло более 10 секунд назад, события этого типа обязательно игнорировать и отправить событие clipboard_text_received » с правильным req_id и без поля data.¶

web_app_request_file_download #

Данные события: JSON-объект со строковыми полями url и file_name.¶

Используется веб-приложениями ботов, чтобы запросить скачивание файла.¶

Это событие обрабатывается по следующим шагам:¶

  1. Вызвать bots.checkDownloadFileParams, передав url, file_name и идентификатор бота.
    Последующие события web_app_request_file_download игнорируются, пока не будет достигнут шаг 3 (новое событие web_app_request_file_download может быть принято, пока предыдущий файл ещё скачивается).
    1.1) Если метод не вернул boolTrue, следует породить событие file_download_requested со статусом cancelled и прервать процедуру.
  2. Если вернулся boolTrue, показать пользователю запрос с уведомлением о том, что $nameOfTheBot просит разрешения скачать файл с именем file_name.
    2.1) Если пользователь отказывается скачивать файл, следует породить событие file_download_requested со статусом cancelled и прервать процедуру.
  3. Если пользователь соглашается, начать скачивание файла по адресу url под именем file_name и породить событие file_download_requested со статусом downloading.
  4. По завершении скачивания показать пользователю всплывающее уведомление о том, что файл успешно скачан.

Независимо от содержимого события клиент должен немедленно ответить событием oauth_supported » со значением version, равным 1.¶

web_app_request_chat #

Полезная нагрузка события: JSON-объект со следующими ключами:¶

  • req_id — строка, значение bots.requestedButton.webapp_req_id, полученное ботом из bots.requestWebViewButton

Используется приложениями Mini App, чтобы попросить клиент выполнить запрос пира, подготовленный ботом.¶

Клиенты обязаны вызвать bots.getRequestedWebViewButton, передав бота данного Mini App и значение req_id в качестве bots.getRequestedWebViewButton.webapp_req_id.¶

Метод bots.getRequestedWebViewButton вернёт keyboardButtonRequestPeer, который клиенты обязаны обработать так, как описано в разделе запрос пиров через Mini Apps.¶

При успехе порождает событие requested_chat_sent.
При неудаче или отмене порождает событие requested_chat_failed.¶
