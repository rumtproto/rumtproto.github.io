API платежей #

Вы можете принимать платежи от пользователей Telegram через Telegram Bots.¶

Примечание. Эта статья предназначена для разработчиков API MTProto. Если вы ищете общий обзор платежей Telegram, посетите блог Telegram и руководство по платежам API-бота.¶

Знакомство с платежами #

Боты Telegram могут принимать оплату за товары и услуги от пользователей. Для получения дополнительной информации о том, как работают платежи, посетите Блог Telegram и Руководство по платежам API-бота.¶

На этой странице подробно разбираются действия, необходимые для работы с платежами через MTProto API.¶

Упрощенная версия процесса доступна только для ботов, использующих bot API.¶

Первый шаг для ботов — включить платежи, как описано здесь ».¶

Далее работа с платежами выглядит следующим образом.¶

Пользователь связывается с ботом и просит что-то купить. Бот формирует inputMediaInvoice с конструктором invoice с описанием товара или услуги, суммой к оплате, а также запрошенной информацией о доставке. Параметр provider конструктора inputMediaInvoice — это место, куда вы помещаете значение токена, которое вы получили ранее через Botfather. Один торговый бот может использовать несколько разных токенов для разных пользователей или р��зных товаров и услуг.¶

Для отправки счёта invoice используйте метод messages.sendMedia. К сообщению можно также прикрепить инлайн-клавиатуру через поле reply_markup: если оно передано, первой кнопкой обязана быть кнопка keyboardButtonBuy. Иначе инлайн-клавиатура будет создана автоматически, и единственной её кнопкой станет keyboardButtonBuy с надписью Pay 'total price'.¶

Сообщение со счётом и кнопкой оплаты можно отправить только в личный чат с пользователем. Группы и каналы не поддерживаются.¶

---functions---

payments.exportInvoice#0f91b065 invoice_media:InputMedia = payments.ExportedInvoice;

Боты могут также создавать глубокие ссылки на счёт (deep link — ссылка, которая открывается непосредственно в приложении Telegram) с помощью метода payments.exportInvoice.¶

Возвращаемый конструктор payments.exportedInvoice содержит глубокую ссылку на счёт, которой можно поделиться напрямую или отправить её в Mini App бота (встроенное веб-приложение внутри Telegram) событием web_app_open_invoice.¶

Метод payments.getPaymentForm возвращает платёжную форму по счёту; в параметре invoice передаётся одно из следующих значений:¶

  • inputInvoiceMessage — используется:
    • Если пользователь нажимает кнопку keyboardButtonBuy; содержит ID сообщения с предпросмотром счёта.
    • При покупке платного медиа ».
  • inputInvoiceSlug
    • Если пользователь открывает глубокую ссылку на счёт, содержит параметр slug
    • Если клиенту нужно обработать платёж за Telegram Premium, содержит параметр конфигурации приложения premium_invoice_slug »
  • inputInvoicePremiumGiftCode
    • Используется, если пользователь хочет запустить розыгрыш в канале или отправить подарочные коды участникам канала в обмен на бусты.
      Поле purpose следует заполнить конструктором inputStorePaymentPremiumGiveaway для розыгрышей и inputStorePaymentPremiumGiftCode для подарков.
      Поле option следует заполнить одним из вариантов розыгрыша, возвращаемых методом payments.getPremiumGiftCodeOptions.
      Подробнее см. документацию по розыгрышам ».
  • inputInvoiceStars
    • Используется для покупки Telegram Stars. Поле option следует заполнить одним из вариантов пополнения баланса звёзд, возвращаемых методом payments.getStarsTopupOptions.
      Подробнее см. документацию по звёздам ».
  • inputInvoiceChatInviteSubscription
    • Используется для реализации подписок » на ботов и каналы.
      Подробнее см. документацию по подпискам ».
  • inputInvoiceStarGift
    • Используется для покупки подарков за Telegram Stars.
      Подробнее см. документацию по подаркам ».
  • inputInvoiceStarGiftUpgrade
    • Используется, чтобы оплатить превращение подарка в коллекционный.
      Подробнее см. документацию по коллекционным подаркам ».
  • inputInvoiceStarGiftPrepaidUpgrade
    • Используется, чтобы оплатить за другого пользователя превращение подарка в коллекционный.
      Подробнее см. документацию по коллекционным подаркам ».
  • inputInvoiceStarGiftTransfer
    • Используется, чтобы оплатить передачу подарка другому пиру.
      Подробнее см. документацию по подаркам ».
  • inputInvoiceStarGiftResale
    • Используется, чтобы купить подарок при перепродаже.
      Подробнее см. документацию по подаркам ».
  • inputInvoicePremiumGiftStars
    • Используется, чтобы подарить другому пользователю подписку Premium с оплатой в Telegram Stars.
      Подробнее см. документацию по Telegram Premium »
  • inputInvoiceBusinessBotTransferStars
    • Используется, чтобы перевести Telegram Stars с баланса пользователя, управляемого бизнес-ботом, на баланс самого бота.
      Подробнее см. документацию по Telegram Business ».

Возвращённая форма содержит поля, которые следует передать платёжному провайдеру вместе с полным счётом. Кроме того, платёжная форма содержит сведения о ранее сохранённых платёжных данных и об информации о заказе (имя, номер телефона, адрес электронной почты, адрес доставки и так далее).¶

Полный счёт содержит сведения о том, какие данные требуются для оформления заказа, о цене и валюте, а также о том, тестовый ли это заказ (test). У регулярных платежей установлен флаг recurring, а поле recurring_terms_url ведёт на условия обслуживания такого платежа: пользователь обязан прочитать и принять их, прежде чем продолжить.¶

Если платёж проводится в Telegram Stars (подробнее здесь »), возвращается payments.paymentFormStars/payments.paymentFormStarGift (учтите: этот конструктор используется для платежей в Telegram Stars в адрес ботов и пиров и не возвращается при пополнении баланса Telegram Stars текущего аккаунта через inputInvoiceStars): в связанном счёте в поле currency будет указано XTR.¶

Если счёт запрашивает хоть какие-то данные (name_requested, phone_requested, email_requested, shipping_address_requested), пользователь обязан вызвать payments.validateRequestedInfo, передав требуемые данные (как обычно, msg_id — идентификатор сообщения со счётом). Пользователь может сохранить информацию о заказе для дальнейшего использования, установив флаг save. Данные могут подставляться автоматически, как описано в разделе автозаполнение.¶

Если в отправленных сведениях не найдено ошибок, ответ метода будет содержать флаг id, который понадобится позже для завершения платежа.¶

Если у счёта установлен флаг flexible, вызов метода payments.validateRequestedInfo отправит боту обновление с запросом доставки, на которое бот ответит доступными вариантами доставки для указанного адреса, как описано здесь ». Возможные ошибки возвращаются в виде RPC-ошибок (rpc_error), а описание ошибки от бота приходит отдельно, в дополнительных сервисных обновлениях; подробности см. здесь.¶

Учтите, что ошибки платежа не будут доставлены клиенту по MTProto, если они возникают на этапе дополнительной проверки (когда возвращён payments.paymentVerificationNeeded, а пользователь не прошёл проверку TOTP): такие ошибки отображаются только внутри веб-представления проверки, никаких обновлений MTProto или RPC-ошибок (rpc_error) клиент не получит.¶
