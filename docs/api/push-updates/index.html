Обработка PUSH-уведомлений #

Настройка приложения #

Чтобы приложение могло отправлять APNS-уведомления на серверы Apple или GCM-уведомления на серверы Google, в настройках приложения необходимо указать сертификаты приложения (APNS) либо ключ приложения (GCM).¶

Подписка на уведомления #

Чтобы подписаться на уведомления, клиент должен вызвать метод account.registerDevice, передав в качестве параметров token_type (token_type — числовой код службы push-уведомлений) и token (выданный ею идентификатор), которые идентифицируют текущее устройство. Этот запрос полезно повторять не реже одного раза в 24 часа, а также при каждом перезапуске приложения. Для отписки используется account.unregisterDevice.¶

Поддерживаются следующие значения token_type:¶

  • 1 — APNS (токен устройства для apple push)
  • 2 — FCM (токен firebase для google firebase)
  • 3 — MPNS (URI канала для microsoft push)
  • 4 — Simple push (адрес (endpoint) для устаревшего simple push API от firefox): обратите внимание, что этот тип push-уведомлений может использоваться и открытой спецификацией push-уведомлений вроде UnifiedPush ».
    Simple push работает так: каждый раз, когда приходит значимое сообщение, на указанный HTTPS-адрес отправляется простой запрос PUT с полезной нагрузкой version=number; получив такое уведомление, клиент должен подключиться к MTProto API и забрать обновления.
    (Учтите, что в реализации Telegram значение number не обязательно возрастает последовательно — просто считайте каждый отдельный запрос сигналом о том, что появилось новое сообщение, которое нужно получить через MTProto.)
  • 5 — Ubuntu phone (токен для ubuntu push)
  • 6 — Blackberry (токен для blackberry push)
  • 7 — отдельная сессия MTProto
  • 8 — WNS (windows push)
  • 9 — APNS VoIP (токен для apple push VoIP)
  • 10 — Web push (веб-push, см. ниже)
  • 11 — MPNS VoIP (токен для microsoft push VoIP)
  • 12 — Tizen (токен для tizen push)
  • 13 — Huawei push

Для веб-push (10) токен должен быть объектом в формате JSON со следующими ключами:¶

  • endpoint: абсолютный URL, предоставляемый службой push-уведомлений, по которому сервер приложения может отправлять push-сообщения
  • keys: параметры протокола Диффи — Хеллмана на эллиптической кривой P-256 в виде следующего объекта
    • p256dh: открытый ключ Диффи — Хеллмана на эллиптической кривой P-256 в кодировке base64url
    • auth: секрет аутентификации в кодировке base64url

Шифрование уведомлений #

Для FCM и APNS VoIP в метод account.registerDevice можно передать необязательный ключ шифрования (secret), которым будут зашифрованы push-уведомления. Этот ключ (auth_key — авторизационный ключ, общий секрет, на котором строится шифрование) используется для шифрования полезной нагрузки по правилам MTProto v2.¶

Полезная нагрузка FCM представляет собой JSON, содержащий поле p с зашифрованной полезной нагрузкой MTProto в кодировке base64url. После расшифровки получится объект JSON, перед которым идёт 32-битное целое число с порядком байтов little-endian, равное длине этой полезной нагрузки JSON. Как обычно, обязательно выполняйте все проверки безопасности, описанные в документации по MTProto.¶

Пример реализации.¶

Как упоминалось выше, полезную нагрузку можно также шифровать с помощью протокола Диффи — Хеллмана на эллиптической кривой P-256 при использовании веб-push.¶

Структура уведомления #

Уведомление (при необходимости зашифрованное) передаётся как объект JSON следующего вида:¶

{
  "data": {
    "loc_key": "CHAT_MESSAGE_CONTACT",
    "loc_args": ["John Doe", "My magical group", "Contact Exchange"],
    "user_id": 14124122,
    "custom": {
      "chat_id": 241233,
      "msg_id": 123
    },
    "sound": "sound1.mp3",
  }
}

Каждое уведомление описывается несколькими параметрами.¶

  • loc_key — тип уведомления: строковый литерал вида /[A-Z_0-9]+/, кратко описывающий уведомление. Например, CHAT_MESSAGE_TEXT.
  • loc_args — аргументы для подстановки в уведомление: список аргументов, которые при подстановке в шаблон дают читаемый текст уведомления.
  • custom — произвольные параметры, передаваемые в приложение при открытии уведомления. Возможные поля:
    • attachb64 — для уведомлений о медиафайлах: TL-сериализация соответствующего объекта Photo / Document в кодировке base64url
    • updates — TL-сериализация объекта Updates в кодировке base64url; сейчас отправляется только для PHONE_CALL_REQUEST (внутри содержится updatePhoneCall)
    • call_id — идентификатор звонка, используется в PHONE_CALL_REQUEST
    • call_ah — хеш доступа к звонку, используется в PHONE_CALL_REQUEST
    • encryption_id — идентификатор секретного чата для ENCRYPTION_REQUEST, ENCRYPTION_ACCEPT, ENCRYPTED_MESSAGE
    • random_id — случайный идентификатор сообщения в ENCRYPTED_MESSAGE
    • contact_id — идентификатор пользователя Telegram из контактов, который зарегистрировался в Telegram, для CONTACT_JOINED
    • msg_id — идентификатор сообщения для события нового сообщения или события реакции
    • channel_id — идентификатор канала или супергруппы, где произошло событие
    • chat_id — идентификатор обычной группы, где произошло событие
    • from_id — идентификатор пользователя, у которого произошло событие
    • chat_from_broadcast_id — если сообщение в группе было отправлено от имени канала, это поле содержит идентификатор канала-отправителя
    • chat_from_group_id — если сообщение в группе было отправлено от имени супергруппы, это поле содержит идентификатор супергруппы-отправителя
    • chat_from_id — только для групп: идентификатор автора сообщения (игнорируйте, если присутствует chat_from_broadcast_id или chat_from_group_id)
    • mention — было ли в этом новом сообщении упоминание текущего пользователя или ответ ему
    • silent — было ли сообщение отправлено без звука (для такого уведомления звук воспроизводить не следует)
    • schedule — является ли сообщение исходящим и отправленным через отложенные сообщения
    • report_delivery_until_date — если поле задано и текущее время в формате unixtime больше указанного, вызовите messages.reportMessagesDelivery, установив флаг push и передав идентификатор и пир этого сообщения сразу же, как только клиент его получит (запросы для одного и того же пира допускается объединять в пакеты); применяется для проверочных сообщений Telegram Gateway.
    • edit_date — когда сообщение редактировалось в последний раз
    • top_msg_id — thread_id для новых упоминаний и ответов в обсуждениях
    • data_url — полный URL веб-страницы, которая пытается выполнить вход через OAUTH_REQUEST
    • announcement — идентификатор объявления, используется в MESSAGE_ANNOUNCEMENT
  • sound — имя звукового файла, который следует воспроизвести.
  • user_id — идентификатор аккаунта, которому нужно доставить PUSH-уведомление; актуально для клиентов, где одновременно активны несколько аккаунтов.
  • message — необязательный текст уведомления, сейчас используется в MESSAGE_ANNOUNCEMENT

Машиночитаемый список всех типов уведомлений вместе с их шаблонами и аргументами для подстановки также встроен в индекс /api/config.json — под ключами push (шаблоны уведомлений по типам) и push_arguments (списки аргументов для подстановки по типам).¶

Обработка уведомлений #

В принципе, для формирования уведомления достаточно data.loc_key, data.custom и подключения к интернету. Разумеется, при формировании визуального уведомления по возможности не нужно использовать все переданные данные — можно опираться на сведения, которые уже хранятся у клиента. Но если пользователь или чат локально не закешированы, допускается использовать и значения, переданные в loc_args. data.user_id — это идентификатор аккаунта, которому нужно доставить PUSH-уведомление; актуально для клиентов, где одновременно активны несколько аккаунтов.¶

Если передан адрес первого DC (dc=1), рекомендуется сразу же вызвать help.getConfig, чтобы обновить конфигурацию дата-центров.¶

MESSAGE_MUTED #

Описание¶

Присылается редко для чатов с отключёнными уведомлениями — примерно на каждое десятое сообщение в таком чате или примерно раз в 15 секунд в личных переписках, чтобы обновить состояние счётчика непрочитанного либо инициировать получение обновлений с сервера.¶

Этот push не предназначен для показа пользователю в виде видимого уведомления.¶

MESSAGE_ANNOUNCEMENT #

Дополнительные аргументы custom¶

data.custom.announcement — идентификатор объявления (целое число)¶

Дополнительные аргументы верхнего уровня¶

data.message — непустой текст объявления¶

Описание¶

Примерно соответствует сообщению, полученному от служебных уведомлений (updateServiceNotification со значением type="announcement"), но доставляется через push-уведомления, без обращения к API.¶

Текст push-уведомления берётся из data.message.¶

Клиенты могут отсеивать повторяющиеся объявления по идентификатору объявления из data.custom.announcement: например, сохраняя полученные идентификаторы в течение 7 дней и не теряя этот кеш при перезапусках.¶
