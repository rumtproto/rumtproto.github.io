Ошибки

Оригинальное русскоязычное описание того, как сервер сообщает об ошибках и как клиенту на них реагировать. Первоисточник: core.telegram.org/api/errors.

Ошибка метода возвращается вместо результата в rpc_error:

rpc_error#2144ca19 error_code:int error_message:string = RpcError;
  • error_code — числовой код, совместимый по смыслу с HTTP-кодами;
  • error_message — строковый идентификатор вида PHONE_CODE_INVALID, иногда с параметрами: FLOOD_WAIT_12, FILE_MIGRATE_2.

Типовые коды и поведение клиента

Код Примеры Что делать клиенту
303 PHONE_MIGRATE_2, FILE_MIGRATE_5, NETWORK_MIGRATE_1 Переподключиться к дата-центру с номером из суффикса и повторить.
400 PHONE_CODE_INVALID, MESSAGE_EMPTY, PEER_ID_INVALID Ошибка входных данных: исправить и повторить; показывать пользователю осмысленное сообщение.
401 AUTH_KEY_UNREGISTERED, SESSION_EXPIRED, USER_DEACTIVATED Сессия/ключ больше не действительны: заново пройти авторизацию.
403 CHAT_WRITE_FORBIDDEN, USER_PRIVACY_RESTRICTED Операция запрещена правами/настройками; повторять бессмысленно.
406 FRESH_CHANGE_ADMINS_FORBIDDEN и др. Специальные ограничения; см. оригинальный справочник.
420 FLOOD_WAIT_N, SLOWMODE_WAIT_N Пауза: подождать N секунд и повторить.
500 MSG_WAIT_FAILED, RPC_CALL_FAIL Временный сбой сервера: повторить с экспоненциальной задержкой.

Практика обработки

  1. Разбирайте error_message как ИМЯ[_ПАРАМЕТР] — числовые суффиксы (номер дата-центра, секунды) важны для логики.
  2. Паузы из FLOOD_WAIT выдерживайте всегда: агрессивные повторы приводят к более длинным блокировкам.
  3. Ошибки миграции (303) обрабатывайте автоматически и прозрачно для пользователя.
  4. Неизвестные коды логируйте и повторяйте только 5xx-подобные.
  5. Полный актуальный перечень кодов — в оригинальном справочнике: он пополняется вместе с развитием API.
