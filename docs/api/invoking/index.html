Вызов методов

Оригинальное русскоязычное описание правил вызова методов схемы. Первоисточник: core.telegram.org/api/invoking.

Метод схемы — это RPC-запрос: клиент сериализует конструктор метода и отправляет его как тело зашифрованного сообщения (формат); сервер отвечает результатом через rpc_result или ошибкой rpc_error.

Слои (layers)

Схема версионируется слоями: каждый клиент сообщает серверу, какую версию схемы он понимает.

  • Первый запрос авторизованной сессии оборачивается в цепочку: invokeWithLayer (номер актуального слоя) → initConnection (параметры приложения и устройства) → сам запрос.
  • Пока клиент не сообщил слой, сервер отвечает схемой минимальной совместимости.
  • История изменений схемы по слоям — на странице Слои схемы.

Повторные вызовы и идемпотентность

  • Методы с побочными эффектами (отправка сообщений, платежи и т.п.) принимают random_id — повторный вызов с тем же random_id не создаёт дубликат.
  • Повторно отправлять сам запрос на уровне протокола допустимо (с тем же message_id), если он точно не был доставлен; см. сообщения о сообщениях.

Ограничения и ошибки

  • Флуд-контроль: ошибка FLOOD_WAIT_N — повторить не раньше чем через N секунд. Поведение по типовым кодам — в ошибках.
  • Таймауты: если ответ не приходит разумное время, запросите состояние (msg_resend_req), а не дублируйте запрос с новым идентификатором.
  • Отмена: rpc_drop_answer позволяет отказаться от ожидания ответа (например, для «долгих» запросов при уходе в фон).

Полезные обёртки

  • invokeWithoutUpdates — не присылать обновления, порождённые этим запросом.
  • invokeWithMessagesRange / invokeWithTakeout — вызовы в контексте диапазона сообщений / выгрузки данных.
  • invokeAfterMsg — просить сервер выполнить запрос после указанного (упорядочивание).
