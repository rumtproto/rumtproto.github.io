Введение #

По сути, Telegram Bot API — это программное обеспечение, которое возвращает на запросы ответы в формате JSON.¶

Бот, с другой стороны, — это, по существу, программа, приложение или скрипт, который обращается к API посредством HTTPS-запроса и ожидает ответа. Можно выполнять несколько типов запросов, а также использовать и получать в ответах множество разных объектов.¶

Поскольку браузер умеет отправлять HTTPS-запросы, с его помощью можно быстро опробовать API. После получения токена попробуйте вставить эту строку в адресную строку браузера:¶

https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getMe

Теоретически можно взаимодействовать с API такими простыми запросами через браузер или другие специализированные инструменты, например cURL. Для простых запросов, подобных приведённому выше, это может сработать, но для крупных приложений такой подход непрактичен и плохо масштабируется.
Поэтому это руководство покажет, как с помощью библиотек и фреймворков и базовых навыков программирования создать более надёжный и масштабируемый проект.¶

Если вы умеете программировать, то быстро пройдёте все шаги, а если только начинаете — это руководство покажет всё, что нужно освоить.¶

В этом руководстве будет использоваться Java, один из наиболее популярных языков программирования, однако можно следовать инструкциям с любым языком, поскольку все шаги по сути одинаковы.
Java полностью кроссплатформен, поэтому каждый пример кода будет работать в любой операционной системе.
При выборе другого языка эквивалентные примеры доступны на C#, Python, Go и TypeScript .¶

Подготовка #

Сначала кратко разберём, как создать первый проект, получить токен API и скачать все необходимые зависимости и библиотеки.¶

Для этого руководства также доступна копия создаваемого бота — @TutorialBot. Заглядывайте в неё по ходу работы, чтобы видеть, как должна выглядеть собственная реализация после каждого шага.¶

Получение токена бота #

В этом контексте токен — строка, которая аутентифицирует бота (не учётную запись) в Bot API. У каждого бота есть уникальный токен, который также можно в любой момент отозвать через @BotFather.¶

Получить токен просто: обратитесь к @BotFather, отправьте команду /newbot и выполните шаги, пока не получите новый токен. Пошаговое руководство доступно здесь.¶

Токен будет выглядеть примерно так:¶

4839574812:AAFD39kkdpWt3ywyRZergyOLMaJhac60qc

Обязательно сохраните токен в безопасном месте, обращайтесь с ним как с паролем и никому его не сообщайте.¶

Скачивание IDE #

Для программирования на Java понадобится IDE — специальный текстовый редактор, позволяющий писать, компилировать и запускать код.
В этом руководстве используется IntelliJ; есть несколько бесплатных альтернатив с открытым исходным кодом, например Eclipse или NetBeans, работающих точно так же.¶

Также понадобится JDK — программный комплект, позволяющий запускать код Java.
Большинство IDE не включают JDK, поэтому следует отдельно скачать версию, совместимую с операционной системой. Бесплатную версию с открытым исходным кодом можно найти здесь.¶

При использовании другого языка шаги будут такими же. Потребуется лишь скачать другую IDE и комплект разработки программного обеспечения.¶

Выбор фреймворка или библиотеки #

Фреймворк можно представить как программное обеспечение, которое берёт на себя всю низкоуровневую логику, включая вызовы API, и позволяет сосредоточиться на логике конкретного бота.¶

В этом руководстве используется TelegramBots, но можно следовать ему с любой эквивалентной реализацией, поскольку все базовые методы похожи или полностью совпадают.¶

Множество фреймворков вместе с примерами кода приведены в специальном списке.¶

Создание проекта #

В IntelliJ перейдите в File > New > Project.¶

Заполните поля следующим образом:¶

  • Name — Название проекта. Например, BotTutorial .
  • Location — Место хранения проекта. Можно использовать значение по умолчанию.
  • Язык — Java
  • Build System — Фреймворк для управления зависимостями. Выберите Maven .
  • JDK — Выберите скачанную версию. В этом руководстве используется версия 17 .
  • Add Sample Code — Оставьте выбранным: будут созданы необходимые файлы.
  • Advanced Settings > GroupId — Рекомендуется tutorial .
  • Advanced Settings > ArtifactId — Можно использовать значение по умолчанию.

После нажатия Create, если всё сделано правильно, в представлении Project в левом верхнем углу должна отображаться структура проекта, примерно такая:¶

BotTutorial
├─ .idea
├─ src
│  └─ main
│     └─ java
│        └─ tutorial
│           └─ Main
└─ pom.xml

В других IDE структура будет похожей. Система управления зависимостями будет называться иначе (или не иметь названия вовсе, если она встроена) в зависимости от выбранного языка.¶

Если это выглядит пугающе, не беспокойтесь. Будут использоваться только файл Main и файл pom.xml.
Чтобы убедиться, что пока всё работает, дважды щёлкните Main, затем щёлкните маленькую зелёную стрелку слева от public class Main и выберите первый пункт.
Если шаги выполнены правильно, в консоли ниже появится Hello world! .¶

Добавление зависимости фреймворка #

Теперь укажем IDE скачать и настроить всё необходимое для работы с API.
Это очень просто и происходит автоматически в фоновом режиме.¶

Сначала найдите файл pom.xml в левой части экрана.
Откройте его двойным щелчком и просто добавьте:¶

<dependencies>
    <dependency>
        <groupId>org.telegram</groupId>
        <artifactId>telegrambots</artifactId>
        <version>6.0.1</version>
    </dependency>
</dependencies>

сразу после тега </properties>.¶

Когда закончите, pom.xml должен выглядеть примерно так.¶

Начало программирования #

Всё готово к написанию кода. Начинающим стоит учитывать, что знание выбранного языка очень поможет. С этим руководством можно научить бота базовому поведению, однако для более сложных возможностей потребуется опыт программирования.¶

Создание класса бота #

Если вы знакомы с объектно-ориентированным программированием, то знаете, что такое класс.
Если вы никогда о нём не слышали, представьте класс как файл, в котором пишется логика.¶

Чтобы создать класс, который будет содержать логику бота, щёлкните правой кнопкой мыши tutorial в дереве проекта слева и выберите New > Java Class. Назовите его Bot и нажмите Enter.¶

Теперь нужно подключить этот класс к фреймворку бота. Иными словами, необходимо убедиться, что он расширяет TelegramLongPollingBot. Для этого просто добавьте extends TelegramLongPollingBot сразу после Bot.
Появится красная линия — это лишь означает, что отсутствуют важные методы.¶

Чтобы исправить это, наведите курсор на красную линию, щёлкните implement methods, затем нажмите OK.
В зависимости от IDE этот пункт может называться implement missing methods или похоже.¶

Должно получиться следующее; если что-то пошло не так, можно скопировать это отсюда и вставить в свой класс:¶

package tutorial;
import org.telegram.telegrambots.bots.TelegramLongPollingBot;
import org.telegram.telegrambots.meta.api.objects.Update;

public class Bot extends TelegramLongPollingBot {

  @Override
  public String getBotUsername() {
      return null;
  }

  @Override
  public String getBotToken() {
      return null;
  }

  @Override
  public void onUpdateReceived(Update update) {}

}

Если под TelegramLongPollingBot появилась красная линия, значит, pom.xml настроен неправильно. В этом случае начните заново отсюда.¶

Доступные методы #

Рассмотрим эти 3 метода по очереди.¶

  • getBotUsername — Этот метод должен быть изменён так, чтобы всегда возвращать имя пользователя бота. Замените им возвращаемое значение null .
  • getBotToken — Фреймворк будет использовать этот метод для получения токена бота. Замените возвращаемое значение null токеном.
  • onUpdateReceived — Это самый важный метод. Он будет вызываться автоматически при появлении нового Update. Добавим в него вызов System.out.println(update);, чтобы быстро увидеть, что получается.

После замены всех строк должно получиться следующее:¶

@Override
public String getBotUsername() {
    return "TutorialBot";
}

@Override
public String getBotToken() {
    return "4839574812:AAFD39kkdpWt3ywyRZergyOLMaJhac60qc";
}

@Override
public void onUpdateReceived(Update update) {
    System.out.println(update);
}

Теперь бот настроен и готов к работе — пора зарегистрировать его в API и начать обрабатывать обновления.¶

В дальнейшем стоит хранить токен в отдельном файле настроек или в переменных окружения. Для этого руководства хранить его в коде допустимо, однако это не слишком гибко и обычно считается плохой практикой.¶

Регистрация бота #

Чтобы зарегистрировать бота в API, просто добавьте пару строк в главный метод, который запускает приложение. Если класс был назван Bot, главный метод должен выглядеть так:¶

public static void main(String[] args) throws TelegramApiException {
  TelegramBotsApi botsApi = new TelegramBotsApi(DefaultBotSession.class);
  botsApi.registerBot(new Bot());
}

Этот метод можно поместить в любой класс. Поскольку в классе Main есть автоматически созданный метод main, в этом руководстве будет использоваться он.¶

Первый запуск #

Пора запустить бота впервые.
Нажмите зелёную стрелку слева от public static void main и выберите первый вариант.¶

И ничего не произошло. Да, немного разочаровывающе.
Это потому, что боту нечего выводить — новых обновлений нет, ведь ему ещё никто не написал.¶

Если написать боту в Telegram, в консоли появятся новые обновления. Теперь у вас есть собственный Telegram Bot — серьёзное достижение. Пора сделать его немного умнее.¶

Если ничего не появляется, убедитесь, что сообщение отправлено правильному боту и что вставленный в код токен верен.¶

Получение сообщений #

Каждый раз, когда кто-то отправляет боту личное сообщение, метод onUpdateReceived будет вызван автоматически, и можно будет обработать параметр update, содержащий сообщение, а также множество другой информации, подробно описанной здесь.¶

Пока сосредоточимся на двух значениях:¶

  • Пользователь — Кто отправил сообщение. Доступ через update.getMessage().getFrom().
  • Сообщение — Что было отправлено. Доступ через update.getMessage().

Зная это, можно сделать вывод в консоль немного понятнее.¶

@Override
public void onUpdateReceived(Update update) {
    var msg = update.getMessage();
    var user = msg.getFrom();

    System.out.println(user.getFirstName() + " wrote " + msg.getText());
}

Это лишь базовый пример — теперь можно поэкспериментировать со всеми методами и узнать всё, что можно получить из этих объектов. Можно попробовать getUsername, getLanguageCode и десятки других.¶

Теперь, когда известно, как получать, обрабатывать и выводить входящие сообщения, пора узнать, как отвечать на них.¶

Не забывайте останавливать и заново запускать бота после каждого изменения кода.¶

Отправка сообщений #

Для отправки личного текстового сообщения обычно нужны три вещи:¶

  • Пользователь должен сначала обратиться к боту. (Если только пользователь не отправил запрос на вступление в группу, где бот является администратором, но это более сложный сценарий).
  • Необходимо предварительно сохранить идентификатор пользователя (user.getId())
  • Объект String, содержащий текст сообщения длиной от 1 до 4096 символов.

Разобравшись с этим, создадим новый метод для отправки первого сообщения:¶

public void sendText(Long who, String what){
   SendMessage sm = SendMessage.builder()
                    .chatId(who.toString()) //Who are we sending a message to
                    .text(what).build();    //Message content
   try {
        execute(sm);                        //Actually sending the message
   } catch (TelegramApiException e) {
        throw new RuntimeException(e);      //Any error will be printed here
   }
}

И вызовем его в методе main сразу после регистрации бота.
В этом примере предполагается, что идентификатор пользователя — 1234.¶

public static void main(String[] args) throws TelegramApiException {
   TelegramBotsApi botsApi = new TelegramBotsApi(DefaultBotSession.class);
   Bot bot = new Bot();                  //We moved this line out of the register method, to access it later
   botsApi.registerBot(bot);            
   bot.sendText(1234L, "Hello World!");  //The L just turns the Integer into a Long
}

Если всё сделано правильно, бот будет отправлять вам Hello World! при каждом запуске кода. Отправлять сообщения в группы или каналы — при наличии соответствующих разрешений — так же просто: замените 1234 идентификатором соответствующего чата.¶

Попробуйте другие типы сообщений, например SendPhoto, SendSticker, SendDice…
Полный список доступен, начиная отсюда.¶

Эхо-бот #

Закрепим всё, что было опробовано, написав эхо-бота.
Его функциональность будет довольно простой: каждое полученное текстовое сообщение будет сразу отправлено обратно пользователю.¶

Копирование текста #

Самый очевидный способ реализовать это — сохранить идентификатор пользователя и вызывать sendText сразу после каждого обновления.¶

Иными словами:¶

@Override
public void onUpdateReceived(Update update) {
    var msg = update.getMessage();
    var user = msg.getFrom();
    var id = user.getId();

    sendText(id, msg.getText());
}

Это работает для текста, но может быть расширено на стикеры, медиа и файлы.¶

Копирование всего #

Есть более специализированные функции, которые можно использовать для копирования сообщений и их обратной отправки.
Создадим метод именно для этого:¶

public void copyMessage(Long who, Integer msgId){
   CopyMessage cm = CopyMessage.builder()
              .fromChatId(who.toString())  //We copy from the user
           .chatId(who.toString())      //And send it back to him
           .messageId(msgId)            //Specifying what message
           .build();
    try {
        execute(cm);
    } catch (TelegramApiException e) {
        throw new RuntimeException(e);
    }
}

После замены вызова метода вonUpdateReceived выполнение кода даст полностью работающего эхо-бота.¶

Для простоты это руководство предполагает, что обновления всегда содержат сообщения. Это не всегда так — обязательно добавьте в код все необходимые проверки, чтобы обрабатывать каждый тип обновлений соответствующими методами.¶

Выполнение команд #

Чтобы узнать, что такое команда и как она работает, рекомендуется прочитать это специальное описание.
В этом руководстве основное внимание будет уделено технической стороне.¶

Создание команды #

Начните с открытия @BotFather.
Введите /mybots > Your_Bot_Name > Edit Bot > Edit Commands.¶

Теперь отправьте новую команду, а затем краткое описание.
Для этого руководства будут реализованы две простые команды:¶

scream - Speak, I'll scream right back 
whisper - Shhhhhhh

Логика команд #

Нужно, чтобы эхо-бот отвечал прописными буквами в режиме крика, а в остальных случаях — обычно.¶

Сначала создадим переменную для хранения текущего режима.¶

public class Bot extends TelegramLongPollingBot {

   private boolean screaming = false;

   [...]
}

Затем изменим логику, чтобы учитывать этот режим.¶

public void onUpdateReceived(Update update) {
    [...]                                   //Same variables as the previous versions
   if(screaming)                            //If we are screaming
       scream(id, update.getMessage());     //Call a custom method
   else
       copyMessage(id, msg.getMessageId()); //Else proceed normally
}

private void scream(Long id, Message msg) {
   if(msg.hasText())
       sendText(id, msg.getText().toUpperCase());
   else
       copyMessage(id, msg.getMessageId());  //We can't really scream a sticker
}

Наконец, добавим ещё несколько строк в метод onUpdateReceived, чтобы обрабатывать каждую команду перед ответом.¶

if(msg.isCommand()){ 
   if(msg.getText().equals("/scream"))         //If the command was /scream, we switch gears
      screaming = true;
   else if (msg.getText().equals("/whisper"))  //Otherwise, we return to normal
      screaming = false;

   return;                                     //We don't want to echo commands, so we exit
}

Как видно, выполняется проверка, является ли сообщение командой. Если да, бот переходит в режим крика.
В методе обновления проверяется, какой режим активен, и сообщение либо копируется, либо перед обратной отправкой преобразуется в верхний регистр.¶

Вот и всё. Теперь бот может выполнять команды и соответственно изменять своё поведение.¶

Разумеется, эта упрощённая логика изменит поведение бота для всех, а не только для того, кто отправил команду. Для этого руководства это может быть забавно, но в рабочей среде так не получится — используйте Map, словарь или эквивалентную структуру данных, чтобы назначать настройки отдельным пользователям.¶

Не забывайте всегда реализовывать несколько основных глобальных команд.
Можно попрактиковаться, добавив простой ответ на команду /start, которую намеренно оставили без внимания.¶

Кнопки и клавиатуры #

Чтобы упростить взаимодействие пользователя с ботом, многие текстовые обмены можно заменить удобными кнопками. Эти кнопки могут выполнять самые разные действия и настраиваться для каждого пользователя.¶

Типы кнопок #

Есть два основных типа кнопок:¶

  • Кнопки ответов — используются для предоставления списка предопределённых текстовых вариантов ответа.
  • Инлайн-кнопки — используются для быстрой навигации, ярлыков, URL, игр и многого другого.

Использовать эти кнопки так же просто, как прикрепить ReplyKeyboardMarkup или InlineKeyboardMarkup к объекту SendMessage.¶

В этом руководстве рассматриваются инлайн-кнопки, поскольку для них требуется лишь несколько дополнительных строк кода.¶

Создание кнопок #

Прежде всего создадим несколько кнопок.¶

 var next = InlineKeyboardButton.builder()
            .text("Next").callbackData("next")           
            .build();

 var back = InlineKeyboardButton.builder()
            .text("Back").callbackData("back")
            .build();

 var url = InlineKeyboardButton.builder()
            .text("Tutorial")
            .url("https://core.telegram.org/bots/api")
            .build();

Вернёмся к указанным полям:¶

  • Текст — То, что увидит пользователь: текст на кнопке
  • Данные callback — Будут отправлены экземпляру кода как часть нового Update, что позволяет быстро определить, какая кнопка была нажата.
  • URL — Кнопка, задающая URL, не содержит callbackdata, поскольку её поведение предопределено: при нажатии она откроет указанную ссылку.

Создание клавиатур #

Созданные кнопки можно собрать в две клавиатуры, которые затем будут использоваться для перехода между двумя примерными меню.¶

Сначала добавьте два поля для хранения необходимых клавиатур.¶

private boolean screaming = false;

private InlineKeyboardMarkup keyboardM1;
private InlineKeyboardMarkup keyboardM2;

Затем создайте и назначьте их.¶

keyboardM1 = InlineKeyboardMarkup.builder()
          .keyboardRow(List.of(next)).build();  

//Buttons are wrapped in lists since each keyboard is a set of button rows
keyboardM2 = InlineKeyboardMarkup.builder()
          .keyboardRow(List.of(back))
          .keyboardRow(List.of(url))
          .build();

Этот код можно разместить где угодно; важно лишь убедиться, что переменные клавиатур доступны из вызова метода, который будет отправлять новое меню. Если эта концепция непонятна и неизвестно, куда их поместить, просто вставьте их перед обработкой команд.¶

Отправка клавиатур #

Для отправки клавиатуры достаточно указать разметку ответа для сообщения.¶

public void sendMenu(Long who, String txt, InlineKeyboardMarkup kb){
    SendMessage sm = SendMessage.builder().chatId(who.toString())
            .parseMode("HTML").text(txt)
            .replyMarkup(kb).build();

    try {
        execute(sm);
    } catch (TelegramApiException e) {
        throw new RuntimeException(e);
    }
}

Возможно, вы заметили, что также был добавлен новый параметр HTML.
Он называется параметром форматирования и позволит впоследствии использовать HTML-теги и добавлять к тексту форматирование.¶

Запуск меню #

Можно было бы отправлять новое меню каждому новому пользователю, но для простоты добавим новую команду, которая будет открывать меню. Это можно сделать, добавив новую ветвь else в предыдущую логику команд.¶

 var txt = msg.getText();
 if(msg.isCommand()) {
        if (txt.equals("/scream"))
            screaming = true;
        else if (txt.equals("/whisper"))
            screaming = false;
        else if (txt.equals("/menu"))
            sendMenu(id, "<b>Menu 1</b>", keyboardM1);
        return;
 }

Теперь попробуйте отправить боту /menu. Если всё сделано правильно, появится совершенно новое меню.¶

В рабочей среде команды следует обрабатывать с помощью подходящего шаблона проектирования, который изолирует их в отдельных классах-исполнителях — модульных и отделённых от основной логики.¶

Навигация #

При создании сложных ботов навигация необходима. Пользователи должны иметь возможность беспрепятственно переходить из одного меню в другое.¶

В этом примере кнопка Next должна вести пользователя ко второму меню.
Кнопка Back будет возвращать назад.
Для этого начнём обрабатывать входящие CallbackQueries — результаты, получаемые после нажатия пользователем кнопки.¶

CallbackQuery по существу состоит из трёх основных параметров:¶

  • queryId — Нужен для закрытия запроса. Новые запросы обязательно всегда нужно закрывать после обработки — иначе у пользователя над каждой кнопкой будет продолжать отображаться символ загрузки.
  • data — Определяет, какая кнопка была нажата.
  • from — Пользователь, нажавший кнопку.

Обработка в этом контексте означает лишь выполнение действия, однозначно определённого кнопкой, а затем закрытие запроса.¶

Очень простой обработчик кнопок мог бы выглядеть так:¶

private void buttonTap(Long id, String queryId, String data, int msgId) {

    EditMessageText newTxt = EditMessageText.builder()
            .chatId(id.toString())
            .messageId(msgId).text("").build();

    EditMessageReplyMarkup newKb = EditMessageReplyMarkup.builder()
            .chatId(id.toString()).messageId(msgId).build();                           

    if(data.equals("next")) {
        newTxt.setText("MENU 2");
        newKb.setReplyMarkup(keyboardM2);
    } else if(data.equals("back")) {
        newTxt.setText("MENU 1");
        newKb.setReplyMarkup(keyboardM1);
    }

    AnswerCallbackQuery close = AnswerCallbackQuery.builder()
            .callbackQueryId(queryId).build();

    execute(close);
    execute(newTxt);
    execute(newKb);
}

С этим обработчиком бот будет автоматически переходить между инлайн-меню при каждом нажатии кнопки.
Развитие этой идеи позволяет создавать бесконечные комбинации навигируемых подменю, настроек и динамических страниц.¶

База данных #

Telegram не хранит для вас базу данных обновлений — после обработки и получения обновление больше недоступно. Это означает, что такие функции, как списки пользователей, списки сообщений, текущее инлайн-меню пользователя, настройки и т. д., должны быть реализованы и поддерживаться разработчиками ботов.¶

Если боту нужна одна из этих возможностей и требуется начать работу с постоянным хранением данных, рекомендуется изучить практики сериализации, библиотеки выбранного языка, а также доступные базы данных.¶

Реализация базы данных выходит за рамки этого руководства, однако в интернете доступно несколько руководств для простых встроенных решений с открытым исходным кодом, таких как SQLite, HyperSQL, Derby и многих других.¶

Выбранный язык также влияет на доступные и поддерживаемые базы данных — приведённый выше список предполагает, что вы следовали этому руководству по Java.¶

Хостинг #

До сих пор бот работал на локальной машине — вашем ПК. Это может быть удобно для разработки, тестирования и отладки, но не подходит для рабочей среды.
Бот должен быть постоянно доступен и отзывчив, однако компьютер не всегда может быть в сети.¶

Это можно сделать в четыре шага:¶

  • Упакуйте код
    Чтобы разместить бота в другом месте, необходимо сделать его легко переносимым и запускаемым вне IDE.
    Если вы следовали этому руководству, подойдёт это стандартное руководство. В противном случае изучите руководства по экспорту или упаковке для выбранных IDE и языка: процедуры могут различаться, но результат будет тем же.¶

  • Приобретите VPS или эквивалентную услугу
    Сервер — это, по существу, постоянно работающая и подключённая к сети машина, о которой не нужно беспокоиться. Для размещения бота можно выбрать VPS, который служит этой цели и может быть арендован у различных поставщиков.
    Другой вариант — приобрести сетевой микроконтроллер, доступный в самых разных конфигурациях и размерах в зависимости от потребностей.¶

Необходимо обеспечить, чтобы все данные пользователей в базе данных постоянно оставались надёжно зашифрованными для гарантии конфиденциальности пользователей. То же относится и к локальному экземпляру, однако это становится особенно важным после переноса базы данных на удалённый сервер.¶

  • Загрузите исполняемый файл или пакет

После настройки рабочего соединения ssh между вашей машиной и новым сервером следует загрузить исполняемый файл и все связанные файлы.
Предполагается, что запускаемый JAR TutorialBot.jar и его база данных dbase.db сейчас находятся в папке /TBot.¶

$ scp -r /TBot/ username@server_ip:/bots/TBotRemote/
  • Запустите приложение

В зависимости от выбранного языка может потребоваться по-разному настроить серверное окружение. Если выбран Java, достаточно установить совместимый JDK.¶

$ apt install openjdk-17-jre
$ java -version

Если всё сделано правильно, в выводе будет показана версия Java и несколько других значений. Это означает, что всё готово к запуску приложения.¶

Теперь, чтобы запустить исполняемый файл:¶

$ cd /bots/TBotRemote/
$ java -jar TutorialBot.jar

Теперь бот работает в сети, и пользователи могут взаимодействовать с ним в любое время.¶

Чтобы упростить и сделать этот процесс модульным, можно использовать специализированный контейнер docker или эквивалентный сервис.
Если вы следовали одному из эквивалентных примеров (C#, Python, Go и TypeScript), подробные инструкции по экспорту и запуску кода доступны здесь.¶
