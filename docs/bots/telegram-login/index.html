Вход через Telegram #

Telegram предлагает разработчикам приложений и сайтов бесплатную и открытую платформу, которая позволяет более чем 1 миллиарду пользователей без затруднений регистрироваться и входить с помощью учётных записей Telegram.¶

Telegram Login

Преимущества Telegram Login #

  • Более высокая конверсия
    Пользователи входят в систему несколькими касаниями, что повышает конверсию и удержание.¶

  • Меньше затрат на верификацию
    Пользователи могут передать свой подтверждённый номер телефона, устраняя необходимость в дорогостоящих кодах.¶

  • Прямые каналы связи
    С пользователями можно связаться внутри Telegram благодаря встроенной поддержке push-уведомлений.¶

  • Дополнительная интеграция
    Больше сервисов можно предоставлять напрямую через Bot API и Mini Apps.¶

Примечание: Этот документ описывает библиотеку Telegram Login и новый процесс входа через OpenID Connect.
Документация по устаревшему виджету JavaScript на основе iframe находится здесь.¶

Начало работы #

Telegram предлагает компактный инструмент для быстрого добавления в интерфейс кнопок входа через Telegram. Также можно напрямую использовать JS API нашей библиотеки.¶

Разработчикам мобильных приложений мы также предлагаем готовые к использованию нативные SDK для iOS и Android.¶

Кроме того, Telegram поддерживает стандартный протокол OpenID Connect. Это позволяет интегрировать авторизацию Telegram в приложение с помощью любой библиотеки или платформы авторизации, совместимой с OIDC (например, Keycloak, Authentik, Auth0 и т. д.).¶

Наша реализация следует стандартному потоку кода авторизации с поддержкой PKCE.¶

Для подробного ознакомления с общим процессом OIDC обратитесь к руководству для разработчиков OpenID Foundation.¶

TL;DR #

  • Настройте бота, который будет представлять приложение.
  • Зарегистрируйте разрешённые URL через @BotFather и получите Client ID и Secret.
  • Добавьте библиотеку Telegram Login на страницу.
  • Подключите нативные SDK, если вы разрабатываете мобильное приложение для iOS или Android.
  • Проверяйте ID-токены для криптографической проверки входящих запросов.

Кроме того, можно использовать интеграцию OpenID.¶

Возникли сложности с каким-либо из описанных выше шагов? Свяжитесь с нами через @BotSupport, обязательно добавив в сообщение хештег #oidc.¶

Настройка бота #

Чтобы использовать Telegram Login, понадобится бот Telegram, который будет представлять приложение.¶

Настоятельно рекомендуется, чтобы фото профиля бота соответствовало логотипу сайта, а имя бота отражало эту связь. При входе пользователи увидят окно подтверждения, подобное показанному ниже:¶

Login confirmation box

Пользователи с гораздо большей вероятностью авторизуют приложение, если у бота знакомые и ожидаемые ими имя и логотип. Для большей прозрачности официальные сервисы также могут подать заявку на верификацию в Telegram или у третьих сторон.¶

Регистрация разрешённых URL #

Выбрав бота, откройте мини-приложение @BotFather, выберите бота, а затем — Login Widget.¶

Добавьте все разрешённые URL для приложения. В их число входят источники сайта, на которых встраивается виджет входа (например, https://example.com), и конкретные URI перенаправления для процесса OIDC (например, https://example.com/auth/callback). Для поддержки разных доменов или адресов можно зарегистрировать несколько URL.¶

В этом разделе @BotFather также покажет Client ID и Client Secret. Надёжно сохраните эти значения — они понадобятся для настройки клиента OIDC.¶

Важно: В целях безопасности Telegram будет обрабатывать входы и перенаправлять пользователей только с использованием предварительно зарегистрированных URL.¶

Данные callback #

После завершения процесса входа callback может получить либо полезную нагрузку успеха (данные пользователя), либо ошибку.¶

ПолеТипОписание
id_tokenstringТокен OIDC JWT, содержащий утверждения пользователя. Важно: проверяйте действительность ID-токена на сервере
userUserDataДекодированный id_token, содержащий запрошенные сведения о пользователе.
errorstringОписание ошибки.

Важно: Для завершения процесса авторизации библиотека telegram-login.js использует связь со всплывающим окном. Если сайт отправляет HTTP-заголовок Cross-Origin-Opener-Policy: same-origin, эта связь между окнами будет заблокирована, и вход завершится ошибкой. Чтобы библиотека JavaScript работала корректно, необходимо удалить этот заголовок либо использовать более разрешающую политику, например Cross-Origin-Opener-Policy: same-origin-allow-popups.¶

Нативные SDK #

При разработке нативного мобильного приложения Telegram предоставляет специальные SDK, упрощающие вход на устройствах iOS и Android без необходимости использовать веб-представления.¶

  • Telegram Login для iOS
    Нативный пакет Swift для интеграции авторизации Telegram в приложения для iOS или iPadOS.¶

  • Telegram Login для Android
    Нативная библиотека Android, позволяющая без затруднений авторизовать пользователей в приложениях Android на Kotlin или Java.¶

Примечание: Полные руководства по настройке, инструкции по установке и примеры использования для каждой платформы находятся непосредственно в файлах README соответствующих репозиториев GitHub.¶

Структура данных пользователя #

Все запрошенные сведения о пользователе возвращаются непосредственно в ID-токене. После успешной авторизации декодированный ID-токен будет выглядеть так:¶

{
  "iss": "https://oauth.telegram.org",
  "aud": "123456789",
  "sub": "1234123412341234123",
  "iat": 1700000000,
  "exp": 1700003600,
  "id": 987654321,
  "name": "John Doe",
  "given_name": "John",
  "family_name": "Doe",
  "preferred_username": "johndoe",
  "picture": "https://cdn4.telesco.pe/file...",
  "phone_number": "971577777777",
  "phone_number_verified": true,
}

Обратите внимание: Telegram сейчас не предоставляет отдельный адрес UserInfo. Однако некоторые библиотеки OIDC могут ожидать этот адрес по умолчанию, и может потребоваться настроить их, чтобы пропустить отдельный запрос userinfo.¶

Ручная реализация #

Если процесс OIDC интегрируется вручную, без библиотеки, используйте приведённые ниже адреса и описание процесса.¶

Адреса #

  • Авторизация: https://oauth.telegram.org/auth
  • Токен: https://oauth.telegram.org/token
  • Ключи (JWKS): https://oauth.telegram.org/.well-known/jwks.json

Запуск авторизации #

Направьте пользователя на адрес авторизации со следующими параметрами. Этот URL необходимо открыть в браузере пользователя.¶

GET https://oauth.telegram.org/auth?
    client_id=<YOUR_BOT_ID>&
    redirect_uri=<YOUR_CALLBACK_URL>&
    response_type=code&
    scope=openid%20profile%20phone&
    state=<RANDOM_STRING>&
    code_challenge=<PKCE_CHALLENGE>&
    code_challenge_method=S256
  • client_id: Client ID, предоставленный BotFather.
  • state: Случайная строка, сгенерированная бэкендом для предотвращения CSRF.
  • code_challenge: SHA256-хеш средства проверки кода (PKCE), закодированный в Base64URL.

Обмен кода на токены #

Если пользователь одобрит вход, он будет перенаправлен на ваш redirect_uri с параметром code. Обменяйте этот код на токен доступа и ID-токен, выполнив POST-запрос на сервере.¶

Для этого запроса требуется Basic Authorization с использованием Client ID и Client Secret (base64(client_id:client_secret))¶

POST https://oauth.telegram.org/token
Content-Type: application/x-www-form-urlencoded
Authorization: Basic <BASE64_CREDENTIALS>

grant_type=authorization_code&
code=<AUTHORIZATION_CODE>&
redirect_uri=<YOUR_CALLBACK_URL>&
client_id=<YOUR_BOT_ID>&
code_verifier=<PKCE_VERIFIER>

Ответ:¶

{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "id_token": "eyJhbGciOiJ..."
}

Проверка ID-токенов #

id_token — это подписанный JSON Web Token (JWT). Прежде чем доверять содержащимся в нём данным пользователя, необходимо проверить подпись:¶

  1. Получите ключи: конкретные открытые ключи с адреса JWKS.
  2. Проверьте подпись: убедитесь, что токен подписан Telegram.
  3. Проверьте утверждения: убедитесь, что iss имеет значение https://oauth.telegram.org, aud соответствует ID бота, а срок действия токена не истёк (exp).

Алгоритм подписи #

По умолчанию Telegram подписывает ID-токены с помощью RS256, который сразу работает со всеми библиотеками OIDC. Если нужен другой алгоритм, его можно изменить в разделе Login Widget > Advanced в @BotFather:¶

АлгоритмПримечания
RS256Default.
ES256Меньший размер токенов, более быстрая проверка.
EdDSAEd25519 (кривая TON, Solana). Для интеграций Web3.
ES256Ksecp256k1 (кривая Bitcoin, Ethereum). Для интеграций Web3.

EdDSA и ES256K ограничены областью доступа openid, поскольку токены, подписанные этими алгоритмами, могут передаваться в блокчейн или проверяться смарт-контрактами. Сейчас выбор любого из них приведёт к отклонению областей доступа profile и phone.¶

После установления связи с пользователем при желании можно использовать привязанного бота, чтобы предоставлять сервисы непосредственно в интерфейсе чата через Bot API, или без затруднений предложить всё веб-приложение внутри Telegram с помощью Mini Apps.¶
